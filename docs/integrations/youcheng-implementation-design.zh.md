# 有成财务与报销实现方案

[English](youcheng-implementation-design.md) | 中文

当前范围仅财务，不安排报销或双模块隔离建设。[逐项执行计划](youcheng-finance-execution-plan.zh.md)定义本期 Goal；下文报销及双模块条目仅为暂缓备忘，不是开发或验收前提。保留已有报销数据，财务不误调用报销接口；不同客户／账套的访问范围仍须校验。

## 目标和边界

本文是[开发计划](youcheng-natural-language-development-plan.zh.md)的拟实施设计，不是已交付行为。当前只修订财务方案；报销及双模块设计不属于执行范围。既有文件、凭据与记录保留，必要的财务实现只复用适合当前业务的基础设施。

先在现有包内拆分清楚的业务文件，不修改 agent loop（智能体循环），也不先建空壳连接器、规则引擎或工作流包。职责出现独立演化需求时才拆包，并同时落地实际消费方。标准模式不得因这些财务能力改变行为。

## 本期财务范围与账套保护

本期不实现双模块切换、报销连接解耦、双向隔离框架或报销验收。财务执行路径只装配必要财务工具及财务适配器，不调用报销业务执行器；已有报销数据不删除、不迁移为财务数据。下文报销相关设计只保留为备忘，不是前置任务。

财务会话、查询、材料、凭据、确认和任务绑定准确客户及账套；切换客户或修改配置后重新核验，不能仅凭重名或本地 test 标签选择目标。后端拒绝请求越出所选账套，日志与普通模型输出不包含秘密。无需为这些财务要求新增通用多模块框架。

## 财务流程与数据：首先实施

财务使用自己的执行器：解析账套及获授权资料 → 准备凭证或其他已确认财务动作 → 确定性校验 → 预览确认 → 持久化财务任务 → 财务 API → 回查 → 报告核实与未核实结果。来源及确认保护可复用基础代码，不能调用报销业务执行器。

| 财务数据 | 最小内容 |
|---|---|
| 账套资料 | 财务模块、客户、账套 ID、源地址／配置版本、科目及辅助维度 |
| 待执行财务记录 | 动作、日期／期间、币种、分录或流水字段、准确金额、已授权材料引用 |
| 财务任务 | 模块／客户／任务 ID、内容摘要、确认、外部请求编号、进度 |
| 财务结果 | 外部记录 ID、字段／状态核验、安全错误、未知结果及恢复证据 |

F1–F3 完成确认后的财务范围，包括必需的日记账、账户、往来、删除或核销动作。不能把难做的必交付项静默移入报销阶段就称 F4 通过；整体验收条件以开发计划为准。

## 一次操作的流程

用户材料与需求 → 客户及资料核对 → 生成待确认内容 → 用户确认 → 上传及外部写入 → 回查 → 带证据的结果。草稿创建、草稿修改、提交和凭证创建是不同动作，即使底层使用同一个 API 也不能共用一个无差别写开关。

skill（技能）负责理解用户目标、整理材料和追问。后端决定客户、凭据、地址、允许动作、金额计算、必填项及执行顺序；模型不能选择任意 URL、AppSecret、外部企业或 `pushOrderStatus`。所有模型可见的进度和缺项必须由已记录事件或工具结果重建。

用户已明确的信息不重复询问。缺少事由、部门或项目时合并追问；缺少权限或不支持组件属于系统能力问题，不要求用户换发票格式来解决。准备结果展示可填写内容和真实缺口；确认后的业务内容发生变化则重新确认。

## 报销数据：R 阶段再实施

| 数据 | 首版必要内容 | 为什么分开 |
|---|---|---|
| 来源文件 | 客户、来源记录 ID、文件名、摘要、格式、大小和受控路径 | 一张发票可能多张图，一份 PDF 可能多张发票 |
| 发票事实 | 票据身份、金额、日期、主体、原件引用及需要复核的字段 | 识别结果不是有成发票池记录，不伪造缺失票号 |
| 费用行 | 金额／币种、费用类型、日期、业务字段、原件及发票引用 | 每行只关联该行材料；无票费用是单独业务情况 |
| 待执行内容 | 任务 ID、动作、目标客户／账套／企业、模板字段、关联材料、配置版本及确认摘要 | 确认绑定准确内容，不只绑定一个“同意”词 |
| 操作回执 | 任务版本、步骤、外部请求编号和单据 ID、已完成上传、核验结果、安全错误及时间 | 重启后可回查，模型不负责记住进度 |

优先扩展现有类型与回执，不一次新增五个独立存储系统。金额使用现有可复核计算方法和明确精度，不能靠模型求和或二进制浮点累计；发票数与文件数分开。只对实际支持的组件定义映射，选项必须来自所选客户的实时或仍有效资料。

## 连接、权限和配置

每个模块保存自己的 HTTPS 地址、凭据引用、身份范围和版本；令牌按模块、源地址和凭据版本隔离，刷新合并并发请求。过期令牌可重新获取，但不能因此自动重放结果未知的写入。诊断区分网络、IP 白名单、凭据、权限、错误环境和响应不兼容，不输出密钥或 token。

本地客户、财务账套、报销企业是不同身份。能从 API 核验则核验；不能核验时由用户明确确认对应关系并显示限制，不猜测第一条记录或同名对象。权限仍受有成账户约束；本机无登录不等于安装包应内置公共密钥。

现有凭据服务负责秘密，日志、模型和普通前端读取不接收秘密。普通附件授权覆盖具体原件及 OSS 上传。完整银行账号只在必要的受控设置／执行路径处理，模型使用脱敏资料。本机功能开关只控制已实现、已验证动作，不另建权限管理平台。

## 报销附件与发票：仅 R 阶段

普通附件：校验来源归属和字节未变化 → 上传私有 OSS → 后端生成短期 HTTPS 签名链接 → URL 数组编码为 `attachment.bindingVal` → 保存报销草稿。保留已验证的单据级附件传参方式，不因模板元数据省略此字段就拒绝附件；费用模板声明附件时，费用级只放对应行的原件链接。

发票池：仅在业务需要时，用已授权原件调用发票录入 → 保存返回的 `invoiceIdList` → 在对应费用的 `invoice` 组件关联 → 验证发票与费用关系。发票池录入是额外写入，必须纳入预览授权；失败不能悄悄降级为仅附件而宣称发票关联完成。

同一任务的同一原件优先复用已核实上传结果；临时链接过期时重新签名，不因此重复创建单据。签名链接不进入聊天和持久业务日志，记录对象引用及安全证据即可。模型不需要看到 URL 才能正确报告上传进度。

分别记录上传完成、链接已传入、单据已关联、原件可打开以及过期后可访问的证据。若 API 不能读回本单附件，受控界面核验可作为该测试用例证据，但不冒充自动核验。关联单据接口不能替代本单附件核验。

必须确认有成是转存原件还是只保存链接。若只保存链接，当前短期签名方案不能保证报销档案长期访问；在 R1 验收中明确此缺口，再选择供应商正式转存能力或经授权的持久访问方案。不得改为公开 Bucket，也不得仅延长一次链接有效期就宣称解决长期留存。

## 任务状态、重复和恢复

复用原子写入、锁及版本化持久化设施，但财务和报销分别保存业务回执及模块／客户任务索引。F2 增加财务自己的回执，报销改动等待 R 阶段。恢复校验模块、客户、身份、权限及配置，不得查询另一模块或企业。保留历史记录和用户文件，不要求数据库迁移。

| 执行结果 | 恢复行为 |
|---|---|
| 待确认／已取消，尚无外部写入 | 不执行；用户修改后重新准备，取消不能被模型猜测绕过 |
| 已确认，尚未发送业务写入 | 重新核对相关版本，按已确认内容继续允许的步骤 |
| 部分步骤完成 | 保留成功上传／发票 ID／单据 ID，只处理剩余步骤 |
| 写入已发送，结果不明 | 先按原请求编号／单据 ID 回查；查不到不自动等于失败，不盲目重建 |
| 明确失败 | 展示原因；只有已核实可安全重试的步骤允许重试 |
| 单据与必需结果已核实 | 返回既有回执；附件或字段未核实的部分仍单独显示 |

同一任务使用稳定请求编号和内容摘要防止模型重复调用；新增任务再检查同一客户的发票身份和已有业务记录。文件摘要只防同字节重复，不是业务幂等；一张发票分次报销须检查金额和既有记录，不用票号一刀切拒绝。

本机进程锁不保证其他电脑不会重复创建。只有有成验证过的唯一编号／幂等能力才能提供对应外部保证；否则声明支持范围为本机，并对跨设备及查询延迟保留人工核验。取消只停止后续动作，不撤销已有单据或云端文件。

已有草稿修改先读取当前状态和内容、展示差异，再执行已核验的修改 API。若无可靠外部版本检查，只能声明并发限制并复核关键字段，不伪称乐观锁；不可编辑时返回原因，不新建替代旧单。

## 模型和用户结果

结果至少包含模块、任务 ID、客户、动作、真实单据号、字段核验结果、附件核验结果和下一步。成功文字由这些状态生成；不得把“收到请求”“上传 OSS”“传入链接”写成“附件已长期保存到有成”。

工具按业务动作暴露类型化参数和结构化缺项，不把完整厂商目录或任意请求体交给模型。保留当前运行时规则随会话恢复更新的机制，避免旧会话持续使用失效指令。具体工具拆分在实现对应业务时决定，不为每个 API 创建一个工具。

列表／统计必须带客户、期间、分页和完整性；无法获取全量或必要详情时，报告可见范围而非“没有异常”。专业合规规则仍按产品路线另行开发，不把简单必填检查包装为合规审计。

## 验证、发布和暂缓条件

接口参数、组件映射、金额、错误和恢复用聚焦测试；真实产品组合的无 Key 快照验证工具与确认；授权测试租户验证真实状态和附件；真实模型验证自然语言、追问和取消。测试层次相互补充，不用纯 mock 证明外部成功。

每批开放已验收的模板／动作；保留禁用新写入与继续回查。测试材料脱敏，原件与签名链接不写仓库。升级必须保留客户、凭据、导入记录和历史任务；状态格式变更要明确读取与迁移方案，不删除旧数据来获得干净测试。

只有出现实际第二消费者才提取通用执行逻辑；只有查询规模或并发需要才评估数据库；只有用户要求跨设备／电脑离线执行才评估云服务。文件夹自动化复用已存在的本机调度能力或一个最小扫描任务，不先做工作流编排平台。
