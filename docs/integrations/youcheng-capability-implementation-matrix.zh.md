# 有成能力范围与接口核验矩阵

[English](youcheng-capability-implementation-matrix.md) | 中文

当前范围仅财务，不安排报销或双模块隔离建设。[逐项执行计划](youcheng-finance-execution-plan.zh.md)定义本期 Goal；下文报销及双模块条目仅为暂缓备忘，不是开发或验收前提。保留已有报销数据，财务不误调用报销接口；不同客户／账套的访问范围仍须校验。

## 来源与使用方式

本矩阵是[开发计划](youcheng-natural-language-development-plan.zh.md)的范围参考，不是已上线工具清单。官方资料有[报销目录](https://yiqbopenapi.superboss.cc/#/share/7YX0lXxR)和[财务目录](https://yiqbopenapi.superboss.cc/#/share/awXPk8nW)。2026-09-05 核对时分别有 67、45 个叶子条目，其中存在重叠，不能相加为 112 个独立 API。报销资料保存在[本地镜像](youcheng-openapi-replica.json)。2026-09-07 财务目录重读和测试账套结果见 [F0 核验记录](youcheng-finance-f0.zh.md)，其中明确 22 个财务路径的范围和报表缺口；不是完整财务原文镜像或全部接口验收。报销资格核验仍暂缓。

“文档支持”“代码已实现”“真实样例通过”“指定范围验收通过”分别记录，不能相互代替。权限、模板、状态转换或结果核验方法不明的动作保持未开放。当前实现仅包括连接、凭证查询及有限报销草稿等，见 [Finance Host](../../packages/xiaojing/xiaojing-finance-domain/README.zh.md)。

## 业务覆盖与交付顺序

| 所属模块 | 业务范围 | 待核验动作 | 开发及验收 |
|---|---|---|---|
| 财务 | 连接／账套 | 认证、账套选择、身份和权限 | F0／F1；不依赖报销 |
| 财务 | 科目／辅助核算／余额 | 必需查询、计算及受支持维护 | F1／F3；F0 评估全部范围 |
| 财务 | 凭证 | 列表／详情／建议／创建及所需维护 | F1／F2／F3；过账、审核须独立证据 |
| 财务 | 日记账／出纳账户 | 账户、类别、出纳、流水查询和写入 | F1／F3；高风险维护单独确认 |
| 财务 | 往来 | 查询、新增及受支持核销／删除 | F1／F3；必交付项须在 F4 前完成 |
| 财务 | 整体验收 | 功能范围、客户账套保护、恢复及文档 | F4 须用户确认，报销不在本期 |
| 报销 | 企业、人员、部门、模板 | 独立认证、配置及基础资料查询 | R0／R1；不依赖财务凭据或配置 |
| 报销 | 单据与申请 | 查询、草稿、修改、核验后提交、借款／付款申请 | R1／R2；申请不等于银行付款 |
| 报销 | 原件与发票池 | 普通附件、发票录入、费用关联及留存 | R1／R2；记录与授权独立 |
| 报销 | 项目、辅助表单、成本中心 | 必要查询及分别核验的维护 | R0／R2；不能复用财务同名对象 |
| 报销 | 预算、资金、收款资料、角色 | 报销目录中的查询和受支持维护 | R0／R2；角色及账户修改单独控制 |
| 报销 | 批量与目录任务 | 扫描、分组、重复检查、可恢复单据操作 | R3／R4；不执行财务任务 |
| 仅共用基础设施 | 客户基础档案、秘密存储、文件传输、日志 | 按模块限定记录与权限的可复用设施 | 不共用业务凭据、数据访问权、任务或确认 |
| 跨模块 | 单据／凭证关联或结果同步 | 本方案不开放 | 以后另行授权并设计数据交换 |

本表按业务归组，不声称已经完成每个叶子条目的资格核验。财务目录内的报销路径也要核对大小写、版本和参数，不能按同名接口直接去重。范围内未出现明确官方接口的需求，记录为待供应商确认，不补造工具。

## 必须修正的接口语义

| 文档或动作 | 已知语义与开发要求 |
|---|---|
| 报销日记账查询 `BXgRxZ8G` | `/reimburse/journal/queryListPage.rjson` 的 `status` 省略时会改变查询记录状态；只读动作固定传已核验的值 |
| 报销凭证查询 `nzdZkM8j` | `/reimburse/certificate/queryListPage.rjson` 同样存在条件写入；不是当前财务凭证列表接口 |
| 生成单据 `Zd2qAr2w` | `pushOrderStatus` 区分草稿、匹配审批流、直接完成及修改语义；由后端受控动作映射，模型不能任填 |
| 支付／凭证／日记账“回调” | 文档给出向有成发请求的路径；不能直接设计为接收 Webhook。先确认回写方向、权限和业务影响 |
| 关联单据 `pX9mPjXr` | 返回关联单据信息，不是本单附件详情；空关联不能证明本单没有附件 |
| 单据状态 `kXODV7zD` | 查询指定单据状态，不是状态字典；不同接口编码分别核验 |
| 发票录入 `wXnr7YX9` | 返回 `invoiceIdList` 后，创建单据使用 `invoice` 组件关联；普通附件 URL 不是发票 ID |
| 财务创建 `K2ZGNd8v`／`xXaMy0Xo` | 核验 `flowId`、`appId`、返回凭证信息及重复行为；不能在结果未知时自动改用另一接口 |
| 财务／报销认证 | 当前适配器分别处理字符串 token 和含 `accessToken` 的对象；不能只因为认证路径相同就共用解析 |
| 财务测试地址 | 当前两个环境配置默认同一生产源；不能据“测试”标签认定数据隔离，文档 HTTP 示例不能直接用于凭据传输 |

## 首批接口核验记录

每项必要接口记录：官方文档 ID 与更新时间、模块／版本、方法和精确路径、HTTPS 地址与身份范围、必要参数、分页及限制、响应字段、错误和副作用、外部编号、重复及超时恢复方式、结果回查、测试证据和开放状态。已有来源可引用，不复制整篇文档。

F0 先梳理完整财务范围，标出必交付项、须用户同意的例外及不支持接口，再按业务流程实现财务依赖。报销资料发现、模板、发票录入和单据写入不是财务前置任务，只能在 F4 通过后启动。凭证样例成功不代表财务完成。

供应商未确认的幂等、附件转存、单据编辑和身份信息保持待核验；通过局部测试只能提高对应动作的证据等级，不能提升整个目录。
