# 有成财务开发总计划

[English](youcheng-natural-language-development-plan.md) | 中文

## 决策与当前工作范围

当前只规划有成财务，不开发、重构或排期报销，也不把双模块隔离建设作为前置任务。既有报销数据保留；财务只调用财务接口及公共鉴权，不误入报销流程。不同客户／账套之间的身份、数据、凭据和操作范围检查仍为财务必需条件。

本次授权是调整方案，不是启动功能开发或外部写入。报销以后是否开发、如何组织，由用户另行决定；财务验收不自动启动报销。

## 文档职责与已有证据

[逐项执行计划](youcheng-finance-execution-plan.zh.md)是功能编号、依赖、具体 Goal 和完成条件的唯一执行清单；[F0 核验记录](youcheng-finance-f0.zh.md)保留官方目录和只读实测证据；[能力矩阵](youcheng-capability-implementation-matrix.zh.md)提供接口范围参考；[实现方案](youcheng-implementation-design.zh.md)中的财务部分提供实现约束。配套文件中的报销及双模块架构条目均为暂缓备忘，不作为本期开发或验收任务。

当前代码已有客户绑定、财务连接、凭证查询及文件能力，实际行为以 [Finance Host](../../packages/xiaojing/xiaojing-finance-domain/README.zh.md)为准。每个 Goal 先核对现有实现和测试，只补差距，不从头重写。成功样例、可调用接口和完整业务能力分别记录。

F0.1 已完成技术调查；F0.2 的核心功能范围、条件性报表和财务附件定位仍须用户确认。测试账套为 35601（数豆测试帐套勿删），请求源是生产服务，不是独立沙箱；不得删除账套。未知写权限或数据影响不因测试标签而获得授权。

## 阶段与顺序

| 阶段 | 交付方向 | 执行原则 |
|---|---|---|
| F0 | 范围确认、可恢复开发基线和测试计划 | 复用 F0.1，不重新做完整调查；数据写入单独确认 |
| F1 | 连接、基础资料、凭证／余额／流水／往来查询、比较与导出 | 每项以完整、准确的业务结果验收；T01 另行准备非空数据 |
| F2 | 凭证准备、确认、创建及恢复 | 准备不写账；创建包括持久记录和真实回查 |
| F3A | 日记账、应收、应付、科目及辅助项目新增 | 按动作分别交付，不因缺资料而自动新增 |
| F3B | 凭证／流水／往来删除，应收／应付核销 | 指定对象、最新状态、影响确认及结果核验；不等于真实付款 |
| F4 | 财务用户场景与交付验收 | 全部批准项和例外明确，用户确认后才算完成 |

阶段不是一个巨大的 Goal。执行计划将 10 类能力拆为 28 项核心功能，每项映射到有依赖和验收条件的具体 Goal。六种账簿／报表及财务附件独立核验，不能以缺接口为由默默删需求，也不能凭科目余额自行声称还原有成正式报表。

## 最小实现原则

模型理解用户目标，后端限定客户／账套、财务接口、权限、参数、金额计算和执行顺序。沿用现有 Cordis 组合及实际有用的文件、凭据、计算、确认和回执设施，不建设新登录系统、通用工作流 DSL、万能接口工具、双模块切换或空壳插件。

功能 Goal 包含后端、自然语言工具、必要界面、测试和说明，按完整结果交付。当前界面足够时不另建操作中心。先完成已确认的查询，再推进受控新增和高风险维护；需要额外接口或浏览器适配时先补证据和范围授权。

任何业务写入前固定账套、核验输入并取得对应确认，先持久记录再发送；结果未知先回查，不盲目重试或切换创建接口。取消停止后续操作，不撤销已有记录。没有供应商证据时不承诺跨设备绝对去重、并发锁定或可撤销。

## 验收与下一步

单项验收记录真实外部数据、分页与合计、金额和状态、聚焦测试、真实产品组合的无 Key 快照，以及失败／取消／重试／重启行为。F4 复用这些证据并验证组合场景、客户账套范围、干净安装配置和升级数据保留。不把 HTTP 成功、空样例通过或报告生成当作业务验收。

下一步为 F0.2 确认逐项清单，然后完成 F0.3 开发／测试基线，再启动 F1.1 财务连接与账套定位。计划修改不自动创建 Goal；后续按已批准顺序执行，遇到范围扩大或新的外部操作授权需求时再确认。
