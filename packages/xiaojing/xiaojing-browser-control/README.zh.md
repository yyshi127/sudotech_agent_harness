# @deepseek-ai/dsh-xiaojing-browser-control

[English](README.md) | 中文

小兢会计的语义浏览器自动化插件。一个 Cordis 插件同时提供 `ctx.xiaojingBrowserControl`、注册 `browser_control` 工具，并使用浏览器各自独立的专用 profile 启动 Microsoft Edge 或 Google Chrome。`xiaojing-browser-control` 设置默认选择 Edge，并在任务未指定浏览器时生效。明确指定 Chrome 或 Edge 只会覆盖本次任务，不会修改保存的默认值；两个受控上下文可以同时保留，任一浏览器都不会静默回退到另一款。在 Windows 上，插件会在启动 Chrome 前检查强制 `UserDataDir` 策略是否会把独立 profile 重定向到用户正在使用的个人 profile；遇到这种情况会在创建 Chrome 进程前失败，不会在个人窗口留下多余标签页。插件保留显式可执行文件供测试或受控部署使用，但小兢会计 Windows 安装包不包含 Chrome for Testing。

`open` 会发现指定受控上下文中已经存在的页面，包括用户在该窗口中打开的标签页。它依次复用目标完全相同的页面、同源页面和空白页面，关闭该受控上下文拥有的多余空白标签页，并且只有不存在合适页面时才创建新标签页。后续语义动作继续操作该会话的活动页面。产品提示词会优先建议网站使用此能力，但不会拦截或禁止独立的 Shell、PowerShell 或 CDP 操作。所选浏览器启动失败时，系统会直接报告错误；除非用户明确要求另一款浏览器，否则不会自动重试另一款。

模型只能看到有界的页面文本和从可见交互元素生成的不透明目标 ID。每个目标都保留被观察到的准确 DOM 节点，因此节点被替换或脱离文档时会失败并要求重新观察，不会让位置型定位器误点另一个控件。目标会过期，执行动作或切换标签页后立即失效。工具不接受模型提供的 CSS 选择器、JavaScript、CDP 命令或浏览器配置目录。

访问内网、上传本地文件、使用 Enter/Delete/Backspace 等可能提交的按键、提交控件，以及名称涉及支付、删除、转账、发布或发送的控件，都必须先通过 `ctx.approval` 获得一次性授权。Delete 键以及标为删除、移除或卸载的控件使用强制确认，因此会话的 `never` 策略不能抑制该问题；其余上述动作继续使用普通审批。

Service Worker 流量的分类不假定请求关联页面 frame。公共目标正常放行；私有目标仅在 Worker 来源与一个已获得该主机授权的打开页面一致时放行。

取消或导航失败时，插件会关闭受影响的标签页；若它是浏览器最后一个页面，则先保留一个空白替代页。关闭浏览器操控时，插件会取消正在运行及排队的操作，并等待它们全部结束，之后的新请求才可重新启动所选浏览器。浏览器意外退出会使该实例的排队操作失效；插件卸载后会永久拒绝新的操作。产品以可见方式启动浏览器；用户可以登录后将其最小化，普通 DOM 操作仍通过 Playwright 继续执行，不移动物理鼠标，也不通过物理键盘输入。

## 配置

- `profileDir` 必填，用于专用 Edge profile。
- `chromeProfileDir` 用于专用 Chrome profile，默认是 `profileDir` 的同级目录。
- `browser` 是 `open` 或 `tabs` 未提供本次任务浏览器覆盖值时使用的默认值；产品默认值为 `edge`。
- `executablePath` 指向所选浏览器的可选部署受控可执行文件，只用于测试或受控部署；小兢会计 Windows 应用保持该项为空。
- `headless`、超时、观察有效期，以及页面、目标和文本结果上限均为部署配置。
- `allowPrivateHosts` 只用于确定性的本地测试，产品配置必须保持关闭。

## 模型体验

### `browser_control` schema

#### 模型看到的内容

模型会看到 [`browser_control` schema](../../../docs/tool-catalog.md#deepseek-aidsh-xiaojing-browser-control)，其中要求在用户明确指定浏览器时通过 `open` 或 `tabs` 传入该值，否则省略以使用保存的默认值；启动失败时不得自行选择另一款浏览器；它还要求先复用合适的现有页面，再仅操作最新观察中的不透明 ID。每个页面动作都会返回新的 `observationId`、有界可见文本和语义 `targets`；后续目标动作必须使用同一份观察中的 ID。网站操作使用本工具，而不是 Windows 电脑操控。

#### Token 影响

每次请求都包含一个稳定的工具定义。结果只会在当前会话后缀中增加有界的页面、文本和目标元数据，配置的结果上限会限制这部分可变输出。

#### KV Cache 影响

schema 在插件生命周期内保持稳定，不会导致不同轮次之间缓存的请求前缀失效。浏览器观察以普通工具结果的形式出现在该前缀之后。

## 已知限制与后续工作

- 当前实现只使用 DOM 语义与可见文本；不识别像素、不破解验证码、不绕过反自动化机制、不接管用户日常浏览器配置，也不控制页面之外的浏览器外壳。
- 完全由 Canvas 绘制的网站需要未来的视觉能力。
- 所选浏览器必须已经安装且未被设备策略禁止。Windows 的强制 `UserDataDir` 策略会让 Chrome 无法使用这条 Playwright 路径，因为它会把所有启动请求指向用户正在使用的个人 profile；插件会在打开浏览器前报告该状态。所选浏览器缺失或受阻时，系统都不会自动启动另一款浏览器。
- 原生身份验证、证书、UKey、下载和操作系统对话框不属于 DOM 自动化，可能需要用户恢复浏览器窗口或使用 `computer_control`。
