## 功能说明

成功的财务工具通过 `withFinanceCard` 在 `tool/result.meta` 中持久保存精简业务卡片。该投影复用各工具既有的 Host 展示函数，完整结果仍可供模型使用；Web 客户端可以重放业务摘要，而不展示原始参数和内部 JSON。失败调用不会伪装成成功卡片。

核销未发送结果在持久恢复和工具输出中保留有界的最后检查阶段 `preflightStage`。它标识本地检查，不表示供应商根因或重试权限；`final-confirmation` 表示批准之后的最终 Host 回调。旧结果没有阶段时仍可读取，且不被改写。不返回原始异常或凭据。参见[诊断决策](../../../.agents/notes/implemented/bug-fix/2026-09-14-write-off-preflight-diagnostics.zh.md)。

Finance专用工具 `finance_open_item_accounts` 读取明确的已有往来页所带账户属性，不表示完整目录。`finance_prepare_open_item` 使用同方向的 `accountReferenceQuery` 准备／修改，或按原本地ID查看记录。仅接受已观察到且启用的本位币账户；缺少ID／标志时保持未知，属性冲突时拒绝。预览保留来源查询与记录，不扫描其他期间。该页未出现的账户，包括尚无业务记录的账户，保持未解析。

往来准备校验方向、精确到分的正金额、日期及同账套资料ID。重新查询类别／项目，将 `auxiliaryItemNames` 组装为 `categoryName:itemName`；同名歧义、停用项目和未支持的分隔符会被拒绝，缺少项目状态时保持未知。`finance_create_open_item` 仅接受本地ID／版本，必须对完整预览获得本次强制确认。Host在确认后及发送前复核配置、来源账户属性和选中类别／项目。不自动新增缺失资料，不收付款、核销余额或生成凭证。

按归属隔离的原子记录在锁内复核版本，单次POST前持久保存未知状态与完整请求。重启或并发调用不能重新发送同一操作；这不等于跨操作去重。发送器重建固定参数、核实唯一账套身份，不重试写入，取消后仍保留已收到的成功ID。响应丢失、无效／过大JSON、HTTP失败或含密钥响应保持未知。Host先保存传输结果，再按已接受ID在原月份／方向内有界回查。业务内容、账户／类别／往来关联及初始未结余额分别比较；缺失、重复或失败的页面保持不可核验。无Key应用组合场景验证确认、版本修改、拒绝与持久结果恢复，不代表完整F3A实账验收。

内部科目标量准备校验编码／父级／分类一致性、UTF-8容量、同账套启用父级及返回的重复资料。其他父级下的同名项保留展示；已有末级或层级未知科目需要先核实历史影响才能改为父级。已核验的标量提交映射使用借方false、贷方true，与公开说明相反。回查分别比较原始值和配置，不会为匹配意外结果而改写预览。一级科目在方案中使用四位编码和null父级，公开请求不传父级字段，回查要求明确的空父编码；响应缺少该字段时仍为不可核验。显式核算选择解析同账套辅助类别及当前科目中已观察到的币种。提供accounting时两个编码数组都必填；省略时保留普通行为。批准选择保留ID／名称，回查比较准确配置，不添加本位币。未知或冲突资料拒绝；不注册币种、设置汇率或提升已有末级。参见[核算配置决策](../../../.agents/notes/implemented/feature/2026-09-14-subject-accounting-options.zh.md)。

内部辅助项目准备模块依据同账套返回资料，校验明确的类别、编码、名称、提交人和请求状态；拒绝经过筛选的资料子集、类别歧义及已返回的重复名称／编码，不隐式创建类别。六字段请求的提交人必须是有成真实成员。独立公开接口回查可核实返回的类别／编码／名称，但缺少状态；身份匹配不代表启用／停用核验完成。见[F3A提案](../../../.agents/notes/proposed/feature/2026-09-09-finance-business-creation.zh.md)。

仅Finance模式提供的 `finance_prepare_master_data` 使用顶层action／kind／input准备或修改，使用action／id查看；`finance_create_master_data` 只接受已保存的ID／版本并要求本次强制确认。Host在确认后及发送前再次核实资料和配置。普通科目创建支持一级科目，但其类型必须出现在当前账套同总分类的已返回资料中；也支持已启用的现有分支下级，要求类型相同且父级没有数量、辅助或外币核算。两条路径均不支持数量核算。科目类型保留有成名称，不用自造枚举；不匹配时拒绝，不改写方案。辅助项目准备交叉核对类别查询和项目查询中的类别身份。提交人使用用户确认的财务成员姓名，不以报销users／staff查询替代核实。工具不创建缺失类别，不改变已有记录。

基础资料记录保存归属当前用户上下文的可修改版本和准确预留请求。按本机账套／类型／类别／编码共享的目标预留，阻止另一份预览或会话绕过已接收或未知发送；只有持久明确拒绝或确证未发送，才允许另行确认新尝试。目标预留后、记录保存前发生崩溃时保守阻止继续。这不是跨设备幂等。适配器从不重试写入，保留无ID的已接收状态而不捏造标识。按原编码独立回查，缺失字段及类别身份变化保留为不可核验或不匹配。内容匹配不把未知发送转为成功，也不允许重发。辅助启用状态仍未核验；complete要求已接收且支持的各项比较通过。组装应用快照使用模拟接口验证真实确认／结果界面，不代表F3A全部能力的真实接口验收。

仅Finance模式提供的 `finance_prepare_journal` 准备、修改或查看归属当前会话的日记账记录。Host校验精确到分的正数金额、日期、已启用资金账户ID及同一账套内的类别选择。请求的subjectId使用资金账户ID，收入／支出的非活动侧为null，前序记录明确显示。映射到categoryName前检查类别方向及返回结果中的同名歧义。插入位置为指定日期／账户有界查询页最后一条返回记录之后，空页时为零，不代表历史全量。见[F3A提案](../../../.agents/notes/proposed/feature/2026-09-09-finance-business-creation.zh.md)。

`finance_create_journal` 仅接受本地ID与版本，必须对完整预览进行本次强制确认。Host在确认后和发送前复核配置、资料及插入位置。返回的资金账户币别ID、账户类型和原始方向参与比较；这些属性变化或消失时，原确认失效。未提供的属性保持缺失，不作推断。按归属隔离的原子记录在锁内再次检查版本，发送前持久保存结果未知状态和完整请求。重启、取消和结果未知都不允许自动重新提交。适配器不将读取重试用于写操作。返回字符串ID仅表示已接收，不是验证成功。工具可配置的maxBytes限制完整预览和持久记录大小。

日记账回查使用已接收ID及有界的日期／账户分页，比较业务字段、类别ID（而非供应商带收支前缀的显示名）、前序记录、未审核状态和返回的空关联。缺字段或未查到记录保持不可核验，错误字段标为不匹配。未提供的非活动侧金额与预留的null侧比较，不转换成对外报告的零。完成仅说明这条记录的技术比较，不证明日记账全量覆盖或实际资金收付。创建不调用生成凭证、审核、核销或支付接口；inspect只读取原操作及其已接收ID。

F2 准备校验拒绝无效日期／金额、重复辅助类别及整数分合计不平衡；只读解析器核验精确资料编码、启用末级科目、必需辅助／币种配置和账套身份。未知辅助状态仍保留未知。原币金额乘用户确认汇率后逐条十进制四舍五入到分，必须等于输入的本位币金额，校验不自动修改输入。这些检查不证明可写期间或汇率选取恰当，也不授权写入，见[创建决策](../../../.agents/notes/implemented/feature/2026-09-09-finance-voucher-creation.zh.md)。

内部凭证记录按归属使用带版本的原子文件，拒绝旧凭证／配置版本。提交预留返回前将完整请求、目标及 appId/flowId 连同结果未知状态保存。重载重建请求并拒绝不一致；传输观察分别持久化为已接收、被拒绝、未发送或结果未知，不代表已核验完成。已有预留的记录重启后不可修改或自动再次预留。

准备阶段可暂缺凭证号，但会在 `missingFields` 列出；提交必须有预览过的凭证号。普通创建接口发送方法核验账套身份，并在单次发送前再次检查 Host 配置，不受查询重试设置影响；保留稳定 appId/flowId，拒绝附件数量不匹配和有损 JSON 数值转换，不填写审核字段或分录借贷双侧金额。返回 ID 仅表示已接收，不是验证成功；响应丢失、HTTP 失败及模糊响应保持结果未知。

提交回查比较预留账套、返回 ID、凭证号、日期／期间、制单人及保留重复项的分录集合，并拒绝非预期的已审核／已结账状态。独立的逐分录辅助核算比较保留重复项和前导零编码；真实资料对照表明详情字段 `auxiliaryCategoryTypeId` 和 `auxiliaryCategoryId` 返回类别／项目编码，而非资料行 ID。缺失辅助数组保持不可核验，不当作空数组。币种比较将分录直接字段 currencyCode、originalCurrencyAmount 和 exchangeRate 与会计值及辅助编码组成集合核对，不取 foreignCurrencySimpleList。仅会计信息、辅助核算和币种数据匹配，且未请求原件或全部所选副本在源链接过期后独立核验匹配时，`complete` 才为真。这表示单张凭证技术核验，不证明票据真实性、会计建议恰当性、审核／过账或整个 F2 项目验收。回查失败不允许重新提交。

原件副本核验仅下载详情 `attachmentList.downloadUrl` 中精确匹配配置 `youchengAttachmentHosts` 的主机（默认 `yiqicai.oss-cn-zhangjiakou.aliyuncs.com`）。必须 HTTPS，无用户凭据、片段、非默认端口；不跟随重定向，不把源对象链接当作副本。整个核验受 `attachmentRequestTimeoutMs` 限时及 `youchengAttachmentVerificationMaxBytes` 合计字节上限约束（默认20000000）。关联核验比较实际大小／SHA256 集合，不信任或展示供应商文件名和声明大小。副本一致时，只有下载核验开始于全部源链接过期之后才标为留存 verified，否则 pending。缺字段、非许可地址或无法读取保持 unavailable，数量／内容错误为 mismatch；均不允许再次创建。安全上传回执本身仍标关联未核验，独立的当前副本证据位于 `readback.originals`。

`inspect` 也可在重启后读取已预留记录，查询已返回 ID 前核对保存的配置摘要；结果未知且没有 ID 时保持未知并要求人工核实。不返回私有提交请求或附件链接。回查失败保留已接收的凭证 ID。

`finance_create_voucher` 只接收已准备的 ID／版本。Host 展示完整预览请求本次强制确认，再次核验内容／资料／配置未变，持久化预留后单次发送。鉴权期间凭据／配置变化会阻止发送；发送后取消或回查失败不能抹掉已持久化结果。Host 配置 `youchengVoucherAppId` 默认为 `xiaojing-accounting`，flowId 使用记录 UUID。两个工具都仅限 Finance；外币创建要求科目已配置相应币种且换算校验通过。可写期间尚未独立核实，由有成写入校验并在确认中说明。模拟有成响应不代表真实写入验收。

所选 PDF／PNG／JPEG 原件使用财务凭证确认，不复用报销同意。上传前核对已确认存储目标及版本，并再次核对导入归属、限量字节、大小／哈希和格式头；上传请求携带对应格式的媒体类型。交给供应商的下载链接使用短期 OSS 兼容签名，并以带后缀的内联文件名结尾；链接不携带斜杠可能破坏供应商文件名推导的响应媒体类型参数。其他 OSS 传输仍使用 V4 签名。创建凭证前逐份保存私有上传回执，每份所选原件都必须对应已保存链接。任一上传、回执或配置检查失败均阻止创建；已上传对象保留，已保存回执可查看但不暴露签名链接。修改预览保留此前回执，但只提交当前所选原件。预留同时确保记录容量足够保存最长返回 ID；链接过期会阻止发送。上传和交付链接不证明有成已转存或在链接过期后保留文件。

`finance_prepare_voucher` 在 Finance 预设中开放 `prepareVoucher`：准备、修改和查看本地预览，不提交。修改必须提供最近返回的版本。来源必须属于会话导入日志和原始资料目录；准备、修改及查看重新限量读取字节，拒绝大小／哈希变化。这只核验导入字节，不证明票据真实性或转存成功。客户版本及凭据变化使配置摘要失效。工具配置限制分录数（`maxEntries`，默认100）和完整记录／结果字节数（`maxBytes`，默认131072）。结果明确保留待核验项，不构成确认或创建证明。

小兢会计 Finance 模式的本地纳税主体档案与会话客户上下文 Host 能力。该 Cordis 插件负责存储、基于 revision 的安全修改、首轮前选择、持久化会话绑定、浏览器 Remote 和模型可见的 Finance 上下文。它不修改 Agent Loop，并且只由小兢会计产品组合加载。

## 客户档案

已绑定客户的 Finance 会话在每次模型请求中接收固定查询证据规则，不依赖可选技能加载。跨来源比较必须核实账户映射、币种、期间口径、记录范围及记账状态；未知字段限定在对应来源和科目。这些规则约束解释，不保证供应商数据完整性或模型回答正确。

一条记录对应一个独立纳税主体。修改时必填主体全称、简称、纳税人类型、注册地区和会计准则；历史记录可在下次编辑前暂时缺少简称。可选业务字段包括统一社会信用代码、行业和财务政策备注。档案还可以选择一个财务系统：有成把测试／生产环境、AppKey、账套 ID 和所选账套名称保存在客户目录中；SDOO、用友和金蝶在各自连接器定义配置字段前只作为系统选择占位。科目映射继续为已有领域消费者保留，但不在客户资料表单中手工维护。

有成 AppSecret 通过 `ctx.credentials` 按客户单独保存，绝不会写入 `clients-v1.json`、Workspace 客户档案快照或会话事件。完整详情读取只返回该秘密是否已配置及是否可写。启用有成时必须已有 AppSecret 或在本次修改中提交新值；以后修改时省略该值会保留已有凭据。客户档案文件锁会覆盖凭据准备过程；若档案文件写入失败，Host 会在释放锁前恢复原凭据。

客户目录保存在 `$DSH_HOME/finance/clients-v1.json`，schema 版本为 `1`。每次修改都必须提交文件级 `expectedRevision`；编辑窗口持有旧 revision 时会被拒绝，不会覆盖另一个窗口的修改。写入使用文件锁和原子替换。文件损坏时插件拒绝启动，并保留原文件不变。客户只能归档，不能物理删除；归档客户仍可供历史会话读取，但不能创建新会话。

## 有成连接核验

一个客户选择一个账套 ID，保存于 `financeSystem.accountCode` 并以 `setOfBooksId` 发送。仅限 loopback 的 `financeClients.checkConnection` 读取已保存凭据、完成鉴权，并在返回的账套列表中精确匹配唯一 ID；仅名称相同或取第一条均不足以确认绑定。适配器依据 [V2 财务 API 文档](https://yiqbopenapi.superboss.cc/#/share/awXPk8nW/JzAPN6Xp)，使用 `/auth/getAccessToken.rjson` 和 `/finance/auxiliary/queryAccountList.rjson`。核验只返回选中的账套，不写入账务，也不返回 token 或供应商错误原文。

仅限 loopback 的 `financeClients.listYouchengAccounts` 接收编辑窗口的 revision、环境、AppKey 和可选的未保存 AppSecret。省略秘密时，只复用该客户已保存的凭据。账套发现请求不发送账套 ID，只返回授权范围内的账套 ID 和名称，不推断哪些账套属于当前客户。它拒绝过期 revision 和归档客户，区分空列表与请求失败，不改变已保存档案、凭据、连接状态点或已保存连接的 token 缓存。账套发现使用相同的请求期限，Host 释放时会等待请求结束。

Host Config 的 `youchengTestApiUrl` 和 `youchengProductionApiUrl` 均默认使用 `https://cwdata.yiqiyun.com`。测试与生产是内部标记，不代表对供应商基础设施的判断；二者可以解析为同一个 HTTPS 源。编辑器只读显示解析后的地址。`youchengRequestTimeoutMs` 默认是 20000，约束完整核验过程。请求拒绝重定向。token 只驻留 Host 内存，凭据和源地址未改变时最多复用 115 分钟。

核验状态保存在 Host 内存，客户修改、凭据替换或 Host 重启都会使旧结果失效。执行中的旧请求不能为已被替换的配置发布成功状态。绿点表示最近一次鉴权及精确账套查询通过，不代表全部业务操作权限或持续可用；红点附带安全错误分类，未核验显示灰点。客户资料保存与连接核验是独立操作：核验失败不会撤销成功的保存。

核验区分网络故障与完整检查超时，读取响应正文也受期限限制。HTTP 401 归为鉴权失败；HTTP 403 归为拒绝访问，不推断究竟由权限还是访问策略引起。供应商明确返回 IP 白名单拒绝时优先显示该分类。Client 只接收安全分类，不接收原始正文。

## 财务基础资料查询

方向说明只适用于当前查询类型。科目方向已经独立核验为0借1贷；未返回方向时，不能根据名称或会计惯例推断。这些模型指令减少歧义，但不保证每次生成的解释都遵守要求。

科目行保留受长度限制的供应商subjectType名称，与编码对应的总分类区分。缺失或null时省略，空字符串仍为空，两者都不能据此推断类型。工具说明与返回提示采用相同的已核验方向含义。不增加总分类筛选、不隐式继承父科目属性，也不增加写入权限。

仅 Finance 提供的 `finance_references` 工具使用会话已保存账套查询科目、辅助类别／项目、出纳账户和收支类别。科目查询可以指定根编码并要求完整返回子树；Host 先解析唯一根科目，在模型侧不加筛选地取得科目行，再按父级身份遍历，直至收集全部可达后代。Host 重新核对精确账套 ID 及唯一名称，查询项目之前验证类别，并在配置或凭据变化后丢弃结果。输入不能覆盖账套、源地址或秘密，不自动新增缺失资料。结构化行序列化为 JSON 写入日志结果和通用只读卡片，不透传供应商原始载荷。

`youchengReferenceMaxRows` 默认 1000，并作为 `pageSize` 发送；`youchengReferenceMaxBytes` 默认 262144，约束每个响应及最终完整结果。整个操作使用 `youchengRequestTimeoutMs`。这些接口没有文档化的页码／游标或总数，部分忽略 `pageSize`，因此 `coverage` 始终为 `unverified`；超过任一上限则失败，不静默截断。名称／编码精确筛选只针对本次返回集合。保留全部同名候选；返回集合中唯一，不代表全库唯一或已选定。

保留接口提供的科目父子关系、辅助及币种编码，以及各接口自己的启用／停用状态；缺失状态为 `unknown`。方向保留原值：科目与出纳账户分别独立核验为0借1贷，收支类别为0收1支。不伪造缺失的上级科目或方向值。

## 临时凭证查询

Host 内部记录安全分类与失败阶段（认证、账套核验、请求、响应校验）。网络传输异常归为 `network`，从固定允许列表追加可识别的连接重置、套接字、DNS 或连接超时原因码。未知错误码、原始异常信息和请求 URL 不会进入模型结果；投影校验失败在内部归为 `invalid-response`。Host Config 的 `youchengRetryTransientReads` 默认 `true`：认证及读取请求遇到 `ECONNRESET`、`UND_ERR_SOCKET`、`EAI_AGAIN` 或 `UND_ERR_CONNECT_TIMEOUT` 时，使用相同请求和原总期限重试一次。取消、永久 DNS 失败、HTTP／供应商失败和无效响应不重试。模型只会收到一条日常语言的可执行失败说明。读取失败不等于空结果，也不能单凭错误认定是供应商或配置问题。

`finance_voucher_detail` 通过 `/finance/certificate/info.rjson` 读取指定凭证。Host 与列表共用会话/工作区归属和凭据变更检查；适配器核对返回的 `accountId` 与 `certificateId` 后才发布。详情包含十进制字符串分录金额、凭证日期、会计期间、制单人及审核/结账布尔状态。附件、辅助核算及外币明细明确标注不在返回范围，不能理解为没有这些资料。工具使用已查询到的 ID 或用户提供的 ID；指代有歧义时选择候选，不猜 ID。

自然语言意图由 Agent 理解，不交给供应商摘要筛选。对于近义表达或业务含义，工具要求省略 `summary`，在限定期间内分页读取，结合全部分录、科目、借贷方向和金额判断。关键词未命中不代表业务不存在。非首页空页附带警告：供应商可能将越界页返回为 `count: 0`；报告总数为零前必须重查第一页。这些指令不等于真实模型语义验收已经通过。

Finance 预设通过 `./vouchers-tool` 暴露只读工具 `finance_vouchers`，调用 [V2 财务凭证列表](https://yiqbopenapi.superboss.cc/#/share/awXPk8nW/aXYwLJ2r)，不调用报销凭证导出接口。Host 从会话绑定确定客户、核验工作区，并将已保存 ID 解析为唯一且授权列表中名称不重复的账套，因为接口接受 `accountName`。咨询、Standard 会话、未配置连接、重名账套和查询期间档案变更均被拒绝。查询采用当前已保存的连接配置，不改变历史客户事实。凭据和供应商错误原文不会进入结果。

`month` 接受会计期间 `YYYY-MM` 或 `current`（北京时间本月）；省略时不限期间，不承诺按最新日期排序。凭证日期不能独立核验会计期间。每次返回一页、接口报告的筛选总张数、后续页标志、含十进制借贷金额字符串的分录及范围说明。`page` 默认为 1；配置项 `pageSize` 默认为 20，接受 1–100。未知查询字段、分页长度不一致或重复 ID 均失败；超过总页数的空页不代表账套为空。数值金额超过分单位安全精度时必须使用接口金额字符串。`youchengVoucherMaxResultBytes` 默认对每次响应及完整结果限制 65536 字节。查询期间配置或凭据变更会丢弃结果。取消和 Host 释放会中止请求。已记录的工具调用显示查询／结果卡片；连接绿点不代表查询权限。`finance_vouchers` 返回列表分页，`finance_voucher_detail` 负责单独查询凭证详情。

`monthEnd` 指定包含结束期间的范围，要求开始期间不晚于结束期间。`summary` 原样传给有成的 `abstractName` 筛选，拒绝空或纯空白文字。结果保留这两个条件及返回凭证的全部分录，包括摘要不同的行。后续翻页必须保留相同条件与每页张数。摘要精确／模糊匹配及非空期间筛选仍未核验；工具不猜测未说明的多值筛选分隔符。

## 保留的私有附件与报销后端

仅限 loopback 的附件配置属于本机全局设置，不属于客户档案。`ctx.credentials` 将 OSS 配置、只写 RAM 密钥对和 revision 一起保存；读取只返回配置与凭据状态。部署默认值为 Bucket `rhy-attachment`、地域 `oss-cn-hangzhou`、HTTPS CNAME `https://attachments.sudo.vip` 和前缀 `xiaojing/`，安装包不包含密钥。连接测试上传合成内容，通过签名 URL 下载并比对，然后尝试只删除该测试对象。保存配置不等于连接测试通过。

保留的 Host 附件操作只接受当前客户会话已导入且未修改的 PDF、PNG 或 JPEG。Host 在上传前校验导入归属、真实路径范围、字节数、摘要和文件头。云端对象名使用客户／会话标识和内容摘要，不使用纳税人名称；原件与云端发票对象均保留。上传请求将 `application/pdf`、`image/png` 或 `image/jpeg` 保存为对象媒体类型；凭证交付链接以带后缀的通用文件名结尾，不暴露来源文件名，也不添加带斜杠的媒体类型查询值。传输拒绝重定向，使用 `attachmentRequestTimeoutMs`（30000）、`attachmentMaxFileBytes`（20000000）和 `attachmentUrlExpiresSeconds`（3600）；签名 URL 不进入模型可见结果。RAM 策略应只允许对指定 Bucket 和前缀上传、读取、删除对象。当前 Finance 预设不注册独立附件上传工具。

报销配置与财务凭据分开，即使 AppKey 相同也不共用秘密。每个客户的独立凭据记录保存报销地址、AppKey、AppSecret 和 revision。默认地址是 `https://yiqbdata.superboss.cc`，也允许 `https://yiqbdatatest.superboss.cc`。报销企业归属由这组凭据决定，不由财务账套 ID 决定。`reimbursementRequestTimeoutMs` 默认为 60000，`reimbursementMaxResponseBytes` 默认为 16000000。查询只返回模板、人员、部门及脱敏收款信息，不返回供应商 Token 或完整银行账号。

保留的报销操作校验实时模板与所选身份，要求用户单次确认，然后上传已导入原件，将 URL 数组编码为 JSON 字符串填入 `orderComponentList` 的固定 `attachment.bindingVal`，即使模板元数据没有返回该字段也照常传入；不创建发票台账。独立的必填 `staff` 员工字段要求明确提供可访问人员的 `employeeId`，不能推定为申请人。仅支持人民币、单日日期、文本／数字附加字段及已支持的必填组件；必填项缺失或类型不支持时停止创建。`pushOrderStatus` 固定为 `1`，必须查询推送结果并回查单据为待提交状态才返回草稿成功。当前 Finance 预设既不注册 `finance_reimbursement`，也不注册报销 skill，因此保留后端不构成 Finance 对话能力。

在保留后端中，费用模板声明 `attachment` 时，其 `feeComponentList` 只接收该行所选原件的链接，复用同一次上传；费用附件为必填时也支持。这属于普通附件传输，不是发票台账关联。已有草稿回执不会被改写或重新提交来补传缺失附件。

在保留后端中，待回答问题或待处理报销确认会阻止创建及单独上传附件。问题失败／取消或确认被拒绝后，必须收到新的用户文字消息才能重新尝试写入；新消息不能替代逐单强制确认。Host 从会话事件重建此决定，从工具消息的 isError 标记读取问题失败，并在外部写入前复核。

私有、带 revision 的任务回执以 schema 版本 1 的 JSON 保存在 `$DSH_HOME/finance/reimbursement-operations`，记录所属会话、确定性请求编号、进度、文件名和单据号，不保存签名链接或凭据。每个所属会话使用独立锁串行处理请求；相同请求复用回执，写入结果不明时阻止本会话修改参数后再次创建，要求先回查。这不等于跨会话发票去重。用户结果区分已核实草稿、待处理、失败和异常状态。有成是保留附件 URL 还是转存原件尚未核验；临时链接本身不能保证附件长期可访问。

## Finance 专属工作区

Finance 拥有与普通 Harness 工作区分离的用户可见工作区根目录。桌面产品将其设置为 `文档/小兢会计工作区/Finance工作区`，其他部署也可提供不同的绝对 `workspaceRoot`。根目录包含一个固定显示为“咨询”的 Workspace，并为客户目录中的每条记录生成一个 `clients/<client-id>` Workspace。目录使用稳定客户 ID，而不是可编辑的显示名称，因此客户改名不会改变路径。

Finance 添加操作只把规范化后的 `workspaceRoot` 提供给本地 Client，作为目录选择器的初始位置。部署可声明 `ordinaryWorkspaceRoots`；Finance 启动时会拒绝与 Finance 根目录重叠的普通根目录，创建 Finance Workspace 时也会拒绝与配置的普通根目录或 Workspace Registry 中已注册普通 Workspace 重叠的所选目录。

创建客户时，系统先生成 `00-客户档案`、`01-财务政策`、`02-原始资料`、`03-会话作业`、`04-成果输出` 和 `05-归档`，并向 Harness Workspace 注册客户根目录，然后才提交客户目录记录。修改失败时会撤销新注册和新目录。启动时若发现上次创建中断留下的孤立 Workspace 注册，只移除注册并保留目录和文件，以便人工恢复。归档客户继续保留 Workspace 和历史会话，但不能新建会话。

Workspace 显示名称与财务列表成员关系独立保存在 `$DSH_HOME/finance/workspace-presentation-v1.json`，使用 schema 版本 `1`、revision、进程安全文件锁和原子替换。重命名会同时修改 Harness 注册标题和展示记录，不改变目录。移除咨询或客户 Workspace 只会从财务列表隐藏，仍保留注册、目录、客户档案和会话；通过添加操作再次选择同一目录即可恢复。列表中必须至少保留一个咨询 Workspace。

客户会话把选定客户根目录作为不可变 `cwd`，每个会话在 `03-会话作业` 下使用独立子目录。每个子目录都会原子写入 `会话信息.json`，记录会话 ID、客户 ID、客户档案版本和显示名称；完整聊天记录仍以 Harness 会话存储为准，该目录只保存作业文件和身份清单。会计期间不是客户目录或会话的固定属性；报税、查账、做账等 Skill 可按当前任务在原始资料、成果或归档目录下创建期间子目录。咨询必须运行在固定咨询目录。Host 会拒绝在客户目录中运行咨询，也会拒绝在一个客户的工作区中绑定另一个客户。

## 受控文件生命周期

用户继续使用同一个上传入口。客户 Finance 会话完成本地上传后，系统把文件复制到 `02-原始资料`，保留上传暂存文件；受支持图片还会继续作为原生视觉附件。通用 Finance 咨询会把文件保留在受保护的本地上传目录，并落盘一条会话级 `finance/consultation-file-imported` 事件，记录真实路径、显示名称、大小和 SHA-256。非 Finance 会话保持普通上传行为。

每个客户会话只在自身的 `03-会话作业/<session-id>` 目录中进行临时工作。Finance 预设增加 `finance_files` 工具：用户以自然语言要求最终版、导出、交付或保存正式成果时调用 `publish`，把已经存在的本会话作业文件复制到 `04-成果输出`；草稿、预览、试算和意图不明确的内容继续留在会话作业目录。只有明确归档意图才调用 `archive`，把该客户的原始资料、当前会话作业或正式成果复制到 `05-归档` 下按北京时间日期生成的子目录。明确提供安全相对路径 `archiveFolder` 时，本次操作改用 `05-归档` 下该目录，不再额外生成日期目录副本。两个操作都不会移动或删除源文件。

每次成功的客户文件复制都会追加到客户根目录下的 `.xiaojing-finance-files-v1.json`，其中保存 schema 版本 `1`、revision、所属客户和会话、操作、绝对目标路径、字节数、SHA-256 摘要及可选源记录 ID。对应的 `finance/file-imported`、`finance/file-published` 或 `finance/file-archived` 事件会在操作返回前落盘；通用咨询登记则落盘 `finance/consultation-file-imported`，不会写客户索引。这些事件使模型可见来源授权可以从会话日志重建。目标文件和客户索引采用原子写入；源路径无效、跨客户或索引损坏时会失败，并保留源文件和损坏索引不变。

## 会话上下文

空白 Finance 会话默认为通用财务咨询。浏览器可在第一轮之前把客户暂存在 Host 内存中，暂存内容不写入日志，并可反复更改。第一次模型请求会先追加并落盘一条 `finance/client-bound` 事件，再把上下文交给模型。该事件只包含不可变客户快照和客户档案版本。

以后修改客户档案只影响未来会话。历史会话始终从自身日志恢复原快照。`financeClient` 会话投影只向浏览器公开显示名称和绑定状态；税号、政策备注、科目映射和旧有外部系统标识保留在 Host。财务系统连接配置与凭据不会进入不可变会话快照或模型提示词。客户专属写操作统一调用 `requireBoundClient()`，通用咨询会被直接拒绝；只读 Finance 服务可以通过 `currentClientBinding()` 取得同一份不可变快照，也可以在没有客户上下文时继续运行。

Finance 预设消费端以 `@deepseek-ai/dsh-xiaojing-finance-domain/context` 独立导出。删除该预设配置行即可移除模型上下文；Web 组合中的 Host 客户档案服务仍可独立插拔。

每次 Finance 提示词组装都会提供由 `FINANCE_POSITIONING` 和权威 `FINANCE_CAPABILITIES` 清单生成的 `xiaojing:finance-capabilities`。一般能力介绍只使用财务资料处理、日常账务协助、财务分析与成果输出、财税支持和综合任务执行等产品定位，不主动罗列实现状态或未支持报表。具体能力问题、完整清单请求和实际操作使用详细清单；执行时还会核验当前连接、权限、账套、期间和数据范围。每个详细状态都标明适用范围：小兢会计通用能力、当前财务工作区或当前有成财务接入。有成接入的限制不妨碍通用咨询、处理用户提供的资料、基于可靠数据分析或未来接入其他系统。客户绑定只证明客户身份，不代表有成当前连接可用或具备接口权限。当前明确请求优先于历史意图；只读请求不能续办旧写操作，失效预览只能重新准备。准备、上传、提交、供应商接收和独立回查保持为不同状态。Standard 等其他预设不会获得 Finance 能力上下文。

## Remote 与隐私

`financeClients` Remote 提供客户档案操作、Workspace 列出／添加／重命名／移除／恢复操作，以及 `stage` 和 `sessionContext`。完整详情读取、全部写操作和暂存选择仅允许 loopback 连接。列表、Workspace 标识、会话上下文和凭据状态使用脱敏返回类型。凭据修改可以接收只写 AppSecret，但任何读取都不会返回该值。本地 Client 只会收到配置的 Finance 根目录，用于初始化添加目录选择器；不会收到各客户 Workspace 路径、密码、Token 或其他会话的完整不可变快照。

## 科目余额查询

仅 Finance 模式提供 `finance_balances`，通过绑定客户已保存的连接查询包含首尾月份的会计期间。`youchengBalanceMaxRows`（默认 1,000）包含汇总行；`youchengBalanceMaxBytes`（默认 262,144）限制每次原始响应及完整结果。查询期间客户信息或凭据变更会丢弃结果。通用只读卡片与会话日志呈现同一份报表，凭据不进入模型上下文。

金额保留接口借贷列及正负号，空字符串转为 `null`，不当作零；发生额空白或期初期末相等都不能证明本期无发生。规范千位分隔符（如 `1,000.00`）按文本去除，不转换成浮点数；错位分隔符拒绝返回。科目行与接口汇总行分开，调用方不得将父子科目和汇总重复加总。实测接口存在有数据但 `count` 为零的情况，因此 `coverage` 保持 `unverified`；未返回某科目不证明余额为零。更完整的科目层级仍需核验，不从含义未明确的字段推导常规期末净余额。

余额回答指令要求表格和结论始终保留借贷标签，科目行与汇总行的缺失值统一写“未提供”。金额相等不证明划转，生成文字不得添加无依据的算式。这些指令仍需真实回答验收，不是确定性的输出校验。

可选 `subjectLevel` 通过相同的接口起止层级选择一个正 int32 层级。返回科目行必须匹配该层级，接口汇总仍单独保留。结果和工作簿记录所选范围，省略参数采用接口默认值，不承诺取得所有子科目。

补充 `subjectLevelEnd` 时，从 `subjectLevel` 起查询包含两端的层级范围。适配器先读取起始层级，再根据 `hasChild` 将父科目 `subjectInfoId` 作为 `parentSubjectId` 查询下级，直至结束层级。请求关闭分页、明确本位币并包含禁用科目，只保留初次查询的汇总。重复科目、错误父级、缺失声明的下级、取消或累计行数／字节超限均拒绝整次操作。结果与工作簿保留所选范围；遍历不独立证明根范围完整，也不允许叠加父子科目余额。

范围查询要求唯一正数科目 ID 和非负父级 ID。返回父级必须恰好高一个层级且声明存在子级，非起始层级科目必须具有返回的父级。未到结束层级时，声明存在的子级必须返回；汇总标识丢弃。这些结构检查不证明接口没有遗漏其他根科目或同级科目。

Finance 分析技能区分引用来源值与用户要求的计算。查询回答保留工具字段含义，不重新推算余额；用户要求的计算须有可核验结果。过程与最终文字使用用户语言，并尊重不导出的选择。余额组装场景在查询前加载实际技能，同时验证两处指令。

跨来源比较须核验账户映射、币种、期间口径、数据集合和记账状态。在此之前，科目余额和出纳日记账分别报告为尚未对账，不称错误或未同步。日记账初始/合计标签不能在共用表格中变成科目期初/期末标签。

## 余额分析

结束月份或层级与起始值相同的冗余参数按同一单月、单层级请求接受；不同的结束值仍拒绝，在联网查询或发布文件前报错。

`finance_balances` 支持 `analyze: true`，须指定单个 `subjectLevel`、当前 `month`，可提供基准 `compareMonth`。它在同一客户配置版本下，按本位币、不分页查询同一层级，以稳定科目 ID 比较。八个借贷列通过整数分计算当前减基准的差额；缺失行或金额保持未知，科目资料变化时报错。`returnedRowSums` 仅加总返回的单层级科目行，排除接口汇总，任一单元格缺失或没有科目行则该列返回 null。完整性仍未核验，不是全账套合计或试算平衡结论。现有余额限制约束两次来源的总行数和完整结果；`exportExcel` 只发布业务差额、来源行、加总和核对工作表，不写入查询元数据，也不认证完整性。分析不能与期间范围或层级范围混用。

## 日记账查询

仅 Finance 模式提供 `finance_journals`，查询单个会计月份，省略日期时补齐实际月初和月末；显式日期必须位于该月份内。Host 读取分页前核验已保存账套及指定出纳账户 ID，凭据轮换或客户资料并发修改会丢弃结果。`youchengJournalMaxRows`（默认 1,000）限制包含余额标记的日记账数组及账户查询；`youchengJournalMaxBytes`（默认 262,144）限制原始响应和完整结果。工具 `pageSize` 默认 20，最多接受 100 笔业务行。

业务行必须有接口 ID、范围内日期及至少一项收支金额。无日期和 ID 的初始余额、合计标记单独作为汇总，不算交易。十进制字符串保持精度，不安全的数字分位值拒绝返回。原币与本位币分开，缺失金额为 null，调用方不得跨币种或重复叠加汇总。日志 JSON 与通用只读卡片呈现相同限制，不含凭据。接口没有已核验的总数或末页信号。仅有汇总的分页不证明账套没有流水。

日记账账户筛选使用供应商的 `subjectId` 出纳账户标识。返回业务行必须标识同一个账户；缺失或不一致时拒绝结果。账户标签为空时采用返回的科目标签，不补造缺失编码。

结果提示将空页表述限定为“本次查询页未返回业务流水”，不证明当天或整月没有发生。币种编码缺失时仍标为未提供，即使账户存在币种 ID。初始余额和合计金额保留接口标签，回答标题也不例外；相邻日期余额相同只是金额对照一致，不独立证明日初或日末余额。工具要求模型在回答前检查所有标题、表格和结论是否存在矛盾断言。这些是模型指令，不是对生成文字的确定性保证，仍需真实回答验收。

## 日记账收支核对

工具开头的说明要求自然语言收支比较及合计使用 `analyze: true`，包括同时查询其他财务数据的混合请求。原始页提示再次说明所需账户查询和分析调用，不允许手工相减未核验汇总。这是模型指引，不是对生成回答的确定性校验，仍须真实混合请求验收。

`verificationOwner: xiaojing` 明确内部报告中的核对由小兢会计完成，不是供应商保证。工作簿用业务语言呈现核对结果，不暴露内部执行方或覆盖范围标签。

`incomeMissingValueCount` 和 `expenseMissingValueCount` 统计已返回业务行中金额未提供的单元格数，不表示缺少交易或遗漏分页。工作簿列名明确这一区别，来源行及空值保持不变。

`finance_journals` 使用 `analyze: true` 时，必须提供绑定账套返回的明确 `cashAccountId`，分页由后端控制。可选 `baselineMonth` 比较另一个月份；两段范围均可提供月份内成对日期。Host 读取到空业务页，拒绝重复 ID 和变化的合计，并将已提供收支金额的精确和与明确返回的接口合计核对。业务行必须标识同一币种，两个非空期间的币种也必须一致。汇总行币种可保持空白，不从业务行补写。

`coverage: empty-page-and-totals-reconciled` 表示这些核对，不代表接口声明总数、原子快照或完整账套。原始空值和缺失金额计数仍保留：已提供值之和相符，不证明每个空值为零。末页合计缺失、业务币种未知、金额不符或超过限制均拒绝报告。不计算历史余额，也不与总账对账。[决策记录](../../../.agents/notes/implemented/feature/2026-09-07-finance-journal-reconciliation.zh.md)说明该范围。

操作复用现有日记账行数/字节限制、`youchengAnalysisPageSize` 及一个 `youchengRequestTimeoutMs` 总时限。每页使用已保存连接并核验指定账户；配置或凭据变化会丢弃整份报告。用户要求导出 Excel 时，重新查询并通过现有文件生命周期发布精确来源行、空值、核对合计和差额。工作簿只包含核对结果及对应业务明细。核对失败不发布文件；金额及类似公式的字符串保持文本。

## 应收应付查询

Finance 专属工具 `finance_open_items` 按明确的会计期间和页码，分别查询应收或应付。已保存且通过授权核验的账套 ID 由 Host 提供，不接受模型覆盖。`youchengOpenItemMaxRows` 默认 1,000，包含列表及上一页汇总；`youchengOpenItemMaxBytes` 默认 262,144，限制原始响应及完整结果。客户资料或凭据并发变更会丢弃结果。工具默认页大小 20，最多 100。

负数 ID、无日期且无科目或辅助项目身份的合计是汇总，不是业务记录。有日期的正数 ID 记录必须属于绑定账套，并提供金额、余额和币种；零金额业务记录仍保留。保留接口记录数，但完整性尚未核验。金额保留十进制精度、null 和币种，不将辅助项目名称推断成往来对象身份，结清字段也不证明银行收付款。日志 JSON 与通用只读卡片呈现相同限制。不执行写入、附件下载或核销。[决策记录](../../../.agents/notes/implemented/feature/2026-09-07-finance-open-item-query.zh.md)说明汇总分类依据。

## 往来比较与汇总

按科目或辅助项目分组要求每条业务记录提供非空标识，不能用名称代替 ID。缺少标识会拒绝整份分析及其导出；其他字段有效时仍可按币种汇总。

缺少分组标识时返回固定的本地说明，并提示可按币种汇总，不归类为认证或网络故障。供应商原始错误文本仍不对外显示。

往来回答指令将 `previous-page` 保留为“上一页总计”，不称初始余额；将 `total` 保留为“接口合计”，不推断本页范围。用户要求的导出可与首次查询一起执行。后续另行导出须显式沿用方向和期间；Host 从第一页开始读取，并将导出业务行数与接口声明总数核对。成功回答只给业务范围、记录数量和完整发布路径，不叙述这段内部取数过程。这些指令仍需真实模型验收，不构成生成文本的确定性校验。

两个往来工具同时约束最终结论和中间表格：期间筛选选择记录，不是历史余额快照。有成接口提供业务明细，小兢会计本地计算分组与差额，不称接口汇总；汇总币种为空时保持未确认。回答报告返回记录的未结余额，不将其改为月末余额。结果说明保留数据限制，不携带开发阶段的待验收状态。

Finance 专属 `finance_open_item_analysis` 按往来记录数读取所有声明页后，按币种、科目或完整辅助 ID 组合分组。整个读取/比较只鉴权一次，共用 `youchengRequestTimeoutMs`；`youchengAnalysisPageSize` 默认 100。既有往来行数上限适用于每段期间，累计分页字节与完整报告均受往来字节上限约束。总数变化、短页、重复 ID、账套/条件不符或取消会拒绝整份报告，不接受模型提供的会计数据行。

分组保留来源记录 ID，以原币精确汇总金额和余额。可选基准比较在同币种内用当前组减基准组；计数核对完整的集合中不存在的分组按零参与差额。`coverage: vendor-count-reconciled` 表示分页与声明总数一致，不代表独立数据验收或供应商原子快照。返回余额不是历史期末余额。余额报表及日记账在完整性与币种前提核实前不进入本工具。固定指令属于稳定提示前缀，查询条件及计算结果进入普通工具日志。

## 往来工作簿序列化

工作簿序列化器接收 Host 生成的分析结果，只写入分组结果和按需生成的期间差额，不写入查询条件、覆盖状态、限制或来源记录 ID。金额和业务编号明确写为文本单元格，保留小数精度和前导零；外部名称不会变成公式。文本金额不是 Excel 数值，不能宣称可直接使用 SUM。仅在用户要求导出时，`finance_open_item_analysis` 接收 `exportExcel: true`：Host 重新查询，通过既有会话文件生命周期发布本次报告，返回报告和已提交文件。它不导出此前查询的快照。写文件之前及开始发布之前检查取消；已开始的发布正常提交，发布未完成时保留工作副本。不写入供应商业务数据。

## 模型体验

### Finance 客户上下文

#### 模型可见内容

每个 Finance 会话都会获得权威能力清单，以及当前咨询或客户绑定状态。通用 Finance 会话还会明确声明当前未绑定客户，禁止推测客户事实。客户会话获得 `finance/client-bound` 中记录的不可变快照、当前任务的期间指引和业务交付规则：最终回答、卡片、表格和文件先给业务结果与实际数据；除非用户明确要求技术诊断，不展示技术名称和内部证据；只有当限制会影响结果理解、操作安全或下一步行动时，才用日常语言简短说明。所有 Finance 工具都会先投影模型需要的业务字段和后续操作字段，诊断元数据保留在 Host 记录中，底层失败也会在进入模型前改为可执行的日常语言。能力回答只能来自该清单，不得由 persona、skill 名称、工具名称或历史对话扩展。Standard 等其他预设不会获得 Finance 客户或能力上下文。

#### Token 影响

每次 Finance 请求都会增加固定的能力清单。绑定会话还会增加随客户字段变化的内容；未选择的客户档案不会进入请求。实际查询与受控写入通过普通工具结果记入日志，确认摘要通过强制审批服务记录。已移除的报销提示词、工具和 skill 不再增加当前模型可见 Token。Token 用量随返回行数与操作详情变化，不包含完整供应商数据集；凭据与签名链接排除在外。

#### KV Cache 影响

能力清单在同一咨询或绑定状态下保持稳定。绑定上下文还会随客户快照变化，因此只有模型可见值完全相同时才能共享提示词缓存。未变化的运行时上下文不会在每一步重复追加。

## 已知限制与暂缓事项

应收应付删除回查将 `balances.original` 与 `balances.base` 分开：保留记录金额和分币种删除差额都必须匹配。本位币证据只在币种代码明确相同时使用原币余额，并标注 `same-currency`；外币缺值仍不可用。不补写返回或保存的余额字段。合计仅覆盖原查询范围，不是全账户余额；详见[余额核验决策](../../../.agents/notes/implemented/bug-fix/2026-09-14-open-item-deletion-balances.zh.md)。

核销恢复独立比较已保存与当前原始业务账户ID，包括已结清目标。身份缺失不会丢弃有效的内容或余额观察，但身份缺失或变化均不允许报告operation=matched。没有保存身份的旧已接收回执保持不变，并报告身份不可用；恢复不会用当前数据补齐该缺口。必须身份、内容、核销金额及回执关联流水全部匹配，才能识别原操作，而非确认实际银行收付款。

全额核销准备从与来源页相同的响应中取得原始业务账户ID，并在带版本的预览中展示。内部发送器在占用前核对原始身份、最新原始账户状态、账套归属及已知凭证／订单关联。即使业务投影行未变，缺少身份、停用账户或已提供关联也会阻止发送。身份不可用的原记录仍可读取，不补造元数据，但不能占用发送名额，必须重新预览。Host通过资金账户对应的准确科目代码、启用末级科目及明确空币种列表核实本位币执行路径，不解码数值币种ID。期间锁定状态仍不可用，确认时明确说明；未观察到的关联及外部并发不作保证。

内部应收／应付删除记录独立于传输结果保留原始按总数核对的清单、未知字段及版本。带已知阻止原因的预览可以检查，但不能预留。原子文件和锁按 Host 归属及账套／业务 ID 绑定预留，不按查询方向拆分目标占用。修改使确认失效；损坏或中断留下的占用阻止发送。接收成功及未知结果在重载后仍禁止重放；明确拒绝或未发送只允许另建并重新确认的提案。记录层不提供确认界面、新查询关联核实或供应商并发锁。

内部应收／应付预留删除发送器重新核对原方向／期间的完整证据及账套名称唯一身份后，只发送一次 booksName/managementId 请求。调用方须核实未知关联风险、强制确认准确版本并在发送前持久预留；适配器不是权限或持久化服务。证据或配置变化时不发送。响应丢失、无效或含密钥时保留未知，不重试。响应只代表传输观察，不是独立删除核验；独立的 finance_delete_open_item 工具在发送前强制确认准确版本并持久预留。

`finance_journals` 和 `finance_open_items` 接收 `exportExcel: true`，重新导出所选日期或会计期间。日记账接口没有总记录数，因此导出从第一页读取至首个空业务页；往来导出从第一页读取，并将全部业务行与接口声明总数核对。工作簿只包含业务明细和单独的业务合计，保留原币/本位币及空值，不写入查询诊断。往来结清标志和组成金额仍是来源值，不是银行付款证据。日记账导出不证明全账套覆盖或原子快照。两项操作沿用其他财务导出的受跟踪本地发布及取消规则。

`finance_balances` 可通过 `exportExcel: true` 导出新查询的接口来源结果。工作簿包含科目行和单独的合计表，保留十二个金额字段，以“本年累计”标记年累计列，不写入查询诊断。余额及比较工作簿使用可读列宽、冻结表头和明确期间标签，并分开显示来源行、分组汇总和勾稽结果；精确金额保持文本，避免二进制数舍入。`未提供` 表示 null 而不是零，负数保留在原借方/贷方列。生成文件不会把此有界来源结果变成完整财务报表，因此确实影响使用的范围限制由随附回答说明，不插入表格。

分析包含一级科目逐列合计核对及单独的工作表。`matched` 表示已提供金额之和与唯一接口合计一致，不表示空值为零或已返回全部科目。缺失或重复合计不可核对，仅子级查询不支持此核对；保留原始金额及空值数。

每个期间八列的核对状态由程序计数。回答指令要求总结使用该计数并与表格一致，不构成对生成文字的确定性校验。

明确指定单月一级科目的普通查询也附带核对结果与计数，不增加网络请求或改变查询范围。完整增强结果仍受字节上限及配置校验约束；分析工作簿通过单独的业务工作表呈现核对结果。其他选择仅返回来源数据。

查询核对明确标记 `verificationOwner: xiaojing`：有成提供金额，小兢计算核对结果，不是有成出具的核验证明。

核对合计或统计核对状态的请求使用一级科目的 `analyze: true`。工具要求模型不从原始报告重算列数、不沿用冲突的历史答案；四个仅保留来源的 Balance 字段不进入八个借贷列的核对。

用户要求按期间及摘要条件导出凭证时，`finance_vouchers` 支持 `exportExcel: true`；“导出全部凭证”不传期间。Host 忽略调用方分页，使用财务凭证工具配置的分页大小，从第一页开始读取，拒绝总数变化、短页或重复页，唯一凭证数与接口总张数一致后才发布一个工作簿。XLSX 只包含全部导出的凭证分录，不添加响应未证明的币种或合计。金额精确文本及公式防护沿用往来导出的发布规则。持久发布证据保留路径、大小和 SHA256；模型可见回执与用户卡片只包含账套、请求范围、凭证和分录数量、文件名及保存位置。导出不是此前结果快照，也不是供应商原子快照。

- V1 只支持手工维护，不提供 Excel 导入、联系人、合同、销售、收费或 CRM 流程。
- 凭证删除预览、强制确认及恢复结果区分凭证不存在与附件清除。本操作不清理原OSS文件，也不证明有成转存文件已清除或永久保留；不发送附件清理请求。
- `finance_prepare_voucher_deletion` 准备／修改版本或检查已有删除；`finance_delete_voucher` 强制确认准确版本。准备操作只接收准确凭证 ID，并根据绑定账套和新读取的详情生成供应商请求：`accountName` 加上一个只含 `cerId` 的 `cerInfoList` 项。它不要求本地创建来源，也不接受调用方传入 appId、flowId、账套身份或接口覆盖。共享账套／目标占用阻止接收或未知结果后的跨会话重发。删除记录使用格式版本2；旧格式记录会被拒绝，旧占用也会保守阻止再次发送。恢复需要两次完整一致的无筛选清单；错误、超限及不完整分页均不证明不存在。原始详情指纹保守地使变化预览失效，但不是供应商锁。完整产品验收及其余 F3B 动作由[维护提案](../../../.agents/notes/proposed/feature/2026-09-10-finance-destructive-maintenance.zh.md)跟踪。预留在确认后核对完整已确认记录，包括未递增版本的请求参数变化。发送器在认证前固定配置、请求参数和检查证据，拒绝最终回调期间的变化。真实实验用最小请求创建并删除专用凭证244499，随后完整清单与实验前一致；尚未单独抽样浏览器手工录入来源。
- `finance_prepare_open_item_deletion` 在保存的客户、方向及期间范围内准备／修改版本，或只读检查原记录。通用工具详情展示准确目标、已知阻止原因及未核实约束；`execution.state=requires-confirmation` 表示预览符合执行条件；独立的 finance_delete_open_item 工具强制确认准确版本后只发送一次。按总数重复查询不证明全账套不存在；缺失金额或状态不当作零或安全。返回凭证 ID 时，即使显示文字为空也阻止操作；其他核销金额缺失仍待核实。网页提示存在联动删除，公开 V2 的对应行为仍需核实。恢复保留原始预览及传输结果，拒绝变化后的配置，不重发；保留记录余额与内容独立检查，不认证供应商总额或银行收付款。限制项为 maxBytes、maxRows、maxPages 及 pageSize。
- `finance_write_off_open_item` 通过Host强制确认、已有记录存储及预留发送器执行准确预览版本。它要求新查询的准确目标及完整未结金额，保留币种与未知组成金额，并将内容与核销金额观察分开比较。发送器在发送前重读原目标页、启用资金账户资料及唯一账套名称；币种 ID 缺失、证据变化或方向错误时不发送。它只单次发送文档已收／已付参数，响应字符串保留为 receiptId，不当作 journalId。记录存储保留准确原始页、资金账户资料及版本，拒绝变化后的确认内容，并在发送前按账套／往来 ID 占用目标，不依赖查询方向。已接收或结果未知的记录重启后不能修改或重发；只有明确拒绝或未发送才允许单独确认的新方案。中断或损坏的占用记录阻止发送，大小限制预留最大回执的空间。共享持久占用串行化本应用对同一账套／往来的删除和核销尝试，但不能串行化外部写入。仅余额观察一致不能识别操作或证明银行资金变动；回执关联检查见下文。Host在确认前后及发送前最终回调中重查原始状态、原业务身份、已知关联及当前资金账户／科目配置，证据变化时拒绝。期间状态未核实，不提供供应商并发锁或自动重试。
- `finance_prepare_open_item_write_off` 准备／修改整笔未结余额方案，或读取归属当前客户的原记录。通用详情保留方向、目标、资金账户、金额、日期、记账人及预期流水影响。Host绑定客户／工作区，保留原始证据与传输回执，并拒绝配置变化。检查时独立重查原始来源页；分页变化或查询失败不能证明已核销。已接收回执允许执行两次有界、按总数校验且包含末尾空页的整月日记账查询。原内容、核销金额及唯一回执关联的WRITE_OFF日记账均匹配时报告 `operation=matched`；缺失、重复、冲突或变化的证据保持未核实。日记账必须匹配资金账户、原往来单位、日期、币种及方向金额。该观察不改写原结果、不允许重发，也不证明银行资金变动。符合条件的本位币往来及当前仅核算本位币的资金科目，准备结果报告 `requires-confirmation`；否则拒绝资格核实或保持不可用。准备本身不请求批准或写入。独立执行器确认准确目标／版本，并说明期间限制；不支持外币换算、部分核销或反核销。
