# Agent Note: 小兢会计 Finance 第一阶段集成验收

Status: implemented

[English](2026-08-29-xiaojing-finance-stage1-integrated-acceptance.md) | 中文

## 问题

Finance 第一阶段横跨客户档案、不可变会话上下文、受控客户文件、文档标准化、官方来源依据、确定性试算和流程 skill。各包测试分别通过，不能证明实际交付的小兢会计组合仍保持 Standard 模式不变、两个客户完全隔离、来源位置可追溯、试算使用绑定客户事实，也不能证明升级后仍可读取已有数据。

仅凭构建成功或文件字节未变化就宣布可发布并不完整。它可能漏掉跨包装配错误、当前解析器无法读取旧 Finance 记录，或客户文件落入其他客户目录等问题。自动测试也不能产生真实 DeepSeek 费用，不能依赖随时变化的搜索结果。

## 决策

第一阶段使用一个无 Key 的组装验收 snapshot。它挂载实际交付的小兢会计组合，创建一个 Standard agent 和两个 Finance agent，并为两个 Finance agent 注入彼此不同的不可变客户绑定，其中包含各自的财务政策、科目映射和外部系统标识。两个客户把完全相同的 CSV 字节导入各自独立的客户根目录。snapshot 会证明第一阶段 Finance 专属工具、当前五个 Finance 专属 skill、Standard 模式没有 Finance 工具、Prompt 只包含当前客户、文档列表只包含当前客户、跨客户文档 ID 被拒绝、读取结果保留来源行、存储路径互相独立，并且增值税试算会根据各自绑定的纳税人类型得到确定结果。它还固定当前权威能力清单及报销排除规则。香港税务请求会在不发起网络请求的情况下返回超出范围。

桌面升级校验现在使用生产环境的 `FinanceClientStore` 读取一份包含两个 schema 版本客户的合成上一版本数据副本。校验会读取各自私有字段，确认原始资料、会话作业、成果输出和归档文件仍位于正确客户根目录，并证明兼容性读取不会改变任何受保护文件的字节。该语义校验补充原有整棵目录摘要比较；它不声称真实发布的 0.1.9 已经包含 Finance 数据。

当前中国大陆税务示例由人工对照全国人大、国家税务总局和财政部官方页面。自动验收保持无 Key 和确定性；真实官方页面检索与模型回答属于人工发布检查，不写入 snapshot。

第一阶段验收门禁只证明源码可进入交付准备，不等于安装包验收。产品回归、Web 预览、桌面检查或数据保留校验失败时，仍然禁止打包。本次验收发现，无 profile 的根构建可能覆盖小兢共享 Client 产物。产品仓库现在默认把完整构建固定为小兢 profile，同时保留显式官方 profile；未打包桌面端也会拒绝缺失或非小兢的构建记录。

## 验证

组装预期输出测试位于 `apps/cli/tests/finance-stage1-acceptance.expected.e2e.ts`。Finance 聚焦测试覆盖客户存储与绑定、官方依据分类、文档格式与视觉提取、确定性试算、工作区路由和预设组合。产品回归覆盖品牌、用量统计、上传、原生视觉、微信、Edge、Windows 控制、Visualize、桌面小兢和桌面生命周期。桌面用户数据校验使用生产读取器检查合成升级副本，并证明读取过程不会修改数据。

## 考虑过的替代方案

- **只依赖各包测试。** 否决，因为各包测试不能证明交付 profile 组装了正确能力，也不能证明独立包对客户作用域的理解一致。
- **只使用一个客户样本。** 否决，因为单客户无法暴露 Prompt、文档、路径或外部系统标识跨客户泄露。
- **升级时只比较文件摘要。** 否决，因为字节没有变化也可能已经无法被当前解析器读取；必须同时完成语义读取并验证读取后摘要不变。
- **在自动验收中使用实时搜索和真实模型。** 否决，因为结果会变化、需要凭据、产生费用，并让源码门禁依赖外部服务可用性。

## 后果

第一阶段现在有一个紧凑的失败信号，可以同时发现组合、隐私、可追溯性、确定性试算、司法辖区限制、能力文案和旧数据可读性问题。该 fixture 有意使用合成数据，不能证明每一份真实客户文档、官方页面响应、Windows 安装或后续业务流程都正确。当前有成操作另有聚焦和组装验收；SDOO、申报、过账、付款和合规不属于本第一阶段快照。本验收步骤不会生成安装包。
