# Agent Note: 小兢会计历史会话准入

Status: implemented

[English](2026-09-22-xiaojing-historical-session-admission.md) | 中文

## Problem

小兢会计 0.2.4 版本在 v0 会话中写入了五种上游冻结清单未列出的财务事件。更早的 0.1.9 会话还可能把首条用户消息紧挨在 `step/start` 之前。新版[系统头节点规则](2026-09-02-system-prompt-as-surface-node.zh.md)要求第一个系统位置先于用户消息，因此上游严格迁移会拒绝这两类已发布数据。

## Decision

v0 清单只接纳小兢会计已发布的五种财务事件，校验其版本和顶层成员，并将客户或文件记录作为 JSON 原样保留。其他未知历史事件仍不受支持。

仅当来源经过前代格式转换、会话无种子且轮次已开启时，V2 到 V3 阶段才会调整一条紧挨首个步骤之前的 `user/message` append：依次输出原 `step/start`、空系统头节点和原用户消息，再重映射后续序号引用。用户消息的 id、时间戳、内容以及模型可见消息间的相对顺序保持不变。直接 V2 来源及其他首步前排列仍拒绝迁移。

## Alternatives considered

**跳过已发布会话：** 保留上游规则，但会使现有小兢会计用户升级后无法读取历史会话。

**接纳任意未知事件或宽泛地重排：** 两者都无法确定历史载荷的归属，也无法保证跨越中间操作后仍保留事件含义。

**把新系统头节点放在用户消息之后：** 这违反当前会话规则，可能使模型请求中的提示词位置改变。

## Consequences

该例外会在目标日志中调整一个生命周期标记与一条用户事件的顺序，但保留源文件和模型可见消息顺序。它无法修复已有损坏日志，也不处理与首个步骤不紧邻的首步前消息。专项迁移测试覆盖准入、拒绝、引用重映射及源文件内容不变。
