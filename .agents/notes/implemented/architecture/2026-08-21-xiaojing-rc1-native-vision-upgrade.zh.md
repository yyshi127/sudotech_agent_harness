# Agent Note: 小兢会计 rc.1 原生视觉集成

Status: implemented

[English](2026-08-21-xiaojing-rc1-native-vision-upgrade.md) | 中文

## Problem

小兢会计的 rc.8 基线包含隔离的品牌层、本机用量统计、修补后的文件上传入口、微信回传、浏览器与 Windows 自动化、强制删除审批、固定桌面身份，以及升级后必须保留的 0.1.9 用户数据。官方 `dsh-v0.1.1-rc.1` 增加原生图片消息和持久附件存储，但浏览器界面只提供粘贴与拖放，没有小兢既有的文件选择器。用上游手势替换产品上传路径会失去文档选择；继续把图片序列化为本机路径则无法使用官方多模态提供方，还会在 Goal 和 Plan 模式重复之前的 `image_url` 不兼容问题。

升级还把本机凭据文档从发布前的扁平 mapping 改为 version 1。只有官方迁移能够保留 API Key、设置、会话、人格、profile、历史用量、旧上传文件和新增附件根目录，而且不会生成明文备份或在失败后留下半迁移数据，产品才能声明支持覆盖升级。

## Decision

### 保留记录的上游合并

升级分支从小兢提交 `xiaojing-history-20260930-2` 开始，正式合并官方 tag `dsh-v0.1.1-rc.1` 对应提交 `dsh-v0.1.1-rc.1`。合并提交 `xiaojing-history-20260930-3` 保留双方历史。[`product.json`](../../../../packages/client/xiaojing-product/product.json) 记录官方 tag、commit 和产品集成基准；官方 rc.1 shell、renderer、附件、凭据和提供方实现继续作为真源。

rc.1 已删除过时的 `packages/util/home` Knip 配置，因此对应且已不再适用的 vendor-rescope 精确编辑被正式退休，而不是重新创建无效目录。保留的中文 vendoring cookbook 后置文本沿用官方文档生成器已经输出的本地化 `rescope.zh.md` 链接。

### 产品展示与功能隔离

`xiaojing` Client profile、五个中性品牌／初次使用 slot、产品插件、主题、启动元数据、默认人格、用量 Host 与 Client 插件、微信 Host 与 Client 插件、浏览器控制插件、电脑控制插件、profile 遮蔽防护和固定桌面 manifest 继续独立于官方 UI owner 和 Agent Loop。包版本与 rc.1 系列对齐，桌面产品版本仍为 `0.2.0`。已有保存设置始终优先；只有没有保存默认模型的部署才从小兢组合获得 `deepseek-v4-flash-vision-exp`。

### 在原生图片之上保留唯一上传入口

`ui-conversation` 提供会话作用域的 `conversation.addImages(files, limits)`，作为与提供方无关的图片接入 seam。粘贴、整页拖放和外部文件选择器会在分配预览 URL 之前，共用一次原子的媒体类型、数量、单文件大小、总大小和输入状态校验。修补后的 `dsh-file-uploads` 会拆分混合选择：PNG、JPEG、WebP 和 GIF 调用原生接入，文档和不支持的图片格式继续使用旧上传路径，并附带不能直接视觉识别的明确文字。普通、Goal 和 Plan 输入使用同一个控件。原生图片提交由 rc.1 负责，持久化到 `$DSH_HOME/attachments/v1`；同步准入失败时，文字与图片草稿保持可恢复。

### 微信视觉与模型作用域

微信频道保留加密 CDN 下载和 `$DSH_HOME/uploads` 来源副本。受支持的栅格图片还会成为原生 prompt 图片块，并由 rc.1 附件存储持久化。持久化“微信助手”会话通过 `session.selectModel({ saveDefault: false })` 切换到 `deepseek-v4-flash-vision-exp`；这个新增的通用选项保留普通界面保存模型选择的行为，同时避免频道图片修改用户全局默认值或其他会话。不支持的图片格式和普通文档继续作为本机路径文字。图片数量、读取或 Host 准入等确定性失败会返回适合手机阅读的原因、完成当前队列项并继续 FIFO，而不会进入暂时故障自动重试路径。

### 计费与持久数据

计费兼容适配器是唯一接触 rc.1 的用量 seam。`deepseek-v4-flash-vision-exp` 使用内置的公开 Flash 价格，图片消耗绝不自行估算，只依据提供方 usage 结算。历史记录保留已存价格版本和准确分类费用。桌面数据约定增加 `harness/attachments`；安装器身份与 `%APPDATA%\@sudotech\xiaojing-accounting-desktop` 保持不变。0.1.9 fixture 门禁在私有副本上运行官方扁平凭据迁移，对比迁移前后 Key 的 SHA-256 指纹，验证 version 1 文件仍可编辑，拒绝有歧义的旧文档且不修改原文件，并禁止出现明文备份或半迁移旁路文件。

Windows 上的杀毒软件或文件索引器可能短暂占用设置文件，拒绝最终 rename。共享原子写入器现在只对 `EPERM`、`EACCES` 与 `EBUSY` 做有界重试，而且不会先删除旧目标。永久故障或重试耗尽时会移除临时兄弟文件、保留之前的完整文件，并继续把错误返回调用方。

## Verification

聚焦测试覆盖产品 profile 条件与 fallback、普通／Goal／Plan 模式下的统一混合文件路由、共享图片准入、持久附件校验、DeepSeek 图片序列化、包含 Vision Exp 的用量结算、微信原生图片传递与仅会话模型切换、确定性图片拒绝不阻塞队列、立即回执与 30 秒进度、浏览器标签复用和浏览器选择、Windows UI Automation，以及 `never` 审批策略下仍强制确认删除。桌面门禁验证不可变安装器身份、准确默认 profile 迁移、旧会话与人格可读、凭据迁移、设置和工作区字节不变、旧上传文件、原生附件根目录保护及历史用量合计。仓库生成器、typecheck、build、lint、hygiene、文档同步、coverage、无 Key snapshot、小兢 Web 预览和 Electron 开发预览继续作为发布门禁；用户确认预览并在之后通过真实 0.1.9 到 0.2.0 Windows 覆盖安装测试之前，仍禁止打包。

## Alternatives considered

- **用 rc.1 粘贴和拖放替换小兢文件选择器。** 这会采用最少的上游界面，却会删除产品已有的统一文档与图片入口。中性图片接入方法让既有选择器把原生图片归属委托给上游，而不用复制草稿实现。
- **所有选择的文件继续走旧上传路径。** 这样能保留文档行为，但受支持图片只能以本机路径文字发送，官方视觉提供方无法检查，并且 Goal 或 Plan 会再次出现不兼容消息序列化。按 MIME 分流可以保留一个用户手势，同时把每类文件交给正确 owner。
- **微信收到图片时修改全局默认模型。** 这样可以让当前频道请求可路由，却会意外改变新桌面会话和用户保存的偏好。仅会话选择把兼容调整限制在持久微信助手内。
- **使用 rc.1 价格版本重算旧用量记录。** 当前 Flash 数值相同，但改变已结算记录的版本会重写历史，也会让后续调价含义不清。历史记录保持不可变，只有新的 Vision Exp 请求使用新内置价格表版本。
- **解决冲突时把产品功能写进 rc.1 UI。** 这样可以减少插件连接，却会重新制造产品层原本要避免的升级成本。合并只修改中性 seam 和兼容适配器，小兢行为继续可卸载。

## Consequences

小兢在不失去既有文档流程的前提下获得官方多模态存储和提供方序列化，后续图片入口可以复用一个通用 Client API，不再复制草稿状态。微信频道可以检查受支持的手机图片，同时保留移动端回执、队列顺序、安全确认和全局模型设置。不支持的格式仍可传输，但需要已安装的文档或转换工具；本次升级不增加 OCR、ModLens、视觉桥接或其他模型提供方。

上传集成仍是针对 `dsh-file-uploads` 维护的 pnpm patch，因此上游插件更新必须显式重放补丁并运行混合模式行为测试。源码与 fixture 门禁可以证明应用 reader 兼容，但不能证明 NSIS 注册表和文件替换行为。发布 0.2.0 前，安装器必须保留永久身份，并通过从 0.1.9 开始的真实覆盖安装。
