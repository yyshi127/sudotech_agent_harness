# Agent Note: 在 web profile 中随附 ModLens 与提示词文件上传

Status: implemented

[English](2026-08-15-bundled-modlens-file-uploads.md) | 中文

## 问题

Windows 应用需要提供图片检查和提示词文件附件能力，同时不能要求每位用户在安装完成后再自行安装插件。如果这些包只安装到某个可变 profile 中，全新安装就不具备完整能力，而且 profile 本地依赖解析可能逐渐偏离应用所测试的版本。文件上传客户端还会隐藏其内部输入引用，但核心输入框仍为该引用保留文本宽度，因此可见光标会与文字实际插入位置分离。主页输入框采用弹性布局时，附件栏还可能被压缩到低于固定附件卡片的高度，并与输入卡片重叠。

## 决策

应用依赖图把 `@liustack/modlens` 固定为 `3.16.6`，并把 `dsh-file-uploads` 固定到上游提交 `3ea46e1583eac426cc34e191ea811e71b0c8347e`。随发行版交付的 `web` profile 模板会在 `@deepseek-ai/dsh-base` 与 `@deepseek-ai/dsh-web-app` 之后叠加这两个组合包，使全新应用从安装目录解析它们，而不需要 profile 本地副本。两个项目均保留其上游包名、作者归属、代码仓库和 MIT 许可证声明；本仓库只负责集成，不主张其实现由本仓库开发。

针对 `dsh-file-uploads` 的 pnpm patch 会把文字选择位置限制在隐藏文件引用之前，在打开文件选择器时维持输入框焦点，并让附件栏成为不可收缩的 54 像素高 flex 项。隐藏引用仍保留在输入状态机中，因此提交的提示词仍能重建所有附件；新增文字则紧邻这些元数据之前出现，光标位置与可见插入位置一致。

## 验证

应用 patch 后，固定版本的软件包通过语法检查及上游的七项 Node 测试。由 Playwright 驱动的已安装 Electron 应用测试会上传一个临时文件，在隐藏引用存在后聚焦输入框并输入 `sd`；最终输入值把 `sd` 存在隐藏引用之前，选择起止位置均为偏移量 2。同一次测试测得附件栏与附件卡片均为 54 像素高，附件栏与输入框之间有 8 像素间距，不再重叠。检查结束后，测试只删除自身创建的临时上传文件。

## 考虑过的替代方案

**应用安装完成后，再把两个插件安装到每位用户的 profile。** 这会让初次使用依赖额外的包管理操作，产生重复依赖，并允许 profile 本地包副本偏离经过测试的应用依赖图。

**把插件源码并入 Harness 包。** 这样会在不改变扩展点的情况下把维护责任转移到本仓库；固定的外部依赖加显式 patch 既能保留上游归属，也让本地差异便于审查。

**等待文件上传插件发布上游修复。** 当前应用需要立即提供可用的输入框，而且不兼容问题明确且改动很小。采用 pnpm patch 能让未来替换为上游修复成为显式操作，而不是隐藏一个本地分支。

## 后果

任一随附插件版本发生变化时，都需要重新构建桌面发行版。固定的上游提交升级时，必须审查文件上传 patch，并选择重新适配或移除。仍与旧版安装自有 web 元组完全一致的 profile 会迁移到随发行版交付的模板；包含额外、缺失或重排组合包的 profile 仍归用户所有，系统不会改写。
