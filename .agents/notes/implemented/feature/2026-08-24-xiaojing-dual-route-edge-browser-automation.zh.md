# Agent Note: 小兢会计 Edge 双路线浏览器自动化

Status: implemented

[English](2026-08-24-xiaojing-dual-route-edge-browser-automation.md) | 中文

## Problem

专用 Playwright Edge 路线可以稳定执行 DOM 自动化，但不能接管用户个人 Edge profile 中的普通标签页。之前尝试的 UI Automation 和截图方式只能发现部分窗口，速度慢、依赖前台焦点、会遗漏网页控件，还会让普通点击出现坐标审批；它们既不能保证目标身份，也不能可靠保留已经完成一部分的表单操作。个人页面不可用时总是再打开专用页面还会产生重复标签，并可能让桌面任务与微信任务选择同一个可见页面。

## Decision

`@deepseek-ai/dsh-xiaojing-browser-control` 继续作为一个可移除 Cordis 能力，通过同一个模型工具提供两种适配器。专用适配器是默认路线，使用小兢独立持久 profile 启动已安装的 Microsoft Edge，并通过 Playwright 执行 DOM 自动化。个人适配器是可选增强，通过随附的 Manifest V3 扩展接管用户个人 Edge 中的普通 HTTP 或 HTTPS 标签页。在非受管 Windows 安装中，扩展由用户手工侧载和配对；开发与内部部署不依赖 Edge Add-ons 发布或企业策略。

协调器维护进程级页面注册表，并把一个页面租给一个 Agent 轮次。页面选择依次优先当前会话已经绑定的匹配页面、当前激活且匹配的个人页面、其他精确 URL、合适的同源页面，最后才使用专用空白页或新页面。它不会导航无关的个人标签，只有明确传入 `disposition: "new_window"` 时才创建顶层窗口；个人扩展中途断线后也不会在专用 Edge 中重放已部分完成的任务。`turn/end`、取消、失败和插件卸载都会释放租约并分离个人标签。

每个 frame 只执行一次有界语义扫描，并遍历嵌套 iframe 和开放 Shadow DOM。目标保存角色、无障碍名称、状态、序号，以及附近对话框、表格行和区域上下文，而不是选择器或坐标。原生控件和 ARIA 控件直接进入投影；具有 pointer 交互语义的紧凑可见 `div`、`span` 和 `li` 控件会投影为按钮，同时抑制继承样式产生的子元素重复目标。每个动作执行前都会重新解析该指纹；React 替换节点但语义等价时可以继续，身份或上下文变化时则失败并要求重新观察。`act` 可以执行有界的 click、fill、type、select、check、uncheck、hover、press、scroll、upload 和 wait 步骤列表，校验已完成状态，在首个失败处停止，并通过 `completedSteps` 和 `failedStep` 返回结果，不会重放已完成步骤。

普通浏览器工作保持后台 DOM 自动化，不会把截图坐标、Windows UI Automation 或 `computer_control` 当作自动兜底。`show` 是唯一明确切到前台的动作。上传以及提交、发送、发布、支付、转账或产生其他外部影响的动作会在对应批次开始前审批一次；即使会话通常设置为从不审批，删除仍必须确认。原生对话框、验证码、关闭的 Shadow DOM、受保护 Edge 页面、InPrivate 标签、本地文件页和纯 Canvas 控件继续交由用户处理。

个人桥接只监听 `127.0.0.1` 的 `53170–53179` 端口。配对使用八位一次性码，有效期两分钟，最多允许五次失败。配对成功后生成随机长期密钥，分别保存在 Harness 凭据服务和扩展本地存储中。桥接会校验固定扩展 ID 和协议版本，日常重连还要求双方通过与随机 nonce 绑定的 HMAC 证明持有该密钥，密钥本身不会重新传输。密钥、原始 CDP 流量和网页内容不会进入设置界面或日志。模型只能调用固定语义动作，不能传入 JavaScript、CSS 选择器或任意 CDP 命令。扩展只在任务期间附加，并在完成、失败、取消或断线时分离。

`@deepseek-ai/dsh-client-ui-xiaojing-browser-control` 继续独立可移除，并负责仅回环地址可见的设置分区。它显示专用 Edge 就绪状态、打开随包扩展目录、打开 `edge://extensions`、开始或取消配对、显示脱敏扩展版本和连接状态，并可撤销授权。删除 Host 与 Client 的组合配置行即可完整移除浏览器功能，不需要修改 Harness 核心、小兢产品层或其他插件拥有的持久数据。

本决策取代[小兢会计仅使用 Edge 的浏览器自动化](2026-08-24-xiaojing-edge-only-browser-automation.zh.md)中“个人浏览器接管延期”的说明。原说明继续负责 Chrome 的移除及旧 Chrome profile 的非破坏性处理。[小兢语义浏览器与 Windows 自动化](2026-08-21-xiaojing-semantic-automation.zh.md)继续负责能力隔离和 Windows 原生自动化。

## Alternatives considered

- **通过 UI Automation 操作个人 Edge。** 否决，因为很多操作要求获得焦点、无障碍树并不完整，而且无法提供 DOM 级目标身份或可靠的后台表单操作。
- **DOM 失败后使用截图和坐标点击。** 否决，因为坐标不是稳定目标身份，布局变化后可能操作错误控件，而且普通导航会因此产生不必要的审批。
- **使用远程调试端口启动个人 Edge。** 否决，因为它要求特殊启动 profile，不能安全接管已经运行的普通 profile，也会改变用户的浏览器生命周期。
- **只保留扩展路线。** 否决，因为非受管 Windows 不能静默安装或授权扩展；专用 Edge 必须继续作为开箱即用且独立可靠的路线。
- **个人任务断线后在专用 Edge 重试。** 否决，因为断线前已经完成的外部操作可能被重复提交。

## Verification

专用路线测试覆盖重复及跨会话页面复用、连续一百次复用不产生重复标签、逐轮租约隔离、嵌套 iframe、开放 Shadow DOM、带上下文的重复名称、委托事件 pointer 标签、React 节点替换、SPA 导航、下拉与复选状态、有界多步骤表单、部分失败不重放、受保护删除、中断导航、重启及卸载。桥接测试覆盖随包扩展的扫描与点击路径、配对成功、过期、五次失败、错误扩展身份、错误协议、错误密钥、附加／分离、取消、断线及凭据撤销。Client 测试覆盖回环限制、专用状态、扩展安装动作、配对状态、脱敏状态、断开连接及 slot 卸载。类型、构建、lint、hygiene、文档、产品层、组装预览和聚焦回归仍是发布前必过门禁。

## Consequences

小兢会计现在通过一个稳定 Edge 工具同时提供立即可用的专用路线和明确的个人标签增强路线。系统会先复用现有页面，浏览器任务不能共享正在租用的页面，多字段操作可以减少模型往返，普通网页操作也不会抢占鼠标或触发坐标审批。个人 Edge 需要一次手工侧载扩展，附加期间会显示 Edge 正常的调试提示；移除或断开扩展后，专用 Edge 仍然可用。
