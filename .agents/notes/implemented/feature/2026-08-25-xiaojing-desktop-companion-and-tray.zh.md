# Agent Note：桌面小兢与系统托盘生命周期

状态：已实施

[English](2026-08-25-xiaojing-desktop-companion-and-tray.md) | 中文

## 问题

小兢会计的任务进度原来只能在主窗口中看到。主窗口被隐藏或关闭后，用户无法从桌面判断 Agent 正在思考、使用工具、等待确认还是已经结束。原 Electron 生命周期也把主窗口当作应用生命周期，这与长时间桌面任务和微信频道冲突：关闭窗口可能停止后台工作，而不是让小兢会计继续驻留在系统托盘。

桌面角色不能接收任务文字，也不能成为第二个任务执行器。动画状态必须与 Harness 核心保持可移除隔离，不暴露会话内容，并且在主窗口隐藏后继续工作。收起角色与退出整个应用还必须具有不同的行为和术语。

## 决策

`@deepseek-ai/dsh-xiaojing-desktop-companion` 是仅限小兢产品的 Cordis Host 插件，观察已经记录的会话生命周期、审批和脱敏微信状态事件。纯跟踪器按会话维护开放轮次、未完成工具、未解决审批和最近终态计数，并按固定优先级归并：等待确认、失败、执行、思考、成功、待机。完成轮次保留成功状态 2.5 秒；失败、阻塞、达到最大 token 和中断轮次保留失败状态 5 秒。用户主动终止的轮次直接回到待机，不显示为失败。

Host 通过仅限 loopback 的快照和 Server-Sent Events 端点，只发布 `state`、`activeTaskCount`、`approvalCount`、`weixinOnline` 和 `revision`。会话标题、提示词、文件名、工具参数、模型回复、凭据和消息内容都不会进入跟踪器或传输。插件不修改 `agent-loop`、工具、模型请求或会话持久化。

`@deepseek-ai/dsh-client-ui-desktop-companion` 注册 order 为 1000、仅限小兢产品的 `desktop-companion` 设置栏目。产品层在 order 1010 注册“关于小兢”，因此“桌面小兢”直接位于最终产品信息页上方。renderer 获得八个受限 Electron preload 方法：一个只读应用版本查询，加上状态、唤醒、收起、重置、视觉尺寸、显示主窗口和订阅。每一份返回宠物状态都在 preload 边界校验。普通浏览器没有 preload bridge，因此只显示 Windows 桌面版可用提示。

原生生命周期由 Electron 拥有。它创建透明、无边框、不抢焦点、置顶且跳过任务栏的宠物 BrowserWindow，只在角色表面接受鼠标交互，支持拖动、双击恢复主窗口，并提供不含歧义“退出”文字的右键菜单。角色默认显示为原始视觉尺寸的 50%，可在 30%–100% 范围内持久化调整；状态提示会跟随缩放后的头部，同时保持文字可读。没有保存位置时和执行“重置桌面位置”时，完整宠物窗口都会放在小兢会计主窗口内部右下角并保留固定内边距；用户拖动后记住的位置仍然优先。启动时创建的宠物窗口会接收只供 renderer 使用的查询标记，等到主应用界面加载完成后再等待 3 秒，然后显示一次持续 5 秒的自我介绍；首个任务状态会取消欢迎语，手动重新创建的窗口不携带该标记。窗口把脱敏状态映射到七张生成的透明角色姿态，并通过 CSS 实现呼吸、眨眼、思考、执行、等待确认、成功和失败动作。连续空闲 3 分钟后，renderer 会从思考、等待确认或执行素材中随机选择两个不同姿势，每个展示 3 秒，再恢复默认姿势并等待下一个周期。这项巡游不改变脱敏 Host 状态，也不显示任务状态气泡；任务开始会将其取消，Windows“减少动态效果”会将其禁用。收起操作销毁该 BrowserWindow 和 renderer，Host 与任务继续运行。

Electron 主进程在应用就绪时创建托盘。关闭主窗口会把它隐藏到托盘并显示一次本地提示；最小化仍进入任务栏。第二个进程通过单实例锁恢复已有主窗口。只有托盘中的“退出小兢会计”会停止 Host 和整个应用；存在活动任务、微信在线或状态无法读取等中断风险时，该操作必须确认。

宠物可见性、视觉尺寸、一次性托盘提示状态和受限显示坐标原子保存到 `%APPDATA%\@sudotech\xiaojing-accounting-desktop\desktop-companion\preferences-v1.json`。缺少偏好文件时默认以 50% 尺寸显示。显示器、分辨率或缩放变化后，已保存坐标会恢复到最近可用工作区。该路径属于桌面用户数据保护清单。

## 评估过的替代方案

- **把宠物渲染在主网页中。** 否决，因为主窗口隐藏时宠物也会消失，无法提供独立桌面表面或托盘生命周期。
- **使用 Live2D、视频或逐帧动画。** 否决，因为首版需要控制素材体积和空闲 CPU。七张透明关键姿态配合 CSS 动画即可用较小运行体积保持角色一致性。
- **保持关闭按钮直接退出应用。** 否决，因为用户只想清理桌面主窗口时，会中断桌面任务并断开微信。
- **收起时保留宠物 BrowserWindow。** 否决，因为隐藏动画仍占用 Chromium renderer。收起会明确销毁窗口，再从最新全局状态重新创建。
- **向 renderer 暴露通用 IPC、Node 或 BrowserWindow。** 否决，因为原生集成只需要八个固定读写操作和一份不含任务内容的状态订阅。
- **从助手文字或工具名称推断状态。** 否决，因为文字检查可能泄露任务内容，而且不如权威生命周期和审批事件可靠。

## 验证

纯跟踪器测试覆盖状态优先级、并发轮次、工具、审批、终态计时、用户终止、微信连接和不含任务内容的快照。Client 测试覆盖设置注册、普通浏览器 fallback、bridge 校验、唤醒／收起／重置／尺寸状态立即更新和释放。Electron helper 测试覆盖 50% 偏好默认值、可接受尺寸范围、已保存位置限制、主窗口内部初始及重置位置、显示器移除和负坐标。产品层和用户数据门禁要求两个组合配置行、受保护偏好路径、托盘生命周期标记、产品版本一致性及升级 fixture 字节保持不变。

Electron 开发预览仍是检查不抢焦点、鼠标穿透、拖动、多屏位置、收起后释放 renderer、关闭到托盘、托盘恢复、第二实例恢复、六种视觉状态和带风险确认真正退出的必要原生验证。

## 结果

主应用窗口隐藏后，小兢会计可以继续作为不暴露任务内容的桌面状态表面运行。用户能够在不影响任务执行的情况下独立收起或唤醒角色，并且只能通过明确的托盘命令退出整个应用。状态功能保持在小兢 Host 与 Client 插件中，Windows 专属窗口、动画、托盘和持久化留在 Electron 产品层。未来可只替换角色素材而不改变任务状态聚合；未来 Harness 升级若生命周期 API 变化，也只需调整事件注册。
