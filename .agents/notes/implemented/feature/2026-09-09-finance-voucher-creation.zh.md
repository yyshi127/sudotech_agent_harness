# Agent Note: 财务凭证准备与确认创建

Status: implemented

[English](2026-09-09-finance-voucher-creation.md) | 中文

## 问题

F1 查询不提供持久化准备、准确版本确认、写入恢复或原件核验。报销确认不授权财务凭证。

## 决策

Finance Host 管理限定到会话、客户及已保存配置的准备版本和发送记录。模型提出业务值，创建前核验真实资料并强制确认。输入校验拒绝无效日期／金额、重复辅助类别和 bigint 整数分合计不平衡；资料校验要求精确编码、唯一启用末级科目及明确辅助／币种配置，未知辅助状态仍为未知。原币金额乘用户确认汇率后逐条十进制四舍五入到分，必须等于输入的本位币金额。这些检查不证明可写期间、汇率选取恰当性或票据真实性。

逐归属记录使用带格式版本的 UUID 文件、原子写入和逐记录锁；仅准备状态且内容／配置版本一致时可修改。确认期间不持锁，预留重新核对版本，发送前保存完整请求、账套、appId/flowId 和结果未知状态，并确保容量足够保存最长返回 ID。重载重建并校验请求；任一提交结果都不能再次预留。稳定 flowId 使用本地 UUID，appId 由部署配置管理。

Finance 专用准备和创建工具分离本地提案与写入。创建只接受 ID／版本，展示完整预览请求本次强制确认，再次校验资料／内容／配置，随后预留并通过普通接口发送；发送方法在鉴权后再次核对配置。不对创建使用查询重试，不填审核字段，不静默损失小数精度。文档规定的2xx参数错误判为拒绝；数字字符串 ID 只表示已接收，不代表核验完成。模糊、超限、HTTP 失败或丢失响应保持未知。发送结果先持久化再回查或处理取消；查询已接收 ID 失败不抹掉 ID，也不允许重发。

原件上传使用财务确认及其存储目标，不使用报销同意。核验导入归属、真实目录、限量字节、大小／哈希及 PDF／PNG／JPEG 文件头；不能通过别名重复选择同一文件。上传请求将对应媒体类型保存到对象。交给供应商的下载使用 OSS V1 查询签名并以带后缀的通用内联文件名结尾，不添加带斜杠的响应媒体类型查询参数；上传、连接测试和清理传输继续使用 V4。这样，即使供应商解码完整源 URL 后按最后一个斜杠截取转存文件名，最后一段仍带正确后缀，同时来源文件名和凭据不进入模型输出。创建前逐份保存私有上传回执，所有所选文件必须匹配已保存链接；存储版本变化、缺回执或链接过期会阻止发送。上传失败或取消可能在 OSS 留下对象，不自动清理或静默省略。修改保留此前回执，但仅提交当前所选原件。原有报销上传仍遵循自己的确认规则。

基本回查比较账套、ID、凭证号、日期／期间、制单人、状态及完整分录集合。辅助核验将编码与各自会计分录关联，保留重复分录和前导零。真实资料对照表明供应商详情中带 Id 后缀的辅助字段实际返回类别／项目编码，而非资料行 ID；缺失数组保持不可核验。币种核验将分录直接字段 currencyCode、originalCurrencyAmount 和 exchangeRate 与会计值及辅助编码关联，保留重复项，不取 foreignCurrencySimpleList。外币创建要求科目支持及换算校验通过；可写期间尚未独立核验，并明确告知由有成写入校验。complete=true 要求本张凭证的会计字段、辅助信息、币种数据及每份所选原件匹配，且源链接过期后原件留存核验通过；不证明票据真实性、会计判断、审核／过账或整个 F2 验收完成。

现有 finance-voucher-draft 技能区分建议、本地准备与用户要求的创建；准确准备版本仍经强制确认，保留用户确认的外币信息并检查十进制换算，对已接收或未知操作使用检查而非重发。真实应用组合快照包含实际传给模型的技能正文；模拟模型响应不等于真实语义可靠性验收。

原件回查从部署许可的 HTTPS 主机核验副本，不跟随重定向，不复用源对象地址。合计字节及整体下载时限有界；实际大小／SHA256 集合证明关联，不使用供应商文件名／大小。下载核验开始于源链接过期之后才证明留存，此前保持 pending；不可核验与不匹配分别记录，仅固定状态／警告进入模型。真实合成样例已核验本位币／外币创建、辅助核算、PDF／PNG 副本字节及源链接过期后的留存，不扩大为全部账套或格式保证。

## 考虑过的替代方案

**复用报销编排：** 授权和模板语义不适用，仅共享原件字节核验、存储及确认基础能力。

**直接提交模型 JSON：** 金额平衡不能证明真实资料、准确确认或响应丢失后的恢复能力。

**重试未知创建：** 不完整查询或客服去重说明都不能证明未创建；保留原记录并核查，不切换另一创建接口。

**把 V4 下载链接交给供应商：** 其中带斜杠的 `x-oss-credential` 值可能在文件名推导时被误认为最后一段路径，造成原扩展名丢失。V1 只用于短期供应商下载，内部传输继续使用 V4。

## 验证

聚焦测试覆盖输入／资料、并发及旧版本预留、回执匹配、存储变化、发送结果和限量副本核验。附件测试要求上传携带格式对应媒体类型，且供应商链接解码后按最后一个斜杠截取的片段以正确后缀结尾；真实组合凭证回放对 PDF／PNG 链接执行相同要求。真实组合快照覆盖预览、实际点击“拒绝／允许一次”按钮、确认中修改、响应丢失、重复发送防护、回查失败、原件副本核验及部分上传失败，Standard 不开放这两个工具。在收到响应时取消，仍保存已接收 ID，支持只读恢复并阻止再次提交。这些使用模拟有成响应；独立真实实验已核验本位币／外币创建、原件副本留存、全新 Host 恢复及重复提交防护。当前配置的真实模型读取合成 PDF，按真实科目解析其中业务事实，并在本地预览保留来源哈希；另行验证的口语修改和强制拒绝未写入财务数据。开发状态文档管理 F2 技术验收证据及其与 F4 发布验收的区别。

## 后果

两份创建文档对必填字段和附件的说明不一致，目前仅核验普通接口。客服 appId/flowId 说明不能证明跨设备去重；结果未知时必须核查，不能重发。期间核验仅覆盖已测账套和期间，其他期间仍由有成校验。为兼容供应商解析器，供应商下载链接使用较旧的 OSS 查询签名格式，并按同一配置时长过期；已有错误副本不会被重写。供应商文件名／大小元数据仍不作为权威证据，回查不显示带签名参数的名称，也不以声明大小证明转存成功。技术核验不认可会计处理恰当性，也不替代用户发布验收。
