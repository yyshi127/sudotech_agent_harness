# Agent Note: 显式科目核算配置

Status: implemented

[English](2026-09-14-subject-accounting-options.md) | 中文

## 问题

公开接口接受选中的辅助类别和币种编码，但科目创建始终发送空的辅助和币种列表。普通科目验收不覆盖这些配置，新增成功响应也不包含新科目ID。

## 决策

可选的 `accounting` 方案包含明确的 `auxiliaryCategoryCodes` 和 `currencyCodes` 数组。省略时保留普通科目行为；重复编码、不完整对象和额外协议字段均拒绝。当前账套的新鲜类别资料提供辅助ID、编码和名称。币种必须在当前账套科目中有唯一、不冲突的名称观察；这是有界的正向资料来源，不是完整币种目录，也不证明启用状态。产品不注册币种或选择汇率。

解析后的配置随准确批准版本保存，现有Host检查在发送前重新比较。公开列表传入所选编码及 `checked=true`，subjectAuxiliary取决于明确的类别选择。独立回查比较类别身份／编码／名称及币种编码／名称，并比较数量；配置缺失、重复或变化不能匹配。不隐式加入本位币。继续拒绝已有末级升父级及改变父级核算。

## 考虑过的替代方案

**要求新增币种目录接口。** 此有界能力不采用：已有科目可为已使用的编码和名称提供正向证据，创建接口还会校验请求。未观察到的编码保持不可用，不猜测。

**隐式复用或复制父级设置。** 不采用，因为新增科目要求的核算和现有父级影响需要分别检查。新子科目不能修改既有核算或迁移历史余额。

## 影响

普通已保存方案仍可读取，请求参数不变。新方案保留解析后的名称和身份，用于确认及恢复。35616的公开接口实验分别验证客户类别和USD配置，保留原有科目及41张凭证。产品测试覆盖发送前选择变化、重复或缺失值、配置持久化、准确版本确认和独立回查。辅助项目启停状态缺失仍是独立的接口限制，不表示所选类别没有关联成功。
