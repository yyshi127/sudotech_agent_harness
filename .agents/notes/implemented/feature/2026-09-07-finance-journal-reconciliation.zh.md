# Agent Note: 单账户日记账收支核对

Status: implemented

[English](2026-09-07-finance-journal-reconciliation.md) | 中文

## 问题

日记账数组没有明确文档说明的总数或末页标记。无日期的汇总行缺少币种，而有日期的业务行可能提供币种。把汇总行缺失视为业务币种缺失，会阻断可用的账户范围分析；把任意短页当完整账套，则会产生缺乏依据的合计。

## 决策

缺失值计数明确指向金额单元格（`incomeMissingValueCount` 和 `expenseMissingValueCount`），工作簿使用相同含义。称为缺失行容易让模型在业务行全部保留时误报丢失交易；这些计数不能证明丢失记录，也不能证明空值为零。

自然语言比较和合计请求即使与其他财务查询混合，也使用分析调用。工具首先说明这条选择规则，原始页结果再次提供所需账户查询和分析参数。否则模型可能绕过已有取数核对，直接相减两个第一页的汇总。该指引保留原始页查询，不声称能确定性控制最终文字。

明确的 `verificationOwner: xiaojing` 字段标识本地核验，不表示供应商声明。工具结果和工作簿均保留这一归属，避免生成文字把核验范围标签误认为供应商保证。

[日记账分析](../../../../packages/xiaojing/xiaojing-finance-domain/src/journal-analysis.ts)接受一个已核验的出纳账户 ID，以及一段或两段月份内日期范围。读取到带有明确收支合计的空业务页，拒绝重复 ID 和不一致合计，再将合计与已提供业务金额的精确和进行核对。每条业务行须提供相同原币。两个非空期间币种不同时不能比较。不向来源行补写币种名称或零金额。

结果使用 `empty-page-and-totals-reconciled` 标识其证据，保留来源 ID 和缺失金额计数，不给出历史余额或跨来源会计结论。金额和相符不证明每个缺失的另一方金额均为零。空期间缺少合计字段时失败；明确返回的零合计可以与空返回集合核对。分页及金额一致不等于接口总数保证或原子快照。

现有日记账工具提供分析和可选 Excel 发布。Host 生命周期检查拒绝绑定客户或凭据变更。一个总时限及部署行数/字节上限约束取数；每页复用已鉴权、已验证账户的查询。工作簿以文本单元格保留精确报告、来源空值和比较方向，打开时直接显示核对数据，将普通导出说明放在最后，不暴露接口名或技术摘要。核对失败不发布文件。

## 考虑的替代方案

**汇总币种未提供时禁止全部日记账分析。** 业务行已提供所需币种标识。汇总行缺失不足以阻断范围明确的单账户核对。

**只加第一页，或仅信任空末页。** 两者都未将可能缺失的交易与接口金额核对。限定账户、排重及明确合计一致提供附加核验，但不声称更强的供应商保证。

**将缺失金额转成零。** 接口省略未使用方向的金额，但空值仍保留；已提供值之和必须匹配明确返回的合计。缺失的合计字段不以猜测零值替代。

## 影响

聚焦测试覆盖分页、十进制计算、空值保留、币种不符、合计变化、身份、限制、取消及精确工作簿单元格。共享 Host 测试验证工作区和凭据保护。组装 Web 场景通过发布的 Finance 预设和持久记录，验证成功发布与核对失败。账套 35601 的只读核验复现九月收入 120、支出 20；独立授权的八月模拟记录 253187/253189 提供收入 60、支出 10，差额分别为 60 和 10。测试造数仍在产品外完成。

本操作不提供全账套汇总、任意跨月区间、供应商记录数保证、供应商并发修改检测或总账余额比较，也不代表 F1 总体验收完成。
