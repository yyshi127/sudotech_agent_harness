# Agent Note: 小兢 Finance 官方来源依据服务

Status: implemented

[English](2026-08-28-xiaojing-finance-official-evidence.md) | 中文

## 问题

Finance 模式需要现行且可归属的中国财税规则，但产品没有获得授权的本地法规语料库。若让模型依赖记忆或搜索摘要，会把来源发现误当成法律依据，隐藏规则日期和法律效力，也无法从会话中重建确定性结论。直接打包公开网页还会错误假设语料完整，并默认已经取得尚未确认的再分发权利。

该能力必须可以独立移除，复用 Harness 服务而不是修改 Agent Loop，同时服务通用和客户 Finance 会话；失败时不能编造引用，也不能泄露凭据、客户档案或底层网络诊断。

## 决策

`@deepseek-ai/dsh-xiaojing-finance-evidence` 是小兢产品专属 Host 能力。它通过现有 `ctx.web.search` 服务发现候选来源，再由私有受限 HTTP 抓取器访问固定官方来源清单准入的 HTTPS URL。清单覆盖国家立法、国务院、税务机关、财政部和省级税务机关来源。搜索标题和摘要始终只是发现线索；只有取得官方正文后才能生成依据摘录。

引擎分别判断每份官方正文的权威层级、法律效力、相对于北京时间指定日期的状态及条件适用性。当前官方清单覆盖 L0 到 L3 材料；L4 专业组织或国际材料不在本次“仅官方来源”范围内。权威层级不能代替法律效力、现行状态或客户事实匹配。客户会话可以从不可变 `finance/client-bound` 快照取得默认地区，但结果必须把该值记录为搜索前提，不能当成适用性证明。

服务以 `verified`、`partial`、`pending` 或 `out-of-scope` 表示依据可用状态。只有已取得官方正文且同时识别出法律效力和现行状态时才能返回 `verified`；其他状态要求受影响命题保留“待核验”。香港、澳门、台湾和境外司法辖区会返回超出范围。这些状态不是法律意见，也不能证明条件性规则适用于用户事实。

只有 Finance 预设加载 `@deepseek-ai/dsh-xiaojing-finance-evidence/tool`。`finance_evidence` 的结果作为普通结构化 `tool/result` 保存，因此模型看到的链接、摘录、前提和限制都能从会话日志重建。`src/compat.ts` 是本包连接 Harness Web 发现与 Finance 客户绑定的唯一适配器。Web Host 配置行和 Finance 消费端配置行都登记在产品清单中；官方预设和 Standard 模式不会加载它们。

`$DSH_HOME/finance/evidence-cache-v1.json` 通过文件锁和原子替换保存带 schema 版本的结构化元数据、受限摘录、响应摘要值和抓取状态。它不保存搜索摘要、批量官方正文、凭据或客户档案。文件损坏会阻止初始化，并保留损坏文件。公开访问不能证明复用许可，因此每项结果都保留 `terms-review-pending`。抓取失败只生成安全的发现线索限制，不向模型暴露底层异常。

## 备选方案

- **打包本地全文财税法规库。** 拒绝，因为产品没有已经确认的完整清单、更新机制或再分发许可；陈旧的不完整语料反而会显得比实际更权威。
- **把通用 Web 搜索结果作为引用。** 拒绝，因为提供方摘要属于截断的发现数据，无法证明官方正文、状态、法律效力或完整性。
- **为 Finance Agent 开启通用 Web 抓取。** 拒绝，因为本功能需要范围严格的官方来源读取器，而不是任意浏览能力或让模型绕过清单提交 URL 的通道。
- **每次研究都强制绑定客户。** 拒绝，因为通用 Finance 咨询也需要研究国家规则；客户地区只是可选上下文，不能成为结论权威。
- **无限期缓存完整下载页面。** 拒绝，因为这会形成未经审查的语料库，扩大权利和隐私风险，并让陈旧正文超出受限抓取用途长期存在。

## 验证

解析器测试固定真实日历校验、标题和日期提取、法律效力与状态分类、受限摘录和正文摘要。来源清单测试固定 HTTPS 准入、官方 Host 优先级、中国大陆范围和地方查询规划。缓存测试固定 schema 校验、容量限制、有效期、原子写入、损坏保留及拒绝发现线索写入。引擎测试固定不采用搜索摘要、客户地区前提、超范围处理、缓存复用、安全抓取失败以及已核验与部分核验状态。工具测试固定公开 schema、可读依据报告和结构化执行结果。

随产品提供的 Web 组合测试挂载真实 Finance 预设，并证明其保留 Standard 能力，同时只增加 `finance_evidence` 和 `finance_files`。产品层检查要求仅小兢启用的一条 Host 配置行、仅 Finance 使用的一条消费端配置行、包清单登记及 `src/compat.ts`。依据缓存位于桌面用户数据约定保护的 `harness/finance` 路径下。

## 结果

Finance 可以通过可归属的官方链接和明确不确定性回答时效性规则问题，而不需要随产品提供本地法规语料库。该设计获得了严格来源准入、可从日志重建的模型依据、受限存储和独立移除能力，同时放弃离线规则研究、完整语料承诺、自动政策监测、中国大陆以外司法辖区覆盖，以及不匹配用户事实就承诺规则适用性的做法。未来扩展来源或权利范围必须通过明确的来源清单和法律审阅决策，不能静默修改爬取逻辑。
