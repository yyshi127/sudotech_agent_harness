# Agent Note: 财务日记账查询证据

Status: implemented

[English](2026-09-07-finance-journal-query.md) | 中文

## Problem

日记账接口需要账套名称、期间及起止日期，尽管文档将日期标为可选。两个日期都不传时返回业务错误 400，缺少一个时返回参数错误 201。测试账套的空结果包含初始余额和合计标记，而不是空数组。

## Decision

Finance 工具在请求前解析月初月末，复用已保存连接及共享会话生命周期校验，并在绑定账套中核验指定出纳账户 ID。投影将无 ID、无日期的余额标记与有日期的流水分开，保留金额精度、缺失值和币种区别。返回数组没有可信总数或末页标志，因此覆盖范围保持未核验。

## Alternatives considered

账套 35601 的非空探针证实，供应商忽略 `accountIdList`，但按 `subjectId` 筛选，值为出纳账户 ID 而非总账科目 ID。适配器发送该字段，并拒绝缺少所选账户身份的业务行。账户标签为空时采用返回的 `subjectName` 和 `subjectCode`。

可选导出工作簿从第一页开始读取，直到遇到首个没有业务流水的页面。它保留每个已投影流水字段，将初始/合计标记放在另一工作表。发布保留查询条件、原币/本位币和缺失金额标签。业务数据在前，普通范围说明在最后；接口名和技术摘要不作为表格内容。精确文本单元格避免公式解释和金额舍入，既有受跟踪发布操作负责文件及持久回执。由于接口没有可信总数或末页标志，读到首个空业务页不等于供应商认证的完整性，也不代表原子快照。

**将所有数组项视为交易。** 这会为空账套虚报两笔流水，并重复计算合计。

**只发送文档中的期间。** 实测缺少日期会失败。猜默认期间或将错误 400 吞成空数组会掩盖失败。

## Consequences

指定银行账户的场景通过完整组装应用验证空结果，以及供应商返回其他账户流水两种情况。账户不匹配会在持久工具结果和浏览器卡片中表现为校验失败，不暴露现金流水，也不发布文件。

聚焦测试覆盖月份日期、汇总分类、精度、限制、账户核验、错误及客户凭据变更。真实组装 Web 测试加载发布的 Finance 预设，在会话日志及浏览器卡片中验证正常、仅汇总、失败和导出结果。单独授权的外部脚本在账套 35601 创建两笔现金测试流水：收入 120、支出 20。六项只读适配器检查验证这些金额、余额 100、现金与银行筛选及页大小一的分页。这些样例不证明任意账套的完整性；产品查询本身不写入业务数据。
