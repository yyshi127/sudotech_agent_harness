# Agent Note: 小兢共享文档读取

Status: implemented

[English](2026-08-29-xiaojing-shared-document-reading.md) | 中文

## 问题

Finance 预设需要确定性本地解析已上传的业务文档，但普通小兢预设不能依赖模型临时发现 Shell 工具、Python 包、Office 自动化或转换器。只提取文字还会遗漏 PDF、DOCX、XLSX、PPTX 和 OFD 内嵌的栅格证据。数电发票还包含 XML、XBRL 和 OFD 包数据，解析时既不能把任意 XML 当作发票，也不能让内容提取造成已经验证真实性的误解。复制解析器或信任模型提供的文件系统路径会产生两套逐渐分叉的实现，并允许跨会话读取本地文件。

该扩展必须让所有非 Finance 小兢预设获得相同解析行为，保留 Finance 客户隔离，复用现有上传入口和原生视觉传输，支持独立移除，并且不修改 Agent Loop。

## 决策

`@deepseek-ai/dsh-xiaojing-finance-documents` 只维护一套解析器、标准化器、缓存和模型输出实现。通用 `DocumentSource` 抽象只接收已经完成授权的来源记录。Finance 适配器从不可变 `finance/file-imported` 和 `finance/consultation-file-imported` 事件重建这些记录；普通适配器只扫描当前会话中持久化的人类 `user/message` 事件，识别随包上传插件生成的精确上传引用行，把真实路径限制在配置的小兢上传根目录，并拒绝插件生成的文字、任意路径、目录、符号链接和其他会话。

小兢 Web 组合全局注册 `document_reader` 消费端，供 Standard、Goal、Plan 等非 Finance 预设使用。Finance 继续注册 `finance_document`，并通过作用域工具 registry 拒绝 `document_reader`，因此通用路线不能绕过客户授权。两个工具都提供 `list`、`read` 和 `visuals` 操作，且都不接受路径。官方 Harness profile 不加载任何小兢消费端。

上传钩子会根据本地会话列表识别非 Finance 会话，并在调用 Finance RPC 或上传前返回未接管；列表中未知的会话仍由 Host 权威判定。标准化器先核验授权路径和记录大小，超限来源会在哈希扫描或 Worker 接纳前被拒绝；符合大小限制的文件仍须先核验摘要才能访问缓存。默认单文档上限为 100 MiB，与随包上传管理器默认值一致，避免上传已接纳但解析器因更低默认值再次拒绝。

标准化会记录文字不足 PDF 页面的完整渲染图，以及文字充分 PDF 页面、DOCX 正文、XLSX 工作表绘图、PPTX 幻灯片和 OFD 页面引用的栅格图片。PDF 渲染使用 PDF.js 与 `@napi-rs/canvas`，受配置的宽度、像素、数量和总字节上限约束，且不调用 OCR。`visuals` 操作重新核验源文件，在隔离 Worker 中按格式自有键精确提取图片，通过规范附件存储保存每张图片，并返回带页面、段落、单元格、幻灯片或 OFD 页位置的原生图片块。只有当前实际路由模型声明支持图片输入时才允许提取。完整 Office 或 OFD 页面渲染、OCR、图表、SmartArt、矢量图、媒体、动画和嵌入对象仍作为明确限制，不会被推断成内容。

数电发票 XML 只有在可识别字段同时包含发票号码、一个交易主体和金额时才会被接受。税务交付常用字段名和财政部 XBRL 字段名会映射为稳定中文标签。OFD 解析读取有序页面文字和页面引用图片，并扫描包内 XML 或 XBRL 以提取同一套可识别发票字段。PDF 交付格式使用共享 PDF 文字与图片路线。所有已识别数电发票结果都会说明解析不验证签名、真实性、发票状态、抵扣状态或入账状态。

标准化记录保留 schema 版本 `3`，使用 normalizer 版本 `4`，保存到 `$DSH_HOME/finance/documents/v3/normalizer-v4/<作用域哈希>/`。更早的 normalizer 记录以及 schema 版本 `1`、`2` 缓存保持不变，因为它们属于可由授权来源重新生成的派生数据。Finance 客户、Finance 咨询和普通会话使用不同的哈希作用域。

## 评估过的替代方案

- **把 Finance 解析器复制到新的普通模式包。** 放弃，因为修复、格式支持、上限和安全检查会逐渐分叉。
- **把 Finance 工具全局暴露。** 放弃，因为它的授权依赖 Finance 事件和客户上下文，会错误处理普通上传。
- **接受模型传入的本地路径。** 放弃，因为会话文字不是来源授权，会造成任意或跨会话读取。
- **渲染每个 Office、PDF 和 OFD 页面。** 放弃，因为需要 Office 渲染运行时，会增加安装体积和延迟，并重复直接文字路线。采用的 PDF 路线只用本地 PDF 运行时渲染文字不足的页面，其余页面仍以直接文字为准。
- **把所有 XML 都当作发票。** 放弃，因为无关配置和导出 XML 会被错误投影为财务字段。识别必须同时具备独立的发票身份、交易主体和金额证据。
- **调用外部发票解析或查验接口。** 放弃，因为本地文档读取不应再要求一套凭据或传输业务数据。真实性与状态查验保持为明确独立能力。
- **让普通模式继续临时尝试工具。** 放弃，因为行为仍然缓慢、依赖机器环境，并与 Finance 不一致。

## 验证

解析器测试覆盖扫描页完整渲染、混合 PDF 页面选择、PDF、DOCX、XLSX、PPTX 和 OFD 的内嵌图片关系与来源位置、精确重新提取、字节上限、纯图片文档、官方风格 XBRL 字段名、OFD 内嵌 XBRL、无关 XML 拒绝以及既有文本格式。真实隔离 Worker 测试会渲染并重新提取一份最小扫描型 PDF。普通来源测试覆盖当前会话人类上传、插件生成文字、越界路径、上传根目录缺失和重复引用。Client 路由测试证明已知非 Finance 上传既不调用 Finance RPC，也不执行第二次上传。工具测试证明原生图片内容块、视觉位置和发票查验免责声明。

无 Key 组装快照分别启动小兢 Standard 和 Finance 预设。Standard 快照证明 `document_reader` 可以列出并读取持久化普通上传，同时不存在 `finance_document`；Finance 快照证明 `finance_document` 仍可读取客户和咨询导入，同时隐藏 `document_reader`。该包的 TypeScript 程序在仓库 strict 配置下编译通过。

## 结果

所有小兢预设都可以通过现有上传按钮获得可预测的本地文档读取，Finance 同时保留更严格的客户专属授权。扫描型与混合型 PDF 组合确定性文字提取和受限完整页面视觉检查；DOCX、XLSX、PPTX、OFD 和文字充分的 PDF 页面继续保留受支持的内嵌图片。可识别的数电发票 XML 与 OFD 会输出结构字段，但不会夸大为已经完成查验。OCR、完整 Office 或 OFD 页面渲染、旧版 Office 格式、图表、SmartArt、签名验证、官方发票查询和财务语义解释仍属于独立能力。
