# Agent Note：小兢会计 Finance 客户域与不可变会话上下文

状态：已实现

[English](2026-08-27-xiaojing-finance-client-domain.md) | 中文

## 问题

Finance 模式已经可以研究官方财税来源，但没有持久化机制区分通用咨询与某一个纳税主体的具体工作。若把可变客户字段直接保存在浏览器状态中，或者每次都读取客户档案的最新值，两个会话可能混用不同主体，旧会话看到的事实也会在档案修改后发生变化。建设 CRM 会引入联系人、销售、合同和收费等无关范围，却不能解决模型上下文完整性问题。

实现还必须遵守“模型可见内容必须能从会话日志重建”的仓库规则，把产品行为留在官方 Harness UI owner 之外，并为未来有成和 SDOO 服务提供一个统一的未绑定拒绝入口。

## 决策

`@deepseek-ai/dsh-xiaojing-finance-domain` 是小兢产品专属 Host 能力。它在 `$DSH_HOME/finance/clients-v1.json` 中为每个纳税主体保存一条记录。文档使用 schema 版本 `1`、文件级 revision 和档案自身版本。修改通过 compare-and-swap revision、进程安全文件锁和原子替换完成。数据损坏时插件初始化失败，并保留原文件不变。档案只能归档，不能删除，因此历史会话引用保持有效。新增和更新必须提供显示简称；缺少简称的历史记录可继续读取，直到下次编辑。每条档案可以选择一个财务系统：有成把环境、AppKey、账套编码和所选账套名称作为非秘密客户数据保存，SDOO、用友和金蝶保留明确占位。有成 AppSecret 按客户保存为 `ctx.credentials` 记录；读取只返回已配置和可写状态。凭据准备在客户档案文件锁内执行，若档案文件替换失败则回滚。

空白 Finance 会话从通用咨询状态开始。客户只在第一轮之前暂存于 Host 内存。第一次模型请求会解析暂存档案，追加并落盘一条 `finance/client-bound` 事件，然后再向请求贡献上下文。事件只包含不可变业务快照和档案版本；财务系统连接配置与凭据不会进入事件或模型提示词。会计年月、季度或年度属于具体任务，由对应财务 Skill 从用户指令读取或在缺失时询问，不能固定在客户或会话上。通用请求不记录绑定事件，并获得禁止推测客户事实的明确无客户上下文。`requireBoundClient()` 是未来所有客户专属财务服务的统一前置条件。

请求准备可能在 `turn/start` 之前落盘绑定；如果任务在这个间隔中中断，会话会同时保持空白和持久绑定状态。重新进入同一客户 Workspace 是幂等操作：Host 会校验客户和 `cwd` 均未改变，返回锁定的脱敏状态，并继续拒绝通用模式或其他客户。Client 直接使用该脱敏状态显示客户名称，锁定两个选择器，同时保持输入区可用。

`financeClient` 会话投影折叠持久化事件，但只向浏览器公开客户显示名称和状态。完整税号、政策备注、映射、外部系统标识和财务系统连接配置仍保留在 Host。生成的 `financeClients` Remote 普通返回只包含摘要和安全会话状态；完整读取、修改和暂存仅允许 loopback。完整客户读取包含凭据状态，但绝不包含 AppSecret；修改请求可以携带只写替换值。

`@deepseek-ai/dsh-client-ui-xiaojing-finance-clients` 从每个客户 Workspace 的操作菜单提供“帐套信息”，设置页不提供客户管理；独立的[附件与报销配置](2026-09-04-reimbursement-draft-attachments.zh.md) 保留这一档案与会话设计。“账套”是展示文案；客户记录、Remote 标识和 Workspace 路径保持原有含义。浮层把客户基本资料与财务系统配置分开，要求填写简称并说明其紧凑展示用途，按选择显示有成字段，把尚未支持的系统保留为具名选项，并移除手工科目映射。它只为 Finance 空白会话填充产品中立 `conversation.hero.context` slot，并在活动会话标题区注册只读上下文标签。“咨询／账套”选择器按“客户简称-账套名称-ID 值”列出选项，历史记录缺少简称时回退主体全称，只在账套模式尚未选择账套时增加带 owner 的输入阻塞。`ComposerBlockRegistry.setOwned()` 让 Finance 只移除自己的阻塞，不会清除模型、上传、Goal 或 Plan 的独立限制。

Finance 还拥有独立于普通用户工作区的文件与会话类别。产品配置把根目录固定在“小兢会计工作区/Finance工作区”，其中一个固定显示为“咨询”的 Workspace 服务无客户会话，`clients/<稳定客户 ID>` 为每个纳税主体提供一个 Workspace。客户根目录是该客户所有会话的不可变 `cwd`，包含客户档案、政策、原始资料、按会话隔离的作业、成果和归档；期间子目录由具体 Skill 按任务创建。Host 在暂存和模型请求前校验实际 `cwd`，从结构上拒绝跨客户绑定。客户创建先配置目录并注册 Workspace，再提交客户目录；失败时回滚新资源。启动恢复会移除未完成创建留下的 Workspace 注册，但保留其文件供恢复。

同一个 Host 能力为这些目录提供受控且只复制的文件生命周期。Client 扩展事件让现有上传按钮仅在会话已绑定客户时把完成的本地上传交给 Finance；Host 将其复制到 `02-原始资料`，咨询和其他预设继续使用普通上传路线。每个会话拥有一个独立的 `03-会话作业/<session-id>` 目录，并原子写入 `会话信息.json` 身份清单；完整聊天记录仍由 Harness 会话存储保存，客户目录只保留作业文件和该清单。Finance 专属 `finance_files` 工具在用户以自然语言要求最终版、导出、交付或正式保存时，把会话作业文件复制到 `04-成果输出`；用户明确要求归档时，把受管文件复制到 `05-归档` 的日期子目录。草稿或意图不明确的内容留在 `03`，两个操作都不会删除源文件。

每个客户根目录下的 `.xiaojing-finance-files-v1.json` 是只追加且带 revision 的索引，记录所属客户和会话、操作、绝对提交路径、文件大小、SHA-256 摘要及源记录关系。成功复制后会追加并落盘对应的 `finance/file-imported`、`finance/file-published` 或 `finance/file-archived` 会话事件，使所有模型可见受管路径都能从日志重建。路径校验会把普通非符号链接文件解析到上传根目录、当前会话作业目录或所选客户目录。目标原子创建与索引原子替换可防止覆盖和半写元数据；索引损坏时操作停止且不替换损坏文件。这些控制约束统一上传和 Finance 工具路径，不约束 Full Access 下任意 shell 写入。

`$DSH_HOME/finance/workspace-presentation-v1.json` 独立于客户档案和 Workspace 注册，保存可编辑的 Workspace 标题与财务列表成员关系。该文件使用 schema 版本 `1`、revision、进程安全文件锁和原子替换。移除 Workspace 是非破坏性的列表操作：注册、目录、客户档案和会话保持不变，隐藏的 Finance 注册继续从普通工作区保留，再次选择同一目录即可恢复。领域服务拒绝移除最后一个仍在列表中的咨询 Workspace。

通用 `ui-workspace` 只增加 `WorkspaceCategoryRegistry` 扩展点，不包含 Finance 文案或识别规则。该扩展点支持产品类别、嵌套节点、产品中立的分类语义图标、保留与可见成员、一个由提供方持有的非破坏性详情操作、重命名和移除操作，以及当前预设的 Workspace 选择范围。即使全局 Workspace registry 把不同分类的成员交错排列，嵌套分类仍按照提供方声明顺序连续成组渲染，并保留各分类内部的 registry 顺序。Finance Client 插件注册“办公搭子／财务助手”文案与类别成员：“账套”使用账套图标并排在“咨询”之前，“咨询”使用讨论图标；两个图标无论是否处于当前分类都保留业务强调色。客户行菜单依次显示“帐套信息”“重命名”“移除工作区”，咨询行不显示产品详情操作。空白普通会话切换到 Finance 预设时自动进入仍在列表中的咨询 Workspace；空白 Finance 会话切换到其他预设时返回先前的普通工作区。选择客户会先进入其 Workspace，再在新会话中暂存客户。归档当前 Finance Session 时会保留财务类别，并重新激活该 Session 所在且仍可新建会话的 Workspace，避免空选择回退到普通工作区。移除 Finance 产品插件后，通用工作区浏览器不保留 Finance 条件。Windows 原生目录选择器把当前前台窗口绑定为模态 owner，因此点击任一分类的添加按钮后，目录选择框会立即显示在应用前面，不再隐藏到任务栏或窗口后方。

Finance 预设增加一个 `finance-client-context` 配置行，加载 Host 包独立导出的上下文入口。监听器先读取实时组合预设，并为恢复会话回退到持久化预设，从而支持会话 header 尚未记录预设的空白 live agent，同时保持 Standard 等其他预设不受影响。两个新包和配置行都登记在 `product.json.financeExtension` 中；删除这些行即可移除能力，不需要修改 Agent Loop 或官方产品行为。

已保存的有成配置绑定一个明确的账套 ID。连接核验在保存后执行，并与客户目录提交分离，因此供应商不可用不会把已经完成的保存变成含糊的失败。Host 校验凭据和精确账套成员关系，产品 Client 通过通用 Workspace 类别提供账套名及语义状态标记。仅鉴权成功不足以确认绑定，因为一组 key 可能开放多个账套。环境标记通过部署管理的源地址解析，也可以共用同一地址；API 访问取决于凭据和已核验的账套选择，而不是标记。核验状态只驻留内存并绑定档案版本，防止客户修改或 Host 重启后展示陈旧的异步成功。本次不引入账务写入或多账套选择。

资料编辑器拥有高度受限的弹窗，字段区域独立滚动，标题和底部操作区不随之滚动。这使“保存”和“取消”在较矮的视口中仍可访问，不必修改共享 Modal 及其其他消费者。财务政策备注作为默认收起的可选上下文保留，避免长期占据大文本框，也不删除已有客户数据。浏览器验证覆盖桌面、矮窗口、窄屏和横屏下的控件可见性及字段溢出。

账套发现与绑定核验相互独立：仅限 loopback 的 Remote 接收未保存的应用凭据，不带账套过滤条件完成鉴权和查询，并返回名称和 ID 供用户明确选择。它不保存凭据，也不改变已保存连接的状态点或 token 缓存。Client 从账套选择项取得绑定 ID，不提供独立 ID 输入框；鉴权字段变化时使候选列表失效，并忽略已被取代的查询响应。返回账套表示应用有权访问该候选项，不证明它属于当前客户。适配器、Host、Client 和真实 Web 组合测试覆盖凭据隔离、取消、revision 冲突、空列表／失败、按名称选择及保存时重新核验。

已配置有成的活跃账套行还通过 `WorkspaceCategoryRegistry.activateWorkspaceBadge` 提供仅限 loopback 的行内链接操作。该操作在 Host 重启后复用已保存配置的核验，无需重新打开或保存编辑器，不改变行的展开状态，也不暂存会话选择。Client 抑制并发重复请求，并在重叠的客户目录刷新期间保留同一档案版本的核验进度和结果；档案版本变更或 Host 连接重置会使该次核验失效。失败后仍可重试；只有核验成功才恢复账套名和绿点。不启用启动时自动核验。

连接失败分类区分期限超时（含正文读取）和网络故障。HTTP 403 只证明访问被拒绝，不能证明具体策略原因；供应商明确返回 IP 拒绝时保留白名单分类。不回显供应商错误原文。聚焦测试验证这些区别；重启后的 Web 场景还验证拒绝访问时取消绿灯，以及不改动客户目录的恢复重试。

同一会话绑定的 Finance 服务拥有只读基础资料查询。一个小型预设工具覆盖五类已文档化资料，不新增工作流引擎。Host 校验当前身份与凭据，保留层级和各接口的状态，仅投影允许字段。接口没有文档化游标或总数，因此有界结果明确保留完整性未验证，精确筛选不宣称全库不存在或唯一。不能凭连接绿灯跳过查询时校验。基础资料通过既有工具结果事件记录，不新增持久化格式。

## 备选方案

- **建设 CRM。** 拒绝，因为联系人、合同、销售、收费和客户关系流程不属于本阶段的 Finance 上下文需求。
- **每次模型请求读取客户档案最新值。** 拒绝，因为档案修改会改写历史会话的实际事实。
- **把每一次选择器变化都写入会话日志。** 拒绝，因为首轮前反复选择并未进入模型；只有第一次请求实际使用的选择属于持久化历史。
- **允许通用会话中途绑定。** 拒绝，因为早期回答没有使用该主体，中途切换会产生含混的会计上下文。
- **通过普通会话投影发送完整客户档案。** 拒绝，因为会话标题不需要税号、映射、政策备注和外部系统引用。
- **把有成 AppSecret 保存在客户目录中。** 拒绝，因为完整客户读取、Workspace 档案文件和不可变会话快照都不能携带外部系统秘密。
- **在客户资料表单中维护科目映射。** 拒绝，因为有成科目是权威 API 数据；未来如有跨系统映射，应由实际需要它的操作持有，而不是连接档案。
- **把选择器直接写进 `ui-conversation`。** 拒绝，因为官方 UI 只应拥有通用 slot 和 fallback，Finance 文案、状态和行为必须留在可移除产品插件中。
- **把客户目录混在普通工作区。** 拒绝，因为普通搜索、会话新建和目录管理会暴露客户目录，并允许用户在错误 Workspace 中建立 Finance 会话。
- **把一次会话作业目录当作客户档案目录。** 拒绝，因为客户档案和政策应跨会话共享，而草稿与临时文件必须按会话隔离。
- **在各阶段之间移动上传或作业文件。** 拒绝，因为取消、重试、审计和人工恢复都要求导入、发布或归档后仍保留源文件。
- **要求用户使用固定“发布成果”口令。** 拒绝，因为 Agent 可以把普通的最终版、导出、交付和正式保存意图映射到一个严格校验的工具；意图不清晰时仍保留草稿。

## 验证

连接测试覆盖精确账套匹配、安全错误、token 复用、超时、取消和并发编辑时的结果失效。真实 Web 组合只替换供应商网络，验证保存、绿点／红点、密钥保留及编辑器快照。loopback 限制在共享通道拦截前对生成的斜线端点执行并接受测试，防止受信任远程主机通过不同端点拼写调用已保存凭据。

存储测试覆盖客户与 Workspace 展示持久化、创建、修改、归档、重复信用代码、过期 revision、原子写入和损坏文件保留。域测试还覆盖有成配置校验、凭据分离与保留、过期 revision 在凭据修改前被拒绝，以及连接配置不进入模型提示词。Client 测试覆盖表单的两个分区、有成字段条件显示、未支持系统占位、科目映射缺席、仅客户可见的资料操作及菜单顺序、创建／编辑／归档流程、咨询／客户选择、预设路由、带 owner 的输入阻塞、统一上传接管、普通会话回退和图片撤回。

随产品提供的 Web 组合会通过真实预设挂载，无 Key 组装通用 Finance 提示词和客户 Finance 提示词。快照证明 Standard 没有 Finance 客户上下文，通用 Finance 明确没有客户，客户请求只获得日志中的不可变快照并按当前任务确定期间，而且只有 Finance 获得受控文件工具与生命周期指令。产品层、用户数据、持久化目录和 Cordis 配置门禁要求包清单、预设配置行、私有 Remote 方法、已知文件事件、受保护 `harness/finance` fixture 和可移除组合全部存在。

重启 Host 的浏览器场景复用已保存凭据，记录行内操作的未核验、核验中、失败和已连接状态。该场景验证键盘重试，并断言客户目录字节及行展开状态不变。

## 结果

Finance 是一个完整、可移除的业务模块：客户档案保存业务事实与非秘密连接配置，凭据提供方持有 AppSecret，Finance 专属 Workspace 隔离文件与会话，受控文件生命周期记录导入和提交副本，产品 Client 插件负责选择、路由、配置和上传交接。客户档案修改只服务未来工作，不能改变历史模型上下文。未来确定性计算器、有成工作流、SDOO 连接器和合规服务可以接收 Agent 并调用 `requireBoundClient()`，无需重复实现客户选择或目录边界。这种拆分避免自然语言工具和模型提示词收到凭据，代价是客户档案提交与凭据提交必须在同一个档案文件锁下协调。未来 Harness 升级若改变相关 API，应优先只调整 `src/compat.ts`、通用 slot owner、Workspace 类别适配、上传事件集成或生成的 Remote 集成；存储、凭据、文件生命周期、工作区、不可变绑定和产品 UI 继续彼此隔离。
