# Agent Note: Finance 权威能力清单

Status: implemented

[English](2026-09-15-finance-capability-inventory.md) | 中文

## 问题

Finance 的能力回答既需要产品层面的介绍，也需要精确的执行边界。如果一般的“你能做什么”直接使用详细支持清单，产品定位就会被实现状态和未支持示例淹没。通用 persona、已注册工具名、已加载 skill 和对话历史也不能安全替代详细清单，因为它们可能遗漏已实现操作、暴露内部保留后端，或把客户绑定误报为有成可以连接。

产品还保留历史报销配置、回执和 Host 服务，但当前开发范围排除报销。删除这些记录会破坏数据；继续暴露旧提示词、工具和 skill 又会与当前 Finance 范围冲突。

## 决策

能力模块维护两个相互配合的真源。`FINANCE_POSITIONING` 通过财务资料处理、日常账务协助、财务分析与成果输出、财税支持和综合任务执行五个大类，把小兢会计定位为 AI 财务助手，并负责一般能力介绍。`FINANCE_CAPABILITIES` 负责精确的支持判断；每个详细条目包含业务名称、已支持／有限支持／暂不支持状态、明确的适用范围（小兢会计通用能力、当前财务工作区或当前有成财务接入）、面向用户的说明、重要限制、是否要求绑定客户，以及证明该条目的内部工具。

每次 Finance 提示词组装都把定位概述和详细清单共同渲染为 `xiaojing:finance-capabilities`。提示要求一般的“你能做什么”只停留在定位层，不主动给出支持状态、接口限制、内部工具或未支持的原生报表。具体能力问题或明确的完整清单请求可以使用相关详细条目，并且必须说明适用范围。当前有成财务接入的限制不能泛化为小兢会计不能提供咨询、处理用户材料、基于可靠数据分析或通过未来其他接入完成。用户要求实际执行时，再使用对应工具完成正常的前置核验。渲染内容还会标明当前是咨询还是客户绑定状态，并说明绑定只证明客户身份，不证明连接、权限、会计期间或数据覆盖。

清单把六类原生账簿／报表、会计控制和报销标为暂不支持，并禁止把浏览器、shell 或本地近似结果说成这些原生能力。Finance 预设不再注册报销提示词、`finance_reimbursement`、独立附件上传工具或报销 skill。既有报销配置、回执、历史事件和 Host 操作继续保留，保证数据连续性。

产品界面根据所选会话预设显示身份文案：普通会话显示 `小兢会计，您的AI办公搭子`，Finance 会话显示 `小兢会计，您的AI财务助手`。`0.2.4` 版本包含这项区分和“关于小兢”中的当前 Finance 能力摘要。

## 考虑过的替代方案

**把能力文案继续写在 persona 中。** 否决，因为 persona 负责身份和语气，不能精确维护支持状态、限制和运行前提。

**根据已注册工具或 skill 推导能力。** 否决，因为一项业务能力可能依赖多个内部工具，一个已注册工具可能只覆盖有限操作，保留后端也不一定属于当前产品能力。

**只向模型提供宽泛定位。** 否决，因为具体问题和执行请求仍需要准确的支持边界。把两层信息保留在同一提示词中，模型可以按用户要求的层级回答，同时不虚构能力。

**每次介绍能力都实时检查有成。** 否决，因为一般产品问题不需要产生网络请求。只有用户询问当前能否执行或要求实际操作时，才检查实时状态。

**删除报销服务和存量数据。** 否决，因为当前范围隔离不授权破坏性迁移历史记录。移除模型暴露已经能够形成所需边界，无需删除数据。

## 后果

一般能力回答会体现小兢会计的产品价值，而不是读起来像接口检查表；具体回答会区分产品支持范围、接入范围和当前运行可用性。改变 Finance 定位或支持范围时，必须更新对应的定位常量或详细清单及组装应用快照。每次 Finance 请求会增加两层固定提示词成本，客户字段仍只进入绑定会话。

历史报销数据仍可读取，但当前 Finance 对话无法从提示词、工具或 skill 中发现和调用报销。未支持的原生报表会明确作为限制，不会输出近似结果冒充。

## 验证

聚焦的定位、清单和 Finance 上下文测试覆盖宽泛介绍、禁止主动披露详细限制、按接入范围表述暂不支持、条目唯一性、暂不支持条目不得登记工具、绑定与未绑定文案、插件释放以及 Standard 模式排除。无 Key 的 Finance 组装快照固定两层提示词，验证两个隔离客户获得相同指引，并证明报销工具和 skill 不存在。产品 Client 测试覆盖两种工作区欢迎语和 `0.2.4` 角标；设置快照覆盖版本历史。
