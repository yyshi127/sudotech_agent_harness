# Agent Note: 私有附件与经确认的报销草稿

Status: implemented

[English](2026-09-04-reimbursement-draft-attachments.md) | 中文

## Problem

财务账套连接不能授权独立的报销服务。聊天还需要供应商可访问的附件，同时不暴露本地文件、应用秘密或无限制云存储。写请求网络结果不明时不能产生重复单据。

## Decision

[Finance Host](../../../../packages/xiaojing/xiaojing-finance-domain/README.zh.md#private-attachments-and-reimbursement-drafts) 管理本机全局的私有 OSS 设置，以及每个客户记录独立的报销凭据。产品界面提供只写秘密配置，安装包不内置共享密钥。[不可变会话绑定](2026-08-27-xiaojing-finance-client-domain.zh.md) 和[凭证只读隔离](2026-09-04-temporary-youcheng-voucher-query.zh.md) 的决策仍然有效，各自保留独立价值。

临时工具通过有界查询解析当前模板与身份，校验必填项，并在云端写入前要求用户单次确认。导入原件按当前会话日志核验后由 Host 上传。供应商支持已确认 `orderComponentList` 中的 `attachment.bindingVal` 接收 JSON 编码的 URL 数组；此固定字段不依赖模板元数据是否返回它，普通附件也不需要先写发票台账。独立员工字段要求明确选择，不能默认为申请人。创建请求固定草稿状态，只有回查状态后才确定成功。

问题取消／失败、单据确认被拒绝后，必须收到新的用户文字消息才能恢复写入；待处理决定也会阻止写入。此状态从持久日志重建，不从模型叙述推测。恢复后仍须强制确认具体单据。模型指令另行禁止编造答案、擅自合并发票或切换模板。

私有原子回执按客户、会话和草稿参数标识请求。每个所属会话使用独立锁串行处理；一旦创建可能已经发生，即使本会话修改参数也会被阻止，必须先核对结果。回执排除签名链接与凭据；凭据 revision 变化后要求人工核对，不能转而读取其他组织的结果。

客户绑定会话的提示词组装通过具名运行时上下文快照提供当前附件规则。这会纠正恢复会话保留的过期“不能带附件”结论，而不改写历史工具结果。快照说明单据／费用明细附件传输、发票台账限制和后台专用链接；它不授权业务写入，也不放宽必填项。

声明 `attachment` 的费用模板通过 `feeComponentList` 接收逐行链接。Host 按输入路径映射已经上传的原件，因此每行只接收该行所选文件，不重复上传，也不把整单文件复制到每一行。必填普通附件组件在校验前生成，在确认上传后填充。已完成回执仍只供回读，不隐式修改已有单据。

## Alternatives considered

**安装包内置 OSS 密钥。** 每台安装设备都能提取共享云凭据；本地授权配置允许当前无登录产品使用云存储，同时不分发该凭据。

**公开附件或临时 shell 上传。** 这会暴露财务文档，或允许模型选择凭据与任意本地源文件，而不是执行日志中的导入归属限制。

**每个附件都先创建发票台账。** 普通附件组件不要求这项额外业务写入，它也不能证明发票关联正确。

**所有超时都重试创建。** 原始写入可能已经成功；持久任务编号允许回查，避免盲目重复创建。

**只修改 Skill 或清空旧历史。** 恢复会话不一定会在操作前重新加载 Skill，而删除历史会丢失先前确认和未知写入证据。记录在日志中的当前规则快照同时保留纠正说明与历史记录。

**只在单据级传附件。** 实时元数据显示所选费用模板包含附件组件，即使单据模板未列出它。只填单据级字段会让这个已声明的费用附件组件保持为空。

## Consequences

能力仅保存已支持、经明确确认的草稿，不支持任意报销表单。必填但不支持的组件、强制发票台账关联会在写入前失败。报销凭据独立于财务账套选择组织，确认摘要列明组织与申请人；不实现审批、支付、定时执行或跨会话发票去重。

签名链接会过期，有成是否转存原始字节尚未核验。已核实草稿不证明附件能长期访问。真实云端验收仍需获授权的 OSS 密钥、用户提供的发票及生成附件的实际检查，才能宣称完整业务流程通过。

## Verification

聚焦测试覆盖凭据分离、revision 冲突、元数据脱敏、取消确认、必填员工选择、缺失附件元数据、附件编码、固定草稿状态及修改参数后的未知写入重试。组装 Web 场景取消真实浏览器问题，验证后续模型写入被拦截，再通过真实 Finance 预设、导入日志、强制确认、工具与浏览器结果确认 PDF 和 PNG 原件，仅替换网络／模型响应。源文件归属与 loopback 检查仍由 Host 负责；真实供应商附件保留行为是明确的验证缺口。

Web 场景恢复含有过期附件错误的持久会话，固定新的模型可见规则及其持久快照，并验证不换模板、PDF 和 PNG 原件分别位于两条费用明细的一次草稿创建。缺少逐行映射时，可选和必填费用附件的单元回归均失败；场景还检查 Standard 模式不包含该上下文。这项确定性回归验证上下文供给与执行器行为，不保证真实模型始终遵循指令或供应商展示全部传入附件。
