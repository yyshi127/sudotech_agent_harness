# Agent Note: 小兢 Finance 确定性文档标准化

Status: implemented

[English](2026-08-28-xiaojing-finance-document-normalization.md) | 中文

## 问题

Finance 用户通过现有同一个上传入口导入 PDF、Word、Excel、PowerPoint、CSV 和文本文件。DeepSeek 原生视觉可以处理图片，但非图片文档此前会让 Agent 临时发现并反复尝试 Shell 工具、Python 包、Office 自动化或转换器。这种行为速度慢、依赖每台电脑环境、难以复现，也无法稳定保证客户数据隔离。扫描型 PDF 和纯图片演示文稿还可能被当成空文本文件，除非 Agent 偶然识别到它缺少文本层。

解决方案必须可独立移除，不修改 Agent Loop，保留现有上传与客户文件生命周期，不依赖外部服务或额外 API Key，不捆绑 OCR 或 Python 运行时，并保证所有进入模型的结果都能从会话日志重建。

## 决策

`@deepseek-ai/dsh-xiaojing-finance-documents` 是小兢专属 Host 能力，只接受当前会话中的不可变授权事件。客户绑定会话把上传文件复制到 `02-原始资料` 并记录 `finance/file-imported`；通用咨询会话把上传文件保留在受保护的本地上传根目录，并记录 `finance/consultation-file-imported`。解析或返回缓存前，服务会取得真实路径，要求来源是事件授权目录内的普通非符号链接文件，并再次核验记录中的大小与 SHA-256。

Host 支持 PDF、DOCX、XLSX、PPTX、数电发票 XML、OFD、CSV 和 TXT，并输出受限的页、段落、工作表行、幻灯片、字段、CSV 行或行号范围单元，同时记录带来源位置的受支持栅格视觉内容。对于 PDF，系统先提取文字层，只渲染缺少文字或文字数量低于配置阈值的页面。每个选中页面通过 PDF.js 和 `@napi-rs/canvas` 转成受限 PNG，再由现有 `visuals` 操作交给当前支持图片输入的模型。文字充分的 PDF 页面仍使用直接文字和可解码 XObject 图片，因此混合型 PDF 不会让每一页都产生视觉成本。不支持、加密、损坏、超过上限或超时的文件返回明确安全状态，不进入转换器兜底。

解析在一个串行 Worker 中执行，并设置运行时限和 V8 内存上限。Worker 使用受限环境，再次核验来源元数据，只返回经过 schema 校验的终态消息。文件、PDF 页数、演示文稿幻灯片数、文本、结构单元、工作表、行、列、单元格、超时、内存和模型单次读取上限均由部署配置负责。公式执行、OCR、演示文稿视觉重建、发票语义提取、会计分类和税务审阅不属于本确定性阶段。

标准化记录保留持久 schema 版本 `3`，使用 normalizer 版本 `4`，保存到 `$DSH_HOME/finance/documents/v3/normalizer-v4/<作用域哈希>/<内容哈希>.<格式>.n4.json`。normalizer 专属目录会让更早的派生记录保持不变，并防止渲染能力上线前的缓存命中压制扫描页视觉结果。客户会话使用客户标识作为作用域，通用咨询使用会话标识作为作用域；作用域值进入路径前先做哈希。文件锁和原子替换保护写入，损坏记录会阻止初始化且不覆盖原文件，缓存命中仍要求当前来源文件有效。作用域哈希可以阻止一个客户或咨询会话复用其他作用域的缓存记录。

只有 Finance 预设加载 `@deepseek-ai/dsh-xiaojing-finance-documents/tool`。`finance_document` 先列出当前会话导入文件，再按不透明文档标识和游标读取受限结构单元。结果保存为普通结构化 `tool/result`；标准化正文不注入常驻提示词，也不需要重复会话事件，因为导入事件已经可以重建来源授权。随产品提供的 Finance Skill 要求支持格式统一使用该工具，并禁止 Shell、Python、Office 和临时转换器尝试。

`src/compat.ts` 是当前 Harness Finance 绑定与导入事件的唯一适配文件。Host 配置行、预设消费端、Skill、包清单和解析依赖都属于小兢产品层。删除这些入口后，上传、客户原文件、官方依据、Standard 模式和官方 Harness profile 保持不变。

## 评估过的替代方案

- **继续让 Agent 临时发现本地工具。** 放弃，因为行为依赖每台电脑环境，反复消耗模型轮次，也无法保证客户隔离和稳定来源位置。
- **把所有文档或每个 PDF 页面都转为图片。** 放弃，因为长文档会更慢、更贵，而且对可搜索文本和表格值不够精确。只渲染文字不足的 PDF 页面，可以保留确定性文字并覆盖扫描型与混合型 PDF。
- **捆绑 OCR、ONNX 或 Python。** 本阶段放弃，因为会显著增加安装体积与维护成本，而带文本层文档已经可以用确定性本地解析器处理。
- **使用 Microsoft Office 自动化。** 放弃，因为无法保证每台电脑安装 Office，桌面自动化依赖前台状态，宏或提示框还会引入不安全副作用。
- **把标准化文件写入客户工作区。** 放弃，因为解析缓存是产品实现数据，不是用户原始资料或正式成果。原始资料仍留在客户工作区，缓存应属于受保护的 Harness 数据。
- **把会话文字中出现的本地路径视为上传授权。** 放弃，因为提示词文字不能证明当前会话上传过该文件，会造成跨会话或任意本地文件读取。只有上传桥和持久会话事件可以授权解析。
- **把完整标准化正文注入每次提示词。** 放弃，因为会浪费 token、破坏固定提示词前缀，并把文档暴露给无关轮次。模型只读取任务需要的结构单元。

## 验证

解析器测试使用真实最小 PDF、DOCX、XLSX 和 PPTX 容器，以及 CSV 与 TXT 输入，固定 PDF 页面渲染、混合文字与图片选择、视觉内容精确重提取、页、段落、幻灯片顺序、演讲者备注、XML 实体解码、行号、工作表行、原生视觉、不支持格式、幻灯片上限、非文本内容提醒和截断行为。存储测试固定客户隔离、不透明路径组件、normalizer 版本隔离、原子持久化和损坏记录保留。标准化测试让真实扫描型 PDF 通过隔离 Worker，并验证记录页面可以用同一来源键重新渲染，同时覆盖内容哈希缓存复用、来源变更拒绝和原始资料路径限制。工具测试固定可读状态、来源位置、提醒和游标。

已发布 Web 组合测试挂载真实 Finance 预设，证明 Standard 不会获得文档工具或 Skill，并在不使用模型和 API Key 的情况下，分别对客户 CSV 和通用咨询 CSV 执行 `finance_document`，快照其已记录且带来源位置的结果。产品层检查要求 Host 配置行、Finance 消费端、Skill、解析依赖、包清单、小兢 profile 限制和兼容适配文件同时存在。

## 结果

Finance 文档读取对支持文档保持确定性、本地处理、会话授权、作用域隔离、日志可重建和快速响应。咨询与客户会话继续使用同一个上传入口，模型不再消耗轮次发现转换器。扫描型与混合型 PDF 现在复用现有视觉模型，不增加 OCR 运行时或外部解析服务。`.ppt` 等旧版 Office 格式、完整 Office 或 OFD 页面渲染、演示文稿视觉重建、公式重算、宏、财务语义提取和 OCR 仍属于独立能力。若配置的模型不支持图片输入，它仍可读取文字单元，但不能理解渲染后的扫描页。
