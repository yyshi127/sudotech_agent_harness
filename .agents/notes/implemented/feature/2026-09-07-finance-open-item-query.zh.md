# Agent Note: 有成往来汇总独立分类

Status: implemented

[English](2026-09-07-finance-open-item-query.md) | 中文

## Problem

官方应收应付列表在记录数为零时仍返回负数 ID 合计及上一页总计。将所有 ID 都视为业务会虚构欠款，而丢弃所有零金额又可能遗漏真实零金额记录。

## Decision

Finance [往来投影](../../../../packages/xiaojing/xiaojing-finance-domain/src/open-items.ts)单独识别无日期、负数 ID、科目与辅助身份为空的汇总。有日期的正数 ID 业务记录必须提供绑定账套、金额、余额和币种。请求受已保存账套及明确方向控制。接口记录数仅为声明，不代表独立核验的完整性。共享 Host 检查拒绝凭据或客户配置已变更的结果。

[分析收集器](../../../../packages/xiaojing/xiaojing-finance-domain/src/open-item-analysis.ts)按统一声明总数核对每页并拒绝重复项，再按原币精确汇总。所有页及可选基准共用鉴权、截止时间和已保存账套授权。只有计数核对后的集合参与差额；缺席的分组代表零分组合计，不代表缺失记录为零。报告明确有成提供业务明细、小兢负责分组计算，区分记录集比较与历史期末余额，并明确没有原子快照一致性保证。开发验收状态保存在开发记录中，不嵌入每次运行结果；阶段结论会独立于查询数据变得陈旧。

XLSX 序列化器使用已完成的报告，不重新计算。明确的文本单元格保留精确金额与编号，并避免公式解释。独立来源记录工作表避免把多个 ID 塞入单个单元格。工作簿打开时直接显示分析结果，将普通查询元数据和限制放在最后；接口名和技术摘要不作为表格内容。金额不使用数值单元格，因为长小数在 Excel 中可能损失精度。分析工具的可选导出发起新的 Host 授权查询，并使用既有文件发布服务；不引入报告缓存，不接收模型编造的数据。Host 在关闭时等待序列化和发布结束，发布前检查取消，并允许已开始的提交完成。保留的工作副本不代表发布成功回执。

## Alternatives considered

原始记录导出区别于汇总分析：它从第一页开始读取，保留八项金额组成、可空结清标志、来源 ID 和两个币种字段，只有唯一业务记录数与接口总数一致后才发布。合计与上一页总计放在独立工作表。导出不额外汇总或推断付款分类，也不宣称取得供应商原子快照。

**按 ID 存在或零金额过滤。** 两者都不能区分生成的汇总与真实业务记录。投影使用已观察到的标记字段，对未知记录报错而非静默丢弃。

**推断结清或往来对象。** 通过金额相减或解释辅助名称会添加接口未证明的事实。结清组成金额分别保留，允许为空，不宣称实际银行收付款。

**只把一页返回值相加。** 可能遗漏业务或重复累加汇总。分析前必须核对完整记录数，不将完整性未核实的余额及日记账来源静默当作可用输入。

## Consequences

适配器只保留本地构造的 `OpenItemGroupingError` 提示，其构造函数不接收外部文本。供应商或传输错误仍使用既有脱敏分类，错误文本相同也不能进入本地提示分支。

按科目和辅助项目分组在生成报告或发布工作簿之前拒绝空白标识。名称存在不代表有稳定 ID，也不能作为替代分组键。仅按币种汇总不要求这些无关标识。聚焦测试覆盖空串及空格标识；组装导出场景核验失败且不发布文件。

两个方向均为只读，不引入写权限。投影/适配器与 Host 聚焦检查通过。真实空样例及非空样例覆盖汇总分类、分页和精确比较，样例验收不证明原子完整性或历史期末余额。[开发状态](../../../../docs/integrations/youcheng-finance-development-status.zh.md)记录当前证据与待验证项。独立的[日记账决策](2026-09-07-finance-journal-query.zh.md)仍适用于其不同汇总格式，未被替代。
