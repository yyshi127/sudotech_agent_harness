# Agent Note: 工作区空白会话上下文

Status: implemented

[English](2026-09-04-workspace-blank-session-context.md) | 中文

## 问题

其他插件改变当前会话的预设后，新会话模式选择器可能仍显示先前的选择。直接从侧边栏选择空白会话还可能绕过产品类别的上下文准备，使客户工作区停留在普通咨询状态。

## 决策

[模式选择器](../../../../packages/client/ui-agent-preset/README.zh.md)在没有待应用用户选择时，显示当前会话已提交的预设。待应用选择保持优先级，仍只通过既有应用流程消耗。显示同步不发起预设选择 RPC。

[Workspace 浏览器](../../../../packages/client/ui-workspace/README.zh.md)在分组和单列表视图中，均通过允许新建会话的产品类别激活当前空白行。既有 Finance 提供方在打开会话前选择预设并暂存工作区对应的客户。历史会话、普通工作区及禁止新建会话的工作区仍直接打开。

[Finance 控制器](../../../../packages/client/ui-xiaojing-finance-clients/README.zh.md)在暂存成功后使上下文显示失效并重新读取。因此复用当前会话时，无需跳转到另一会话也能刷新输入区。暂存失败不会发布上下文变更。

## 考虑过的替代方案

**只修改显示标签**仍会缺少客户暂存，无法建立业务工具需要的上下文。

**在通用浏览器中嵌入 Finance 选择**会让共享 UI 与单一产品耦合；既有类别激活操作已经负责此行为。

## 后果

侧边栏入口与输入区状态保持一致，不改变持久化客户数据、工作区路径或历史绑定。点击产品空白行可能重复执行类别准备；类别仍须在打开前拒绝不可用的上下文。

## 验证

聚焦测试固定外部预设更新、两种布局中的空白行激活以及历史会话直接导航。真实组装 Web 场景选择尚未暂存客户的空白会话，经过普通模式与咨询模式切换，再查询凭证并核验持久化客户绑定；只 mock 模型和供应商网络。
