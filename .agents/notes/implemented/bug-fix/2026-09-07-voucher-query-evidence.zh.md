# Agent Note: 凭证查询证据与上限

Status: implemented

[English](2026-09-07-voucher-query-evidence.md) | 中文

## Problem

凭证查询按会计期间筛选，却返回凭证日期。将两者等同会误拒绝有效响应，也不能证明筛选正确。未满的非末页可能遗漏凭证；仅检查客户版本无法识别凭据直接替换。

## Decision

已绑定客户的 Finance 提示监听器在每次请求中提供必要的跨来源比较与缺失字段规则。可选分析技能的发现机制不能保证普通混合查询收到这些规则。通过实际发布预设的首请求快照覆盖无技能调用时的送达；限定作用域的组装测试排除标准及咨询会话并验证卸载。这证明指令送达，不代表真实模型语义验收。

未经核验的比较不能证明正常或异常，测试账套也不例外。开头说明与最终结论遵守同一规则；免责声明不能修补前面无依据的判断。缺失数值和覆盖限制均限定到各自来源。借方或贷方负数保留接口原列，不解释成相反方向的余额。

共用只读适配器仅在查询诊断中保留固定允许列表内的网络原因码。仅有 `network` 无法区分连接重置、DNS 失败和连接超时，原始异常信息又可能包含凭据。未知错误码保持通用分类。Host 配置启用对可识别临时网络故障的一次重试，复用相同请求和原总期限；HTTP／供应商失败、永久 DNS 失败、未知错误及无效响应不重试。真实二级余额查询在认证时出现 `UND_ERR_CONNECT_TIMEOUT`，随后再次查询成功。有上限的重试处理这类故障，不宣称修复了底层网络。连接状态枚举保持不变。

现有列表工具按报告总数校验分页长度、拒绝额外查询字段、限制每次原始响应大小，并在发布前复查凭据。金额字符串优先；数值金额超过分单位安全精度即失败。持久化的范围说明区分会计期间筛选、凭证日期、分页张数及未核验的期间覆盖。

期间范围和摘要只映射到已记载的列表参数。结果保留请求条件及全部返回分录，不在本地删除未匹配行而破坏凭证平衡。请求参数映射测试不被当成供应商匹配效果的实测证明。

## Alternatives considered

按日期推断期间或静默接受未满页都会给出缺乏依据的完整性保证。这些修正不需要新查询框架。供应商摘要筛选不能替代语义理解：真实查询“取现”未命中“银行提现”。工具指令要求近义表达不直接用作该筛选。独立脚本创建的三张授权测试凭证证实了详情借方字段，不在产品中增加凭证创建功能。

## Consequences

真实应用查询能从口语识别提现凭证，并通过详情工具解析“刚才那张”。真实分页也出现多次 `query-failed` 后才成功，不能用后续成功证明原始原因。分阶段错误分类区分网络异常与投影拒绝，不暴露原始异常。这项诊断修正不证明间歇故障已修复，稳定性验收仍未通过。

详情工具与列表共用会话归属和凭据变更检查，核对返回账套与凭证 ID，并投影经核验的十进制金额、期间、制单人和状态。附件、辅助核算及外币明细明确不在返回范围。账套 35601 的只读检查验证了两页非空数据、越界页、期间范围、摘要样例及三张详情的身份。即使存在三张凭证，越界页仍报告总数为零；受大小上限约束的结果说明防止将其当成空账套。聚焦测试和真实预设 Web 场景覆盖投影及列表到详情执行；模拟模型调用不证明语义理解能力。真实应用已验证口语查询、上下文详情定位及多候选；功能验收和独立稳定性问题见[开发状态](../../../../docs/integrations/youcheng-finance-development-status.zh.md)。
