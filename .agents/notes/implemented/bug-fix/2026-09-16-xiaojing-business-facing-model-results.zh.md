# Agent Note：面向业务的模型结果

状态：已实现

[English](2026-09-16-xiaojing-business-facing-model-results.md) | 中文

## 问题

即使浏览器卡片已经显示简洁的业务结果，小兢会计工具仍可能把内部证据直接返回给模型。Finance 结果包含取数元数据、诊断信息和存储回执，一些工具说明还明确要求模型报告内部状态。任务成功后，最终回答因此可能输出重试历史、分页机制、校验值、字节数、字段名和测试说明，而不是用户要求的交付物。普通会话与微信会话也没有共用的产品级回答规则。

## 决策

所有小兢会计预设都获得一段稳定的业务化回答规则。成功回答先给可用结果，不叙述失败尝试；失败回答只说明用户可见影响、已知的日常语言原因和一个可执行的下一步。生成文件按内容与可用位置交付。只有会改变理解、操作安全或下一步的实质限制才保留。

所有 Finance 工具现在将模型可见结果与 Host 持久记录分别投影。投影保留业务数据和后续确认操作需要的连续标识，并递归移除诊断、取数、校验值、字节数及测试元数据。底层传输和响应校验错误在进入模型前改为一条可执行的财务失败说明，业务校验错误仍保持具体。工具说明也改用业务语言，不再要求报告内部状态名。

微信文件发送和可视化结果不再向模型暴露字节数。浏览器与 Windows 控制结果继续保留页面、窗口和目标的不透明标识，因为模型下一步自动化操作需要它们；产品级规则禁止把这些操作标识写入最终用户回答。财税依据、确定性试算和文档读取继续保留来源位置、前提、计算步骤及实质解析提醒，因为它们属于用户要求的业务证据，而不是实现诊断。

## 备选方案

**只依赖最终回答提示词。** 未采用，因为原始证据仍然十分显眼，模型遵循提示具有概率性，源结果也必须投影。

**删除所有标识和状态字段。** 未采用，因为确认写入、恢复、文档续读和浏览器自动化需要不透明的连续值。只有下一步确实需要时，它们才对模型可见。

**重写所有框架工具。** 未采用，因为缺陷位于小兢会计产品组合和小兢会计自有工具。产品级规则加局部投影可以修复自有表面，不改变无关的 Harness 行为。

## 影响

Host 日志和持久记录继续保留完整恢复及审计证据，模型上下文更小，也更不容易复述实现细节。用户明确要求时仍可提供技术诊断。提示词不能绝对保证输出，因此继续用无密钥完整组装快照验证代表性的最终回答和工具结果投影。

## 验证

单元测试覆盖产品级提示词、Finance 结果递归投影、底层错误净化、Finance 工具行为、微信文件回执和可视化回执。Finance Web 快照通过发布预设执行，并验证业务化导出与操作结果不包含内部取数元数据。
