# Agent Note：小兢会计财务验收加固

状态：已实现

[English](2026-09-17-xiaojing-finance-acceptance-hardening.md) | 中文

## 问题

财务验收发现模型路由、写操作预览、余额比较、资料遍历、税务输入、附件、工作簿、连接错误和会话终态存在正确性或交付缺陷。部分缺陷可能生成表面合理但业务错误的回答、续办无关的历史写操作，或在轮次结束后仍让桌面显示运行中。

## 决策

财务模型上下文现在以用户当前明确请求为准。只读请求不能续办历史写操作，失效预览只能说明需要重新准备。上下文严格区分准备、上传、提交、供应商接收和独立回查；除非用户明确要求诊断，普通回答不输出实现诊断信息。客户显示名称与外部账套名称相互独立；政策依据一旦核验通过，即使客户适用性仍未知，也不能把依据重新降级为待核验。

科目树查询从指定根科目开始，按父级身份遍历返回结果中的全部后代。余额比较必须使用紧邻操作的同一份基线，并分别比较借方和贷方。企业所得税已预缴额是必需输入，缺失时不能默认零。中国大陆政策路由包含苏州。往来比较把完整结果中缺失的分组解释为零组总额，不生成金额补零的虚构记录。

凭证准备在生成可执行预览前拒绝不支持的附件格式。外币确认同时显示币种、原币金额、汇率和本位币金额。凭证上传对象保留安全且带扩展名的文件名。调用方指定归档目录时，本次操作直接使用该目录，不再额外生成默认日期目录副本。

财务工作簿使用可读列宽、冻结表头和中文标签。余额输出使用“本年累计”；比较输出标明两个实际期间，并分开展示来源行、分组汇总和勾稽结果。精确金额继续以文本保存，避免 JavaScript 或电子表格二进制数对大数和高精度金额造成静默舍入。

客户端收到实时 `turn/start` 和 `turn/end` 后立即发布运行状态。上下文压缩即使未产生检查点，失败也保持可见，并提供安全重试提示。财务连接错误向用户显示中文说明，详细原因只保留在日志中。

## 备选方案

**依赖模型自行判断历史意图。** 未采用，因为历史写操作在上下文中仍很显眼，可能在新的只读请求下被错误续办。

**把精确金额文本转换为电子表格数值。** 未采用，因为这只改善表面格式，却可能静默损失精度。列宽、表头和标签可以在不削弱会计准确性的前提下改善可读性。

**把每个验收缺口都当作代码缺陷。** 未采用。偶发查询取消和配置变化后恢复旧删除仍需稳定复现并确定责任组件，当前继续作为调查项。

## 验证

聚焦单元测试覆盖模型上下文规则、完整科目后代、税务输入校验、附件前置校验、外币确认、余额及往来语义、归档目标、工作簿展示、实时轮次结束和压缩失败展示。无密钥 Finance 完整组合快照验证发布提示词和凭证流程；Web 回放验证中文连接错误及受支持的凭证附件流程；完整源码构建通过。

## 影响

财务功能现在优先遵循当前明确意图、保证会计数值安全，并输出面向业务的结果。不支持的文档格式会在确认前失败，不再生成误导性预览。两个证据缺口继续单独跟踪，不计入本轮已完成修复：F08 偶发取消，以及配置变化后恢复旧删除。
