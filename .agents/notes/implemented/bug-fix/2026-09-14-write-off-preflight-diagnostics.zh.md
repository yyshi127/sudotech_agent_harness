# Agent Note: 核销发送前检查诊断

Status: implemented

[English](2026-09-14-write-off-preflight-diagnostics.md) | 中文

## 问题

已预留的核销可能在发送前重读证据、检查身份或执行最终 Host 回调时失败。笼统的未发送结果丢失了最后执行到哪项检查的信息，即使没有写入，也无法在之后准确定位。

## 决策

预留发送器仅在 not-sent 结果中记录有界的 `preflightStage`。记录存储校验该字段，并在重新加载和检查时保留。阶段标识检查步骤，而不是供应商根因：`final-confirmation` 表示批准之后的最终 Host 回调，不表示用户拒绝。不会新增凭据、供应商原始消息、任意诊断文字或重试权限。接收和未知结果保持不变。旧的未发送记录可以不带这个可选字段；不会从后来的观察重建缺失历史。

## 考虑过的替代方案

**保存原始异常。** 不采用，因为请求和供应商错误可能包含凭据或无关财务数据；最后执行的本地检查足以缩小调查范围。

**重试旧失败操作来诊断。** 不采用，因为后来的状态不是原始证据，诊断改动不能重新开放已消耗的意图。另行确认的新方案仍遵守现有执行资格规则。

## 影响

传输测试验证有界阶段及失败时零写入。持久记录测试保留旧结果和带阶段的结果，不重新开放执行。组装后的 Finance 场景覆盖应收和应付预留后来源查询失败、阶段展示、原结果保留及重复发送拒绝。阶段缩小调查范围，但不能事后证明旧笼统失败的原因。
