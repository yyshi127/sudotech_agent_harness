# Agent Note: 财务交付结果以业务内容为主

Status: implemented

[English](2026-09-15-finance-business-first-complete-exports.md) | 中文

## 问题

财务 Excel 导出打开后首先显示技术性的查询说明，而不是用户要求的业务记录。凭证、日记账和往来导出还复用了普通查询的分页设置，因此用户要求导出记录时，系统可能只发布所选页面却表现为成功。即使财务工具已经提供业务展示，工具卡片和详情仍可能暴露原始参数、JSON 结果、内部编号及诊断入口。

## 决策

所有财务工作簿现在只包含业务明细、合计或分析结果，不写入查询元数据、接口名、内部编号、响应摘要、覆盖状态和测试措辞。金额与业务编号仍使用受公式防护的精确文本。

所有有成财务查询与操作工具都提供简洁的业务调用和结果展示。财务文件保存与归档的结果只显示完成动作、文件名和位置，不显示哈希、字节数或存储回执。通用客户端在会话行与详情中使用这些展示，并隐藏只供兜底诊断的输入／输出标签和调用轨迹入口。模型可见结果保留业务字段和后续操作字段，但不包含内部审计元数据；完整持久证据仍保留在 Host 中供恢复和安全检查使用。

财务失败卡片会去掉通用 `Error:` 前缀和机器状态码。可行动的业务提示继续保留；出现接口路径、原始结构或参数名时，改为安全的连接、权限和网络检查提示。

绑定帐套的财务会话获得统一交付规则：最终回答和生成文件先给业务结果与实际数据。只有用户明确要求技术诊断时才展示技术名称和内部证据。限制仅在影响金额或范围的理解、操作安全或需要用户采取行动时保留，并使用简短的日常语言说明。

凭证导出忽略调用方分页，使用财务凭证工具配置的分页大小，从第一页开始读取，只有唯一凭证数与稳定的接口总数一致后才发布一个工作簿。模型可见的成功回执不包含哈希、字节数、分页和内部证据。应收和应付导出对唯一业务记录数采取相同规则。这些导出都拒绝总数变化、短页、重复记录、超过配置限制及发布前取消。这些检查证明记录数完成核对，但不证明取得供应商原子快照。

日记账接口既没有可信总数，也没有末页标志。因此日记账导出从第一页开始读取，直到首个没有业务流水的页面，同时拒绝重复记录和超过配置限制。输出明确这是当前可用的最强收集规则，不将其表述为供应商计数认证的完整结果。

## 考虑过的替代方案

**继续导出所选页面并在元数据中解释。** 不采用，因为“导出凭证”通常表示导出符合条件的业务记录，警告不能弥补文件实质不完整的问题。

**为便于审计保留技术说明表。** 不采用，因为内部证据仍保存在会话和操作记录中；在业务工作簿中重复这些内容会降低文件的可用性。

**把首个空日记账页当作完整性证明。** 不采用，因为供应商响应没有提供总数或快照保证。实现如实披露限制，不编造更强证据。

## 影响

凭证、日记账、应收和应付导出可能发起更多供应商请求；收集期间数据变化或达到配置限制时会安全失败。失败的收集不会发布残缺工作簿。余额和分析工作簿只包含业务数据，但其既有来源覆盖限制不变，并在确实影响使用时于表格之外说明。查询工具仍保留明确分页供交互查看；只有正式导出操作按照上述规则收集所请求的完整范围。

## 验证

聚焦收集器测试覆盖从第一页重启、多页读取、计数核对、重复及总数变化拒绝、限制和取消。工作簿测试验证仅包含业务工作表、精确文本和公式防护。客户端测试证明业务展示会在会话行与详情中替代原始参数和结果。无密钥的完整组装 Web 场景通过发布的 Finance 预设执行查询、操作和完整范围导出，并重放内部持久结果及面向用户的业务卡片。
