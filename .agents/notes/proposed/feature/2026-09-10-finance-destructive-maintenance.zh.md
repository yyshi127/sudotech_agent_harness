# Agent Note: 财务删除与核销

Status: proposed

[English](2026-09-10-finance-destructive-maintenance.md) | 中文

## Problem

F3B 改动已有会计记录。HTTP 成功、详情查询失败或筛选空页均不能证明目标已删除或核销。每项操作必须使用已核实的供应商字段，不能用调用方生成的标识或未经证实的来源要求替代实时目标检查。

## Proposal

2026-09-15 当前检查点：供应商给出的凭证删除最小请求为 `accountName` 加 `cerInfoList: [{ cerId }]`，appId 和 flowId 不是删除字段。产品现已根据绑定账套及准确凭证的实时检查生成该请求，不再要求本地创建记录。领域聚焦测试及组装后的无 Key Web 刷新／回放通过。真实适配器实验创建专用凭证244499，单次发送最小删除请求，观察到接收及两次完整不存在清单，最终41张凭证投影与实验前基线一致。[回执](../../../../critique/f3b-lab/receipts/cf12-minimal-voucher-delete-20260915.json)不含凭据。浏览器手工录入来源及更广关联影响仍需单独核实，因此本提案保持 proposed。此前[六路径回执](../../../../critique/f3b-lab/receipts/f3b-main-app-acceptance-20260914.json)继续证明当前代码 CF12／CF15／CF22／CF23／CF24／CF25 通过真实主应用、两次独立回查及新会话检查。[最新交接](../../../../docs/integrations/youcheng-finance-f3b-handoff.zh.md)记录继续执行状态。

### 早期实现检查点

Host通过既有准确版本预留及强制确认接入整笔核销执行。当前资金账户科目代码须对应启用末级科目，且明确返回空币种列表；只有原币种与本位币一致的往来可以执行，不猜数值币种ID映射。确认前后及发送前比较同一资金账户／科目证据。公开接口未提供的期间状态明确标为未核实，不虚构检查通过，也不把不可用端点设为永久前提。重查不是供应商并发锁。两个方向均有应用组合批准、拒绝、旧版本、接收成功及响应丢失场景；真实主应用执行仍须专用验收。

恢复观察身份时不要求目标仍未结清或可再次发送。来源页和原始业务账户ID来自同一已认证响应；身份缺失时保留有效投影内容，并将身份标为不可用。即使账户名称、核销金额和回执关联流水吻合，ID变化也阻止操作匹配。身份不可用的旧记录保留已接收回执，不改写数据或重建权限。[已结清身份实验](../../../../critique/f3b-lab/receipts/writeoff-settled-business-identity-20260910.json)以六次读取、零次写入观察两个原获批已核销目标，不据此升级缺少保存身份的原记录。正式应用场景分别覆盖两个方向的身份变化。

全额核销准备从与来源页相同的已认证原始响应中取得并保存businessAccountId。发送在占用前比较最新原始身份，同时检查账户和已知关联限制，避免普通投影掩盖同名账户变化。缺少身份在授权前阻止占用；身份不可用的记录及已接收回执仍可读取，不改写记录或重建权限。必需原始状态不能默认为安全；可选关联ID仍沿用空值／null／零值惯例。[业务身份实验](../../../../critique/f3b-lab/receipts/writeoff-business-identity-20260910.json)以六次读取、零次写入分别核实应收72602／账户174626及应付72603／账户174624。此项不核准币种／期间资格，也不开放Host执行入口。[基础资料元数据实验](../../../../critique/f3b-lab/receipts/writeoff-reference-metadata-20260910.json)发现嵌套币种代码，但没有资金币种ID映射或可记账期间状态；历史流水币种不能替代当前配置。

凭证删除在检查、准备、强制确认、提交结果及恢复中共用一份附件提示，包含该提示出现前保存的记录的恢复。不增加审批层、文件删除请求或保留承诺。浏览器场景包含带附件凭证，并禁止请求来源或有成转存文件主机；断言覆盖确认面板及已记录的预览／结果，不仅依赖模型说明。

[附件删除实验](../../../../critique/f3b-lab/receipts/f3b-voucher-attachment-deletion-20260910.json)核实专用244306删除后，原OSS及有成转存文件仍可下载且哈希一致。凭证不存在与文件清除必须分别表述；不得把前者升级为后者，也不得自动删除来源文件。此证据仅覆盖一个合成附件的适配器路径，仍需主应用确认及结果呈现验收，不承诺永久保留。

[凭证主应用回执](../../../../critique/f3b-lab/receipts/f3b-voucher-main-app-20260910.json)通过真实模型调用、强制确认及独立完整列表保留检查，核实原Host创建、未审核、无附件的路径。该历史回执本身不能核实后来最小请求下的网页创建凭证或附件删除影响。测试造数及审批编排保留在独立实验脚本中，不进入产品代码。

[真实模型主应用回执](../../../../critique/f3b-lab/receipts/f3b-journal-main-app-20260910.json)核实合成141110的准确预览删除、独立月内现金余额以及其他已观察记录未变。开发者持续测试授权通过实际强制审批通道执行，不绕过产品。通用与财务确认仍分开；合并时必须保留执行令牌的单调安全保证，不能增加工具名豁免。该样例创建已接收，但preId不一致仍未解决，不属于创建完整核验通过。

已核实的日记账删除请求携带id及从固定已确认清单取得的accountName，发送前重新核验账套唯一身份及完整内容。专用141107实验在补入accountName后收到result100，月内未出现、保留业务行及指定资金账户余额分别匹配。公开文档仅列id，遗漏该必填字段。单元、Host及正式应用组合的网络断言要求账套名称，不仅接受成功响应。开发者常设授权允许在35616内对限定合成样例自主测试，不重复询问；它不取消产品确认、不允许任意清理历史数据，也不释放未知发送意图。

在财务插件中实现六项 F3B 动作：删除凭证、日记账、应收、应付，然后实现应收及应付核销。保留方向专属校验与回查、精确目标、明确影响预览、绑定准确版本的强制确认、发送前持久目标预留，以及不重试的单次写入。结果未知时保留原意图，仅只读排查。不引入通用工作流引擎、自动关联删除或实际支付执行。

凭证检查校验绑定账套与目标，要求返回状态及关联字段，汇总附件和辅助分录数量但不暴露附件 URL，并对有界原始 JSON 生成指纹。指纹变化需要重新预览；JSON 属性顺序变化也可能保守地使其失效。这不是供应商锁，也不证明覆盖全部关联。已知审核、结账、系统生成、关联或尚未核实的调整期间状态会阻止本地路径。缺失元数据时拒绝继续，不转换成 false 或空列表。

供应商确认的删除参数包含 Host 生成的 accountName，以及一个只含 cerId 的 cerInfoList 项。准备操作接收准确凭证 ID，解析绑定账套并实时读取凭证详情；调用方不能传入 appId、flowId、账套身份、来源会话或接口覆盖。Host 确认准确预览并在预留前复核；发送器在单次请求前重读目标并检查当前配置。接口接收与删除核验保持分离。格式版本2拒绝原参数格式；目标占用如果引用旧记录，会保守阻止新发送。

删除记录按客户／环境／账套跨会话共享归属。每次本地操作保留版本、预览、原始参数和结果。预留同时锁定目标与操作，先保存目标占用，再保存 outcome-unknown 后返回。两次写入之间崩溃时，占用记录指向 prepared 状态，仍会阻止再次发送，不把目标当作未占用。只有此前明确拒绝或未发送的结果，才允许另行确认的新操作；旧记录保留。原子替换支持进程重启恢复，不保证掉电 fsync 持久性，也不是供应商锁。

Finance 预设注册独立的准备／检查工具与删除工具。Host 拒绝目标或确认覆盖字段、旧版本、配置变化及凭证证据变化。恢复绝不调用写接口：两次完整、一致、无筛选的全部期间清单均不包含目标，才能报告 absent。分页超限、查询错误、总量变化、重复 ID、筛选或两次清单变化均不能证明不存在。配置页数上限分别约束每轮读取，最终响应也受字节上限限制。

独立实验室把真实写入限定在账套 35616 中已明确批准的测试对象。已批准的专用凭证 244240 核实了该参数及单次发送路径：两次成功、完整、无筛选的全部期间列表查询均保留原有 41 个 ID 及投影分录，同时不再包含目标。这不证明所有无关详情字段完全一致、附件自动删除、产品组装确认流程或重启恢复。[开发状态](../../../../docs/integrations/youcheng-finance-development-status.zh.md)记录当前证据及剩余检查点。

日记账删除检查保留响应外层业务总数，不改变普通日记账查询结果。两次完整月内分页须总数稳定、ID 唯一、原始业务行指纹一致，并读到明确的空业务末页；汇总标记不计为业务行。缺失总数、汇总变化或超限时拒绝该证据。目标须返回审核、账户、来源、附件、关联及可核销金额字段；未核实状态仍阻止执行。月内按总数核对的未出现不等于全账套不存在。

日记账比较分开报告保留内容与观察到的余额。对一个指定资金账户，原目标带方向的原币／本位币金额决定后续余额差异，期初余额保持不变。金额、币种或汇总余额缺失时不能返回余额匹配。发送器再次核对完整已确认清单，在调用方最终检查后只发送一次准确日记账 ID；不调用凭证删除，也不重试未知写入。

日记账 Host 要求明确月份、资金账户和流水 ID，保存包含目标的完整清单，并在取得共享流水占用记录前强制确认准确版本。持久化校验检查行数、唯一 ID、指纹、日期和目标身份，保留字段顺序供新查询比较。准备和恢复不能接收目标账套或确认状态覆盖参数。发送后取消仍保留观测结果；恢复只比较原月份／账户，不把范围内未出现升级为全账套删除结论。存储复用原子替换及文件锁，使用日记账专属证据而非凭证请求字段。Finance 的准备／恢复与删除分别注册工具，使用通用卡片展示。无 Key 组合测试覆盖真实预览、旧版本拒绝、用户拒绝、强制确认、重复拒绝，以及接收成功和响应丢失后的范围内恢复。仍需获批对象真实删除及完整业务验收。

应收／应付检查复用现有鉴权读取器，保留同一响应的原始状态字段。两次按总数核对的清单保留原方向及期间，拒绝范围外或重复记录，并要求空业务末页。目标分开报告已观察到的核销、期初、账户、附件及凭证／订单限制，与尚未核实的审核、来源及完整关联约束。阻止原因列表为空不代表允许删除。独立比较分开报告目标观察、保留内容及保留记录余额；本位币余额缺失或没有保留记录时，余额核验仍不可用。不用供应商汇总证明全账套余额。这些只读适配器操作未注册为删除工具，不能替代待完成的获批真实删除及组装确认流程。

有成官方网页提示，删除往来记录可能同时移除关联的对冲、核销或收入记录。网页端点与公开 V2 不同，因此这证明存在需核实的风险，而非两者服务端行为相同。公开列表投影不足以证明完整关联：网页还展示其他核销组成金额，已测公开记录未返回该字段。检查保留其他金额缺失为未核实，拒绝已返回的非零／无法识别金额，并在凭证显示文字为空但返回凭证 ID 时阻止操作。不从网页私有明细路由猜测公开地址，也不因汇总金额为零清除这些未知状态。确认后单次发送的接入仍需完成该项核实，不能放行未经批准的联动删除。

整笔核销准备校验准确 ID、限定方向的来源查询、币种、日历日期及完整正数未结余额。数值传输校验保留十进制 JSON 表示，不只核对四舍五入后的显示文本。本地拒绝部分核销、端点／确认覆盖字段及未核实的日记账关联参数。新查询的投影目标只是必要条件：Host另行检查当前资金账户／科目资格、原始状态及已知关联，并预览生成资金流水的影响。

回查独立比较未变化的业务内容，以及未结余额为零、已收已付金额精确增加、结清标志和坏账／对冲／退回组成金额未变。仅余额比较仍将操作证据保留为未核实。Host检查另行执行两次按总数校验、结果一致且包含末尾空页的整月查询，将原已接收回执与唯一日记账relationId匹配；缺失元数据、重复ID、业务字段冲突、分页变化或超限均不能确认操作。仅原内容、核销金额及回执关联日记账均匹配时产生 `operation=matched`。查询失败、目标缺失或组成金额未提供，均不能返回核销金额匹配。这些只读观察不改写已保存结果，也不允许再次发送。

独立日记账实验仅对专用样例141107复用产品发送器。默认路径只读；精确目标执行参数属于需要事先人工批准的操作，不是已有批准的证据。发送前比对创建指纹、当前配置和新取得的日记账／往来／凭证清单，再独占保存并同步结果未知的操作意图。已存在意图时只允许检查。注入I/O的离线测试覆盖预留竞争、中断、配置变化及回查失败，不读取凭据。限定范围余额、其余业务内容及传输接收分别呈现；此实验不替代产品组合验收。

已批准的专用应收应付实验核实公开删除参数booksName、managementId，以及不猜填journalId的文档已收／已付核销参数。每项实验保留独占意图、经凭据检查且限大小的响应，以及独立前后查询。实测两项核销各生成一条资金流水；响应data不同于流水ID，并在后续专用只读检查中匹配原始relationId。仅金额一致或WRITE_OFF来源不足以核验关联；回执和流水标识不可互换，这些观察也不证明银行付款。已知关联仍阻止自动删除，专用实验成功不证明级联或任意历史记录安全。按文档仅传id的日记账删除返回明确拒绝；其分类器未保留供应商消息，因此该观察不能确定原因或允许重发。

内部应收／应付预留发送器只负责已核实的公开删除请求及传输观察。它固定原配置／证据，重读原方向／期间完整清单，核实账套名称唯一身份，并在发送前拒绝调用方对象变化。调用方须核实剩余关联风险并持久保存已准确版本确认的预留；阻止原因列表为空并不足够。仅模拟网络的测试覆盖两个方向、目标及保留记录变化、同名歧义、预留失败、取消，以及响应丢失／无效／超限／含密钥。此适配器增量没有注册模型或界面入口，因此组装确认／恢复快照仍须随 Host 接入完成，不能由单元测试冒充。

应收／应付删除持久化复用已有原子文件和锁，并校验自身的方向／期间清单。目标占用键不含方向，因为删除请求只以账套名称及 managementId 定位；改变查询方向不能为同一供应商记录获得另一次发送机会。占用内容仍保留方向用于一致性核对。先保存占用、再保存未知操作记录，明确选择在中断后阻止操作，而不是重复写入。引用操作缺失或损坏仍阻止发送。确认回调后在锁内除版本及配置外，还核对完整预览一致。已知阻止原因禁止预留，未知约束持久保留，交由调用方核实。真实临时文件测试将存储与实际发送器、模拟网络串联，独立范围回查后仍保留接收成功或未知结果；这不是组装 Host／界面或真实业务验收。

Finance 预设开放应收／应付删除前准备及只读恢复，不开放内部发送器。Host 校验保存的客户／工作区及配置，持久保存准确版本，在关联影响未核实期间报告执行不可用。检查沿用原方向／期间，保留原始预览及传输状态。正式应用组合浏览器快照覆盖两个方向、旧版本修改、可见限制和持久保存的未发送记录；网络路径断言拒绝任何业务写入。这不证明真实模型意图识别或破坏性执行已验收。

内部整笔核销发送器固定文档已收／已付参数，在发送前重读原目标页及启用资金账户资料，并核实账套名称唯一身份。证据变化、部分金额及方向错误均阻止发送。响应字符串保留为 receiptId，不当作 journalId：已批准的真实实验表明这些标识不同。Host核实原始状态、币种及已知关联，要求准确版本确认并明确提示期间未核实；适配器仍是内部单次发送传输。两个方向的模拟传输测试保留拒绝及未知响应，不重试。

整笔核销记录保留自身输入、投影原始页及未筛选资金账户资料，不复用创建或删除证据。既有原子文件及锁机制按账套／往来 ID 串行化不同会话和查询方向的占用。先保存占用的顺序刻意让中断写入保持阻止状态；余额匹配不能抹除未知发送。在调用方资格检查及确认后比较完整预览，并在占用前将最大成功回执计入大小检查。仅明确拒绝或未发送允许单独重新确认的新方案。这些本地核销占用不排除删除操作或供应商侧写入。临时文件测试覆盖重载、损坏及并发预留，并把真实预留发送器与模拟网络组合，在核销金额回查匹配后保留回执或未知结果。这些内部测试不替代单独的Host和应用组合确认测试。

Finance预设将整笔核销准备及只读检查与强制确认执行器分开。Host恢复绑定原客户、工作区和配置，保留准确金额及所选资金账户，并比较新来源页观察而不改写原始传输状态。模型不能通过该工具请求发送或提供批准标记。真实预设网页场景覆盖两个方向、版本失效及独立查询成功／失败；直接Host测试还在新会话恢复已接收或未知记录。只有匹配已接收回执关联的观察才能核验操作归因；这不代替真实执行验收。

日记账实验传输在把原始有界响应交还产品分类器前，将HTTP状态、数值结果码及拒绝响应的字符串消息保存为单独的私有诊断。它不保存任意响应data或响应头，对已知凭据的明文、URI编码和Base64形式作屏蔽，不向模型转发该文件；这不是通用秘密识别器。超限或保存失败时，已消耗的意图保持未知且不得重试。不能重放既有尝试以补回丢失消息。产品结果格式保持不变；没有实际新获批请求的响应，诊断机制本身不能确定拒绝原因。

日记账预留在确认后比较完整原始预览，包括格式有效但未变更版本号的持久内容替换，并在选择目标锁前拒绝回调对预览的修改。发送器另行在认证前固定原配置和清单，将新查询与固定副本比较，并在最终回调后拒绝调用方对象变化；这避免回调期间更换密钥或环境而改变已确认请求的目标。真实Finance组合场景在审批框打开时修改已保存证据，核验没有发送、记录仍为prepared且拒绝结果进入日志。通用删除确认与详细Host确认仍同时保留；按工具名省略前者会削弱既有产品策略，而不是安全合并同意。

凭证预留同样将确认绑定到完整原始持久记录，而不只比较版本及配置摘要。即便目标ID和详情指纹未变，同版本请求参数或预览变化仍构成不同请求。回调修改在选取目标锁前被拒绝；持久内容变化在操作锁内、取得占用前被拒绝。发送器另行在任何认证等待前固定配置、请求参数和检查证据，并在发送前再次比较调用方对象。组合场景在强制确认框打开时修改已保存的预览；点击允许不能授权变化后的请求。既有两层确认保持有效。真实适配器实验只证明一个API创建的合成凭证可使用最小请求，不代表所有来源或关联状态。

## Alternatives considered

**重置被拒绝的诊断意图。** 不采用：新批准必须使用独立固定目录和独占意图，并保留前次记录的账套、目标及明确拒绝。诊断02要求原141107/reserved201记录；已接收、未知、错误账套或目标均不能满足前提。本次获批仅含id的请求返回`帐套名称不能为空`，新读取的公开文档仍仅列id。这证明存在未记载的要求，不证明具体字段名，也不授权进一步请求。只读恢复将清单未变与删除成功比较分开报告。不能依据未经测试的字段名猜测修改产品参数。

**从投影缺失或数值币种ID推断执行资格。** 不采用：原始公开账套响应没有期间状态，资金账户currencyId也不是币种代码。既有已结清记录或未明确的流水币种不能证明当前映射。独立实验只读取准确既有来源，保留缺失字段，不通过修改账户推断状态。被拒绝的删除可通过单独获批的新尝试调查，但不能删除或重置已消耗意图来复用旧批准。

**按回执核验日记账关联。** 独立[原始字段检查](../../../../critique/f3b-lab/receipts/maintenance-relation-id-20260910.json)确认两条获批样例的relationId字段。产品核验器保留原已接收回执，要求有界、按总数校验且唯一的匹配证据，包括资金账户、方向、日期、金额、币种和原往来单位。拒绝仅按金额匹配或把receiptId当作journalId。SHA256指纹比较两次清单的原始及投影业务行；它检测观察到的变化，不排除观察范围外的并发写入。Host及真实组合测试在成功或失败的回查后均保留已接收结果。这不证明全账套完整性、银行资金变动，也不授权进一步写入。

**把创建成功或查询错误当作删除证明。** 不采用，因为接收不证明不存在，权限或网络错误会隐藏仍存在的记录。

**为删除保留或生成 appId／flowId。** 不采用，因为供应商确认的最小删除请求不使用这些创建字段。强制要求会排除有效手工凭证，临时生成则引入未经核实的标识。

**先开放通用 API 调用器或开发浏览器扩展。** 不采用，因为前者扩大权限，后者延迟六项具体动作，且都没有解决业务校验与恢复要求。

独立应收应付实验通过已有且已核实的创建适配器分别生成删除和核销样例，不在产品内加入造数功能。创建操作记录前保存独占批次意图，保留未知结果而不重发；每次创建被接收后比较原有往来、流水及凭证。只读执行报告已有标记而不重新造数。创建授权与准确对象的破坏性操作授权分开；新建样例缩小实验范围，但不消除供应商关联未知项，也不证明历史记录安全。

## Acceptance criteria

每项动作需要准确目标选择、完整影响预览、强制确认、配置及状态复核、持久跨会话防重复、有界单次发送、真实结果分类和独立业务回查。单元测试、真实组装应用快照、获批实测数据及恢复测试分别覆盖对应层。模块级发送器和只读检查不能单独完成 CF12；F3B Goal 仍要求六项全部完成。

## Risks

产品通用删除保护也会在财务 Host 前请求确认。组装测试保留两层审批，不按工具名豁免或隐藏删除用途。合并确认仍须保留 Host 内准确版本强制校验；重复确认作为明确的体验缺口保留。

公开接口未证明支持条件删除或供应商事务锁。最后一次查询后状态仍可能变化，未知结果不得重发。原始标识缺失、不可观察关联及回查不完整必须保留为可见限制。测试造数权限不授权删除任意已有记录；实际删除与核销需要准确对象批准。
