# Agent Note: 财务业务创建

Status: proposed

[English](2026-09-09-finance-business-creation.md) | 中文

## Problem

凭证创建不能覆盖日记账、应收、应付或基础资料创建。这些操作的标识、方向规则和回查证据不同；拿凭证的成功响应作为它们的完成证明，会掩盖业务记录缺失或错误。

## Proposal

在小兢财务领域内实现获批的五项 F3A 能力，分别校验业务和解析真实资料。按适用条件复用确认、原子持久化和有界单次发送机制，不建设通用工作流引擎。每项操作都需要可修改的本地预览、准确版本的强制确认、发送前持久预留和独立回查。结果未知时保留原发送记录，不得自动重发。创建基础资料是单独确认的操作，不能因缺少资料而隐式触发。

日记账请求的 subjectId 使用返回的资金账户 ID，不使用会计科目 ID。金额只能填一侧，另一侧为 null。选定收支类别后检查方向和同名歧义，因为写接口接收 categoryName 而不是资料 ID。前序记录必须由 Host 单独核验，不能未经检查默认填零。初始纯准备模块不授予任何外部写入权限。

回查比较选定类别ID：供应商可能给显示名增加收支前缀。在比较前先保留成功响应的ID，不能因显示名差异而重发。有界的已接收ID查找核对准确记录及其返回的关联／审核字段，不宣称历史全量或实际收付款。两笔真实日记账样例核验内部接口链路。独立的组装应用测试验证真实确认界面、准确本地版本、拒绝、单次发送和未知结果保留；模拟供应商返回不能替代真实业务证据。

辅助项目准备要求明确类别、编码、名称、提交人和状态，以及独立核实的账套和未筛选的类别／项目返回集合。重复编码或名称阻止创建，缺少类别不会隐式新增类别。纯校验不证明真实写接口可用，也不证明全量不存在。即使预览明确要求启用或停用，供应商回查未返回的状态仍保持未知。

科目准备保留借／贷语义，不复用查询原始标志。显式编码／父级／分类遵循文档4-2-2-2结构。将现有末级或层级未知科目改为父级，需要独立核实历史影响；已启用的既有分支另行记录。重码和同父级重名拒绝，其他父级下的同名项保留展示。标量准备不证明具体类别、辅助／币种配置或真实写入映射已核实。

基础资料记录只共享已经核验的科目／辅助项目无ID传输状态；业务校验和请求映射保持独立。本机目标预留独立于单份预览持续保留，防止新UUID或会话绕过未知尝试；只有持久明确拒绝或确证未发送，才可经单独确认再次使用该目标。只保存了目标预留、尚未保存对应记录时保守要求核对，以放弃自动恢复换取避免重复创建。该机制不代表跨设备幂等。发送器不重试变更请求，读取暂时失败或发送后取消也不例外。

Finance Host和工具复用已有强制确认服务，对科目／辅助项目准确版本确认后，在发送前持久保存目标预留。新鲜查询检查父级核算设置、类别身份以及重码／重名。开放一级科目及普通现有分支下的新科目；末级提升和数量核算在确认前拒绝。显式辅助／币种选择遵循[核算配置决策](../../implemented/feature/2026-09-14-subject-accounting-options.zh.md)，不改变父级设置。一级科目类型必须是当前账套同总分类资料中已观察到的名称，不维护自造类型目录。账套35616的一级科目1099独立核验确定了方案父级为null、公开请求不传父级参数、回查父编码为空字符串的语义；缺少回查父级时仍为不可核验。即使独立回查找到匹配内容，也保留未知发送状态。无Key组装应用快照覆盖一级和下级科目的真实确认面板、拒绝、改版、单次发送和只读恢复；真实模型及主运行环境验收另行记录。

模型准备命令将action／kind／input放在顶层，不再嵌套一层proposal对象。严格JSON和业务校验仍然保留，不将错误JSON修补成可能产生写入的请求。科目类型使用用户给出的有成名称，财务提交人确认不能由报销成员资料替代。工具说明和Finance提示针对已观察到的模型路由／序列化错误，不新增通用意图解析器，也不暗设会计默认值。

日记账确认比较除身份和名称外，还保留返回的资金账户币别ID、账户类型和原始方向。账户ID不变并不证明其核算属性没有变化。这些可选观察值按原样持久保存，不补造缺失值，已有的已接收或未知记录仍可读取。在预留前发现变化则拒绝原确认；在预留后、发送前发现变化则持久保存未发送结果。两条路径均不发送请求，也不悄悄复用原确认。

科目资料提示采用独立核验的0借1贷回查映射。账套35616的100297和100298分别返回原值0和1，并已与供应商界面独立核对；100298仍保留最初借方意图核对失败的结论。这些证据证明方向含义，不把失败的创建意图改成成功。继续保留早期未核验提示会与科目准备／回查冲突，误导后续模型选择。缺失方向保持缺失，不给查询行补造默认值。定点资料测试和组装Finance资料会话固定提示及缺失字段行为。

资料转换保留供应商subjectType名称，供模型选择和核对类型；仅有Host校验并不等于模型拿到了该证据。缺失／null类型保持省略，空字符串保持为空，外部非字符串或超长值拒绝。工具schema说明与结果提示均声明已核验的方向含义。组装Finance资料场景检查模型实际工具说明与会话结果，并包含未提供类型和方向的下级科目，不只测试独立提示。这避免固化类型目录或暗自继承默认值，同时保留只读操作及结果大小限制。

往来映射先解析辅助类别与项目身份，再组装 `categoryName:itemName`。对方补充说明及分别成功的应收72595、应付72596证明该格式；早期裸名称拒绝不能作为服务端缺陷证据。标量校验和格式化与授权、账户发现、持久发送保持分离。公共资金账户查询即使附带已观察到的type5／type6也不返回应收应付账户；实验使用独立观察的账户ID成功，不代表可以写死这些ID，或把已有业务行当成已启用账户配置。

往来预留复用原子文件与锁，不引入凭证特有标识或通用流程引擎。授权在锁外执行，锁内再次核对准确版本，然后把完整请求保存为未知状态。这防止同一操作重复发送，不保证相同内容的新预览去重。独立公开回查比较原接受ID、业务内容、账户／类别ID、提交人、往来对象、空关联及未变的未结余额；缺少核销金额时保持未知。接口接受、回查匹配和应用验收分别保留证据。文档标为可选的accountId在已核验应付场景不能省略：单次省略试验返回201／未指账户，没有新增记录。已有业务行返回accountStatus／accountWb，但不是完整账户目录。

往来发送器使用持久预留的请求，重建固定公开参数，在最后一次Host检查前重新核实账套唯一性。响应丢失不会进入读取重试路径。两种方向的测试保留收到响应后取消时的成功ID，并在认证前拒绝旧预留及改动参数。公开文档ez7dJ32a明确accountWb表示外币账户；有成前端将真值accountStatus解释为禁用，与当前页面和已保存0／false业务行一致。这些字段可支持限定范围的当前账户核实，但不能证明完整账户目录或首条记录的账户发现；尚未挂载此类发现回退。

明确的已有记录查询页提供一个补充、有界的账户属性来源，不替代完整账户发现。准备过程保留查询及来源记录，核对账套／方向，拒绝缺失、禁用、冲突或未核验币种的账户。辅助／收支类别重新查询并核对选中身份；未知辅助状态仍披露。内部适配器已对两个真实合格样例生成预览，不发送或修改记录。尚无业务的账户仍无法解析，因此不能据此完成F3A或写死ID。

Finance预设挂载已有账户属性查询、本地往来准备和准确版本创建。Host复用已有强制确认服务、按归属隔离的记录及生命周期跟踪，不另设授权机制。确认展示来源限制和选中名称；来源、账户、类别或配置变化使原确认失效。先保存结果再独立回查，收到ID后取消也保留结果。双方向Host测试覆盖拒绝、并发修改、响应丢失和归属隔离；无Key应用组合场景验证实际工具调用、确认及结果界面。真实Host／模型验收与两条直接接口成功样例分别记录，不能从模拟场景推定通过。

## Alternatives considered

**整套复制凭证流程：**凭证特有的标识、原件和分录回查不能证明日记账或往来结果；只有满足相同要求的成熟基础机制才可复用。

**暴露任意接口参数：**这会让模型选择目标账套、审核字段和未核验关联。保留有界业务输入，由 Host 掌握真实资料。

**将接收成功视为完成：**必须独立回查业务记录，区分已接收但未核验与内容匹配，尤其不能忽视接口未返回可用 ID 的情况。

## Acceptance criteria

主Host核验使用单独标注的测试资料，不使用仅供预览的示例。只允许准确预览一次的处理器经过强制确认，但不声称人工点击。辅助状态缺失时，独立API与Chrome观察保持区分。独立核验脚本恢复按所属方保存的记录，比较之前返回的资料及凭证哈希，不重新发送。

启用及禁用辅助样例分别独立验证enableStatus1和0：主Host项目191573及191613的编码名称回查、各自Chrome状态均匹配。公开项目查询包含两者，但不返回状态。出现在查询结果中不能证明启用，也不能把实验中的页面证据注入产品作为永久状态结论。禁用样例没有业务关联，必须保持不使用。

五项能力全部通过定点校验与恢复测试、真实应用组合确认快照、自然语言场景，以及获批测试账套35616的独立实测回查。收入与支出、应收与应付分别留证。新测试记录具有稳定标记和保存的回执，保留全部原有记录。预览修改、配置变化、拒绝确认和重复提交不得写入。响应丢失和重启保留未知或已接收结果，不盲目重试。不加入审核、过账、结账、删除、核销或实际支付。

## Risks

供应商网页中可见的账户，不一定由公共资金账户接口返回。应收／应付准备必须分别核验当前资料来源与公共写入映射；现金日记账成功不能证明这两项成立。实验中可用页面证据支持有界参数验证，但不能将其固化为产品账户清单，也不能回退到私有接口。

公开示例不能证明全部字段的实际语义、支持期间或查询完整性。类别名称可能歧义；缺失值和不完整查询不能证明记录不存在。指定账套样例不能证明供应商跨设备幂等。开发状态必须记录待核验事项和未接通的部分，不能将其宣传为已可用能力。
